## Scenario 3 — `spec-bad.md` (spec prose)

### Output document

    # Spec: Refund handling

    ## Requirements

    1. The system MUST reject a refund request made more than 90 days after
       the payment.
    2. The refund handler SHOULD retry a transient failure. It MAY stop after
       three attempts.
    3. When a refund is issued, the Ledger MUST record the refund against the
       original payment. A second refund request carrying the same
       idempotency key MUST have no further effect.
    4. A refund MUST appear in the Ledger within one Settlement Window.
    5. The system MUST store the RRN with the refund.

    ## Scenarios

    - Given a payment made more than 90 days ago, when a refund is requested,
      then the request is rejected and the Ledger is unchanged.
    - Given a valid refund request, when the refund is issued, then the
      Ledger records the refund, and the refund is settled after the next
      Settlement Window.
    - Given a refund request that has already been handled, when the same
      idempotency key arrives again, then the request succeeds and nothing
      further changes.

    ## Design notes (moved out of Requirements)

    `RefundService.apply()` opens a transaction against the `refunds` table
    through the Drizzle client, takes an advisory lock on the payment ID, and
    writes two rows with opposite signs before committing.
