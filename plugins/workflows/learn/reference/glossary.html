Glossary

The bound vocabulary for this plugin. Every lesson uses these words in exactly these senses, and where two sources use one word for two things, both are listed with the collision named.

The core five

Level

One of minimal, standard, advanced — the single question /workflows:setup asks. A level names a set of schemas, subagents, a config example, and a plugin manifest. The three sets are disjoint: no schema name appears at two levels.

Schema

A workflow definition: which artifacts a change has, and how they depend on each other. Lives at openspec/schemas/<name>/schema.yaml with a templates/ directory beside it. This plugin ships twelve.

Artifact

One document in a schema's chain, with four required fields — id, generates, description, template — plus optional instruction and requires. The instruction is the prompt the agent actually receives.

Change

One unit of work, as a directory under openspec/changes/<name>/ holding its artifacts and its .openspec.yaml. Lowercase kebab-case; a leading number is allowed. Archiving merges its delta specs into openspec/specs/.

Delta spec

The behaviour contract a change adds, modifies, or removes, under the change's specs/. ADDED / MODIFIED / REMOVED blocks. A MODIFIED block replaces the whole requirement, so it must carry every surviving scenario.

Ownership and setup

copy
Plan group: the file is not there yet. Setup will write it.
update
Plan group: a previous run wrote it and nobody has edited it since — the recorded hash still matches. Refreshing these is how a re-run takes updates.
collide
Plan group: your file, or one of setup's you have since changed. Reported by name, never replaced without individual approval. "Approve all" is not an answer.
Reconcile mode
A run where .claude/workflows.json already exists. The alternative is fresh. Reconcile installs only what is missing.
Probe change
zz-workflows-setup-probe — a throwaway change setup's verification creates, queries with instructions --json, then removes by deleting the directory directly. Never archived, because archiving would write into your specs.
Drift
The gap between what a repository has and what its level currently ships. --check reports it and writes nothing.

OpenSpec configuration

context
Prose injected into every artifact's instructions, wrapped in <context> tags. Hard-capped at 50KB; one byte over and the entire field is dropped silently.
rules
A map of artifact id → list of strings, injected only for the matching artifact. Artifact-specific formatting belongs here, never in context.
Operation
A phase that is not an artifact — apply, archive. It has requires, a tracks file, and advisory guidance. apply is an operation, which is why it never appears as an artifact id.
Profile
Machine-global OpenSpec setting deciding which /opsx:* commands exist. Two presets: core (six commands) and custom (a selection you make). Setup never writes it.
Store
A standalone OpenSpec repository registered on this machine, addressed with --store <id>. Without one, commands act on the nearest local openspec/ root.

Doing the work

Slice
One tracer-bullet unit of implementation: a thin vertical cut built test-first in a single session, reviewed, committed. Each slice is self-contained, so the finished slice's context is disposable.
Seam
The public boundary a test is written at. Agreed up front in design — the Seams table — because an unagreed seam is where test effort goes to waste.
Characterization test
A test that pins current behaviour before any code moves. refactor's safety net and its first artifact.
Walking skeleton
The thinnest end-to-end slice building, testing, and deploying green in CI. setup's exit criterion.
Visitor mode
Persuade, Operate, Read, or Experience — chosen from the surface, not the product. Set in a design brief.
Two-axis review
A review split into a mechanical Spec axis (diff versus what was asked) and a judgement Standards axis (code as code), run as parallel subagents on different model tiers.

Escape hatches

Key Read by the CLI? Effect
skip_specs Yes Status shows the stage skipped and excludes it from the count. Declaring it and writing spec files is a validation conflict
retire_capabilities Yes Archive may delete a capability's spec file rather than aborting. Recoverable only from git
skip_grill No Records the judgement. A one-line stub grill.md unblocks the graph
skip_surface No Same — the key is for people, the stub file is for the dependency graph

Collisions worth naming

Word Sense A Sense B
setup /workflows:setup — this plugin's command, which configures a repository's OpenSpec layer The setup schema — one of the eight advanced workflows, which bootstraps a repository's code and CI
config openspec/config.yaml — the project YAML: default schema, context, rules. Edited by hand ~/.config/openspec/config.json — the machine JSON: profile, delivery, telemetry. Edited by openspec config set
design design.md — the technical design artifact: architecture, decisions, seams, ADRs design-brief.md / surface.md — the visual design brief: mode, direction, states
tasks vs plan tasks.md — the coarse, tracked checklist. Checkboxes must be exactly - [ ] plan.md (feature only) — the micro-step, two-to-five-minute decomposition with real test code
verification The archive-gate artifact in craft-driven, feature, and upgrade Setup's own step 9 — behavioural checks that the config reached the model and your specs were untouched
