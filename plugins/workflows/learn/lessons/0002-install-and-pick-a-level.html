Lesson 02·Install and set up·workflows

Install, and pick a level

Setup asks you exactly one question, and this is it. It arrives with a recommendation read off your own commit history — but it recommends rather than decides, and the difference between the three levels is how many kinds of work your repository actually sees.

By the end

The plugin is installed, and you can name the level you would choose for a repository you work in — with a reason drawn from the ladder rather than from taste.

Prerequisites: Lesson 01. You need a repository you can experiment in, and Node 20.19 or newer for the OpenSpec CLI.

Install

claude plugin marketplace add YOUR-GITHUB-OWNER/agent-tools --scope project
claude plugin install workflows@agent-tools --scope project

--scope project writes to the repository's .claude/settings.json, which you commit — so the setup travels with the repo instead of living on one workstation. Run both commands in auto mode — Claude Code's default permission mode on Pro, Max, and Team plans — and a classifier approves them instead of prompting you for each one.

meta-skills arrives with it. The plugin declares it as a manifest dependency, so the skills that produce TOOLS.md and CLAUDE.md are installed and enabled before setup ever runs. That is not a convenience — it removes an ordering problem that would otherwise force setup into two passes with a restart in the middle.

plugins/workflows/.claude-plugin/plugin.json — "dependencies": [{ "name": "meta-skills", … }]
Do not run setup yet

Read lesson 03 first. Setup will show you a plan and wait, and the plan is the thing worth learning to read. Running it now means approving something you cannot yet evaluate.

The ladder

The levels are not small, medium and large versions of one workflow. Each rung adds kinds of work the repository knows how to handle.

Level Schemas Artifacts Longest chain Router
minimal mattpocock-bridge, bugfix-flow 9 6 no
standard craft-driven, surface-driven 12 7 no
advanced feature, bugfix, refactor, rapid, setup, spike, upgrade, hotfix 32 10 yes
Counted from plugins/workflows/payload/levels/*/openspec/schemas/*/schema.yaml. The levels ship disjoint schema sets — no schema name appears at two levels.

What each level is opinionated about

minimal — two schemas, one interview

Built on mattpocock/skills. The default workflow, mattpocock-bridge, opens with a grill: an interview in rounds that sharpens the idea and writes what it learns into CONTEXT.md and ADRs before any spec exists. Its companion, bugfix-flow, deliberately drops the interview and the proposal — a defect needs no case made for fixing it — and gates everything behind a written root cause.

Cost of entry: the pack must be installed, and /setup-matt-pocock-skills must have been run once in the repository. That is an interview only a human can answer, so setup cannot do it for you.

standard — two schemas, one of them design-led

Built on obra/superpowers, plus Impeccable for anything touching a user interface. craft-driven is the feature workflow: brainstorm, proposal, specs, then TDD and evidence-first verification. surface-driven inverts the lead for work that is a surface — a landing page, a dashboard, a redesign — letting the design brief drive and Superpowers supply the execution discipline.

Choose between them per change, not per project. That decision is lesson 09.

advanced — eight schemas and a router

Organized by change type rather than by methodology. This is the only level with a router: ROUTING.md, which the agent reads before creating any change and which classifies the request in one pass. It is also the only level that can handle a production incident, a dependency upgrade, a timeboxed spike, or a fresh repository bootstrap as first-class work rather than forcing them through a feature chain.

Cost of entry: three skill packs — mattpocock, superpowers, and addyosmani/agent-skills — and the same human interview minimal needs.

What gets installed alongside

Independently of the level, setup merges in a base set of plugins, and a second set on top when it detects a web project. It never overwrites a choice you have already made in .claude/settings.json.

How to actually choose

Setup runs this for you — and you should still know it

Before it asks, setup reads the repository's recent commit subjects, sorts them into kinds, and comes back with a recommended level and the evidence for it. It recommends; it does not decide. Knowing the procedure below is what lets you tell a good recommendation from one drawn off forty commits of a rewrite that is not how this repo usually works.

The procedure, which is one question about the repository rather than about yourself:

  1. List the last ten pieces of work in this repository. Pull them from git log or your tracker — real ones, not imagined ones.
  2. Sort them into kinds. New capability, defect, structural cleanup, trivial change, dependency bump, incident, open question, bootstrap.
  3. Count the kinds, not the items. Two or three kinds and a feature-plus-bugfix shape means minimal or standard. Five or more kinds — especially if upgrades or incidents are among them — means advanced.
  4. Break the tie on methodology. Between minimal and standard: does the work usually start with an unclear idea that needs interviewing, or with a surface someone can already picture? Interview → minimal. Surface → standard.
Choosing wrong is cheap

Re-run /workflows:setup with a different level. The run record merges rather than replaces, so the previous level's files stay on disk and stay owned by setup — returning to that level later updates them instead of reporting a collision that never happened.

skills/setup/SKILL.md step 8 — "The record merges into whatever is already there"
