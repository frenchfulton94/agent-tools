Learning the workflows plugin

Fourteen short lessons and six reference cards, for adopting spec-driven development in any repository. Written for someone who has never seen OpenSpec, with author-level detail in marked appendices. Every claim cites the plugin source.

Start here

Lessons run in order and each one is finishable in a sitting. Lesson 01 needs nothing installed. If you only have twenty minutes ever, do lesson 06 — routing is the skill that pays for the rest.

How to use this with an agent

The agent in your session is the teacher. Every lesson ends with a suggested question, and they share a shape: name the file, name what you expected, name what you got. "Read the last thirty commits and tell me which level the ladder points at" beats "which level should I use?", because the first one can be answered from evidence.

Where this course does not go

Authoring a thirteenth schema is out of scope — the configuring-openspec skill owns that. So is what happens inside the skill packs the schemas hand off to (superpowers, mattpocock, impeccable, agent-skills): the lessons teach the handoff point and name the skill, and the far side is that pack's own documentation. And no usage figures are quoted: subscription limits are published as relative multipliers only, so lesson 12 teaches the routing consequences and points at /usage rather than at a number.

The workspace behind this

These pages are the published half of a /teach workspace at plugins/workflows/learn/: MISSION.md (why this exists), RESOURCES.md (every source, ranked by trust, with an explicit gaps section), NOTES.md (conventions and open questions), and learning-records/. Read RESOURCES.md before trusting any claim here — it says which sources outrank which, and where the evidence runs out.
