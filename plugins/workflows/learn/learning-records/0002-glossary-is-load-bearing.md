# The glossary is load-bearing because five words are overloaded

Writing the lessons surfaced five words this system uses for two different things:
**setup** (the plugin's command vs. the `advanced` schema), **config** (project YAML vs.
machine JSON), **design** (technical design vs. visual design brief), **tasks** vs.
**plan** (coarse tracked list vs. micro-step decomposition), and **verification** (the
archive-gate artifact vs. setup's own step 9).

**Why it matters:** a newcomer who conflates any pair will make a real mistake — editing
the wrong config file is the most common wasted edit in OpenSpec, per the
`configuring-openspec` skill's own words. Every lesson therefore links the glossary, and
the glossary carries an explicit "collisions worth naming" table rather than leaving the
reader to notice. Any future lesson that introduces a sixth overloaded word adds it there
first.
