## Choosing the audio layer

| Need | Use | Why |
|---|---|---|
| Music, SFX, mixing, effects, taps, offline bakes | `AVAudioEngine` | The default game stack on every Apple platform. A node graph into `AVAudioOutputNode`, with built-in effects and 3D mixing. |
| Simple 3D panning with distance and reverb | `AVAudioEnvironmentNode` inside the engine | No extra framework. Per-source `AVAudio3DMixing` properties. |
| Geometry-aware sound: occlusion, area sources, event trees, game parameters | PHASE | Apple's own steer: if audio does not react to the world, AVFAudio is enough. |
| A C++ engine's own mixer feeding spatial output | AudioToolbox `kAudioUnitSubType_SpatialMixer` | Takes a multichannel bed, renders binaural or speaker output for the attached hardware. |
| Procedural audio, custom DSP | `AVAudioSourceNode` with a C++ kernel | Render code belongs in C or C++ (see "Real-time audio-thread rules"). |
| A short UI blip outside the mix | `AudioServicesPlaySystemSound(_:)` | 30 s or less, no volume, no looping, one at a time. Never game SFX. |
| One streamed track, no mixing | Audio Queue Services | Its page still calls it the API for all new development, a line written for code leaving the Sound Manager. For a game mix it is the wrong layer. |
| A menu click in a non-game Mac tool | `NSSound` | No graph, no mixing. |

RealityKit's entity audio is out of scope; a custom Metal engine uses PHASE
or AVAudioEngine. A game built on a third-party audio engine still needs the
session and system spatial-audio settings below; Apple's spatial-audio
article names third-party engines in that rule.

## The Mac has no audio session

`AVAudioSession` is `API_UNAVAILABLE(macos)` in the SDK header
(`AVAudioSession.h`, from the class down to every method). The HIG's category
and silent-switch guidance is for iPhone, iPad, Apple TV, Vision Pro, and
Apple Watch. A native Mac game has no category to choose, no Ring/Silent
switch, and no session interruption or route-change notifications. Code that
calls `AVAudioSession.sharedInstance()` does not compile for macOS.

What a Mac game uses instead:

- **`AVAudioEngine` directly.** On macOS the engine's I/O nodes talk to the
  system's default input and output devices (`AVAudioIONode.h`). Nothing to
  activate.
- **`AVAudioEngineConfigurationChange`** for device changes. When the
  hardware's sample rate or channel count changes (headphones plugged in, a
  new default output), the engine stops and uninitializes itself and posts
  this notification. Nodes stay attached with their old formats. Restart the
  engine, and rebuild any connection whose format must follow the hardware.
  Do not release the engine inside the handler: it runs on an internal
  dispatch queue and can deadlock. This applies on iOS too.
- **`AVAudioApplication`** (macOS 14) for app-wide state: record permission
  and input mute (`isInputMuted`, `setInputMuted(_:)`,
  `inputMuteStateChangeNotification`). On macOS only,
  `setInputMuteStateChangeHandler(_:)` is how the app implements mute when an
  AirPods gesture toggles it; on other platforms the system mutes input
  itself (`AVAudioApplication.h`).
- **`AVAudioRoutingArbiter`** (macOS 11, macOS only) to take part in AirPods
  Automatic Switching. iOS apps take part automatically; a Mac app calls
  `begin(category:completionHandler:)` when it starts playing or recording and
  `leave()` when it stops. A game with voice chat brackets the call this way.
- **Core Audio HAL** for a device picker. If the game holds device IDs or
  property listeners, also listen for
  `kAudioHardwareServiceProperty_ServiceRestarted`: after an audio service
  restart every cached ID and listener is stale.

Two iOS-family settings have no Mac counterpart and need nothing on the Mac:
the `AVGameBypassSystemSpatialAudio` Info.plist key (iOS, iPadOS, tvOS 18)
and the session categories.

## AVAudioEngine in a game

The shape that scales: one `AVAudioPlayerNode` per voice or clip, a mixer
node per bus (music, SFX, dialog, UI), each bus into `mainMixerNode`.
Per-bus mixers let you swap what feeds a bus without disconnecting what is
playing, and give the pause menu one volume to duck.

```swift
import AVFAudio

@MainActor
final class GameAudio {
    let engine = AVAudioEngine()
    let music = AVAudioPlayerNode()
    let musicBus = AVAudioMixerNode()
    private var configObserver: (any NSObjectProtocol)?

    func build() throws {
        engine.attach(music)
        engine.attach(musicBus)
        if #available(macOS 27, iOS 27, *) {
            // OS 27: the connect call throws.
            try engine.connectNode(music, to: musicBus, format: nil)
            try engine.connectNode(musicBus, to: engine.mainMixerNode, format: nil)
        } else {
            // OS 26 path. Deprecated in the 27 SDKs.
            engine.connect(music, to: musicBus, format: nil)
            engine.connect(musicBus, to: engine.mainMixerNode, format: nil)
        }
        configObserver = NotificationCenter.default.addObserver(
            forName: .AVAudioEngineConfigurationChange, object: engine, queue: .main
        ) { [weak self] _ in
            MainActor.assumeIsolated { self?.restartAfterDeviceChange() }
        }
        engine.prepare()
        try engine.start()
    }

    private func restartAfterDeviceChange() {
        // The engine stopped itself. Rebuild format-dependent connections, then:
        try? engine.start()
    }
}
```

Judgment calls the docs support:

- **Rewire upstream of a mixer only.** The engine page warns that removing a
  mixer, or a node whose channel count differs from its neighbors, while
  running can break the graph. Per-bus mixers make every live swap an
  upstream one.
- **Match formats at the player.** A player node assumes scheduled buffers
  share its output sample rate, and drops or adds channels to match its
  output; let a mixer do rate and channel conversion.
- **Never stop a player inside its own completion handler**; the page says
  it can deadlock while unscheduling.
- **Effects before DSP.** `AVAudioUnitEQ`, `AVAudioUnitDistortion`,
  `AVAudioUnitDelay`, and `AVAudioUnitReverb` cover most game needs.
  `AVAudioUnitVarispeed` couples rate and pitch (cheap engine RPM, tape stop,
  whole-mix slow motion); `AVAudioUnitTimePitch` changes them independently
  at more cost.
- **Do not loop long music with the `.loops` buffer option.** Apple's
  sequencer sample warns that it drifts over a long session. Schedule one
  iteration at a time at an explicit `AVAudioTime(hostTime:)`, and schedule
  the next at the previous end time. The sample also quantizes stingers to the
  next bar boundary computed from transport start and tempo.
- **Start a voice at volume 0 and raise it** to avoid a click from a
  non-zero first sample. The engine smooths volume changes over one render
  buffer.
- **Ramp every live parameter** you drive yourself (frequency, gain). A step
  change zippers. Apple's signal-generator sample ramps over 100 ms.
- **Voice chat with echo cancellation** is
  `inputNode.setVoiceProcessingEnabled(true)` (macOS 10.15, iOS 13). The
  header's conditions: the engine must be stopped, it must render to a device
  (not manual rendering), enabling one I/O node enables both, and the input
  node's output format must equal the output node's input format. Then
  `isVoiceProcessingInputMuted` for push-to-talk,
  `setMutedSpeechActivityEventListener(_:)` (macOS 14, iOS 17) for the "you
  are muted" prompt, and `voiceProcessingOtherAudioDuckingConfiguration`
  (macOS 14, iOS 17, not tvOS) for how far game audio ducks under speech. The
  symbol page is a stub; the header is the documentation.
- **Faster-than-real-time bakes** (pre-rendered reverb tails, analysis for
  audio-reactive visuals, deterministic audio tests in CI):
  `enableManualRenderingMode(.offline, format:maximumFrameCount:)` before
  `start()`, then loop `renderOffline(_:to:)`. `.cannotDoInCurrentContext`
  means try again.

## OS 27 changes to AVAudioEngine

The macOS 27 and iOS 27 SDKs change the engine's Swift surface. At the 26.0
floor, each one is an `#available(macOS 27, iOS 27, *)` branch with the 26
path beside it.

| OS 26 spelling | OS 27 spelling | Source |
|---|---|---|
| `connect(_:to:format:)`, `connect(_:to:fromBus:toBus:format:)` | `connectNode(_:to:format:)`, `connectNode(_:to:fromBus:toBus:format:)`, both `throws` | `AVAudioEngine.h` |
| `AVAudioPlayerNode.play()`, `play(at:)` | `playAudio()`, `playAudio(at:)`, both `throws` | `AVAudioPlayerNode.h` |
| `installTap(onBus:bufferSize:format:block:)` | `installAudioTap(onBus:bufferSize:format:tapProvider:)`, `throws`, `@Sendable` tap given an `AVReadOnlyAudioPCMBuffer` | `AVAudioNode.h`, swiftinterface |
| `AVAudioNode.auAudioUnit` | `withAUAudioUnit(_:)`, a scoped borrow | swiftinterface |
| `AVAudioUnit.audioUnit`, `AVAudioIONode.audioUnit` | `withAudioUnit(_:)` | swiftinterface |
| `AVAudioEngine.musicSequence` | `withMusicSequence(_:)` | swiftinterface |
| `AVAudioSourceNode(renderBlock:)` (not deprecated) | `initWithRealtimeSafeRenderBlock:`, Objective-C and C++ only, preferred when rendering to a device | `AVAudioSourceNode.h` |

The page for `withAUAudioUnit(_:)` describes it as thread-safe scoped
access: the unit is valid only inside the closure. Do not store it or let it
escape.

`AVReadOnlyAudioPCMBuffer` (OS 27) is a `Sendable` struct, so an actor that
loads or analyzes audio can hand buffers to the actor that owns the engine.
`AVAudioFile.read(frameCount:)` returns one, and
`AVAudioPlayerNode.scheduleBuffer(_:atTime:options:completionCallbackType:completionHandler:)`
takes one. Its `channelData(_:)` returns a non-escapable enum of `Span`s.

A tap that meters a bus, with both paths. The tap writes a single scalar to
an atomic; the frame loop reads it. No lock, no `Task` per buffer. Both tap
APIs document a supported buffer size of 100 to 400 ms (4800 frames is
100 ms at 48 kHz), so a tap meter updates a few times a second at best. For
a meter or beat trigger at frame rate, measure inside the render callback
(C++, below) and publish through the same kind of atomic.

```swift
import AVFAudio
import Accelerate
import Synchronization

final class PeakMeter: Sendable {
    private let bits = Atomic<UInt32>(0)
    func store(_ peak: Float) { bits.store(peak.bitPattern, ordering: .relaxed) }
    var peak: Float { Float(bitPattern: bits.load(ordering: .relaxed)) }
}

func installMeter(on node: AVAudioNode, meter: PeakMeter) throws {
    if #available(macOS 27, iOS 27, *) {
        try node.installAudioTap(onBus: 0, bufferSize: 4800, format: nil) { buffer, _ in
            guard case .float(let samples) = buffer.channelData(0) else { return }
            var peak: Float = 0
            samples.withUnsafeBufferPointer { p in
                vDSP_maxmgv(p.baseAddress!, 1, &peak, vDSP_Length(p.count))
            }
            meter.store(peak)
        }
    } else {
        node.installTap(onBus: 0, bufferSize: 4800, format: nil) { buffer, _ in
            guard let channels = buffer.floatChannelData else { return }
            var peak: Float = 0
            vDSP_maxmgv(channels[0], 1, &peak, vDSP_Length(buffer.frameLength))
            meter.store(peak)
        }
    }
}
```

## The iOS and iPadOS audio session

iOS only (and iPadOS): nothing in this section compiles for macOS, and the
snippet below is checked against the iOS 26.0 target. In your own target
that also builds for the Mac, keep this code behind `#if os(iOS)`.

| Game | Category | Behavior (from the category pages) |
|---|---|---|
| Has its own soundtrack | `.soloAmbient` (the default) | Silences other apps' audio; the Silent switch and screen lock silence the game. |
| Lets the player keep their own music | `.ambient` | Mixes with other audio; still obeys the Silent switch. |
| In-game voice chat | `.playAndRecord`, mode `.voiceChat` | Output defaults to the receiver; add `.defaultToSpeaker`. |

- **Bluetooth headsets in voice chat:** `.allowBluetoothHFP`. Apple's
  stereo-capture sample still passes `.allowBluetooth`, which the SDK
  deprecates in favor of `.allowBluetoothHFP` (both are bit `0x4`,
  `AVAudioSessionTypes.h`). `.allowBluetoothA2DP` keeps high-quality output
  while recording.
- **Do not set the `.longFormAudio` route-sharing policy.** It marks the app
  as a music or podcast player. A game is not one.
- **Game Center's game-chat mode is GameKit's to set.** The C header says not
  to set it directly; a game rolling its own voice chat uses `.voiceChat`.
- **Latency:** ask for a smaller buffer with `setPreferredIOBufferDuration(_:)`
  only when a rhythm game needs it, then read `ioBufferDuration`, because the
  request is a preference. The page puts the minimum at about 0.005 s (256
  frames), possibly lower on some hardware.
- **Route changes:** observe `routeChangeNotification`. It arrives on a
  secondary thread (the interruption notifications arrive on the main
  thread), so hop to your own isolation before touching game state. When
  headphones disappear (`.oldDeviceUnavailable`), pause the game or at least
  its audio rather than jumping to the speaker unannounced.
- **System spatial audio:** on iOS, iPadOS, and tvOS 18 and later, the system
  adds a spatial effect to games when compatible AirPods are worn. A game that
  does its own 3D audio adds the `AVGameBypassSystemSpatialAudio` key to
  Info.plist, or the output is spatialized twice. The key also removes the
  Control Center toggle. Not needed on the Mac.

**Interruptions changed in iOS 27.** The begin/end
`AVAudioSession.interruptionNotification` and its type, option, and reason
keys are deprecated in the iOS 27 SDK. Their replacements are three
notifications: `didBecomeActiveNotification`, `didBecomeInactiveNotification`
(userInfo `deactivationContextKey` gives an `AVAudioSession.DeactivationContext`
whose `source` is `.app` or `.system`), and
`resumptionRecommendationNotification` (userInfo `resumptionContextKey` gives
a `ResumptionContext` whose `recommendation` is `.shouldResume` or
`.shouldNotResume`). The old model could leave a game stuck "interrupted"
when the end event never arrived, which happens when the player answers the
call. The resumption recommendation comes from the system, not from the app
that interrupted.

Two SDK details: the deprecation message on `AVAudioSessionInterruptionReasonKey`
points at `interruptionDetails.reason`, but the declared property is
`DeactivationContext.interruptionContext` (`AVAudioSession.h`); use the
declared name. And the `shouldResume` page says a game may ignore that flag
and resume on its own, because game audio did not start from an explicit
user action.

```swift
import AVFAudio

@MainActor
final class SessionController {
    var onPause: () -> Void = {}
    var onResume: () -> Void = {}
    private var observers: [any NSObjectProtocol] = []

    func configure(voiceChat: Bool) throws {
        let session = AVAudioSession.sharedInstance()
        if voiceChat {
            try session.setCategory(.playAndRecord, mode: .voiceChat,
                                    options: [.defaultToSpeaker, .allowBluetoothHFP])
        } else {
            try session.setCategory(.soloAmbient)
        }
        try session.setActive(true)
    }

    func observeInterruptions() {
        let center = NotificationCenter.default
        if #available(iOS 27, *) {
            observers.append(center.addObserver(
                forName: AVAudioSession.didBecomeInactiveNotification, object: nil, queue: .main
            ) { [weak self] _ in
                MainActor.assumeIsolated { self?.onPause() }
            })
            observers.append(center.addObserver(
                forName: AVAudioSession.resumptionRecommendationNotification, object: nil, queue: .main
            ) { [weak self] note in
                let context = note.userInfo?[AVAudioSession.resumptionContextKey]
                    as? AVAudioSession.ResumptionContext
                let resume = context?.recommendation == .shouldResume
                MainActor.assumeIsolated { if resume { self?.onResume() } }
            })
        } else {
            // iOS 26 path: begin/end pairs. Deprecated in iOS 27.
            observers.append(center.addObserver(
                forName: AVAudioSession.interruptionNotification, object: nil, queue: .main
            ) { [weak self] note in
                let raw = note.userInfo?[AVAudioSessionInterruptionTypeKey] as? UInt
                let began = raw.flatMap(AVAudioSession.InterruptionType.init) == .began
                MainActor.assumeIsolated { if began { self?.onPause() } else { self?.onResume() } }
            })
        }
    }
}
```

`onPause` should pause the simulation and show the pause menu, not only stop
sound: a phone call mid-match must not leave the game running silently. On
iOS 26, also re-check session state when the app returns to the foreground,
because the end event may never come. `setPrefersNoInterruptionsFromSystemAlerts(_:)`
(iOS 14.5) asks the system not to interrupt for alerts such as an incoming-call
ringtone.

## 3D audio: environment node, PHASE, or the spatial mixer

**`AVAudioEnvironmentNode`** is the first step: sources connect to it, each
with `AVAudio3DMixing` position and rendering properties, plus distance
attenuation and reverb parameters on the node. Listener pose is
`AVAudio3DPoint` with a vector or angular orientation. **Only mono inputs are
spatialized**: the node passes stereo through unpositioned and does not take
inputs wider than two channels. Connect positional SFX with a mono
connection format, and send music and stereo beds to an ordinary mixer.

**PHASE** (macOS 12, iOS 15, tvOS 17) is the heavier engine for sound that
reacts to geometry. What a game needs to know:

- **Update mode is a frame-loop decision.** With `.automatic`, PHASE consumes
  your calls at its own rate, so two calls are not guaranteed to land together.
  With `.manual`, nothing applies until `update()`; call it once per frame
  from the frame loop, and every source move and event start since the last
  update lands together. The `update()` page puts 30 to 240 Hz at equivalent
  audio quality; more often gives smoother parameter interpolation. The
  render thread runs independently of either mode, and `update()` is safe to
  call off the main thread.
- **Objects must be in the tree.** `PHASESource`, `PHASEListener`, and
  `PHASEOccluder` are `PHASEObject`s with a `simd_float4x4` transform relative
  to their parent. Add each under `engine.rootObject` with `addChild(_:)`, or
  it is not simulated.
- **Units.** Distances are meters unless you set `unitsPerMeter`.
- **No distance model, no attenuation.** A `PHASESpatialMixerDefinition`
  attenuates only once `distanceModelParameters` is set. With
  `PHASEGeometricSpreadingDistanceModelParameters`, `rolloffFactor` 1.0 loses
  6 dB per doubling of distance per the 3D-scene article; 2.0 doubles the
  loss, 0.5 halves it.
- **Geometry** comes from Model I/O: `PHASEShape(engine:mesh:)` from an
  `MDLMesh`, used for area sources or for occluders with a `PHASEMaterial`.
- **Game parameters** (the RTPC equivalent) are metaparameters on generator
  gain and rate, switch and blend nodes, and reverb sends. Global ones,
  registered on the asset registry, drive every event (weather, music
  intensity); local ones drive one `PHASESoundEvent`.
- **Your own samples into PHASE:** `PHASEPushStreamNode` takes
  `AVAudioPCMBuffer`s you schedule. `PHASEPullStreamNodeDefinition` (macOS 15,
  iOS 18) calls your render handler on PHASE's render thread, under the
  real-time rules below.
- **Errors come in three domains**: `PHASEErrorDomain`, `PHASEAssetErrorDomain`
  for registration and loading, `PHASESoundEventErrorDomain` for prepare and
  start.
- **`PHASEEngine.RenderingMode` is visionOS 26 only.** Its page lists iOS
  with no version; the SDK header says `API_UNAVAILABLE(macos, ios, tvos)`,
  and the SDK wins. On the Mac and iPhone the engine renders in process and
  is created with `init(updateMode:)`.

```swift
import PHASE

@MainActor
final class SpatialAudio {
    let engine = PHASEEngine(updateMode: .manual)
    let listener: PHASEListener

    init() throws {
        listener = PHASEListener(engine: engine)
        try engine.rootObject.addChild(listener)
        try engine.start()
    }

    func makeSpatialMixer() -> PHASESpatialMixerDefinition? {
        guard let pipeline = PHASESpatialPipeline(flags: [.directPathTransmission, .lateReverb])
        else { return nil }
        let mixer = PHASESpatialMixerDefinition(spatialPipeline: pipeline)
        let distance = PHASEGeometricSpreadingDistanceModelParameters()
        distance.rolloffFactor = 1.0
        mixer.distanceModelParameters = distance   // without this, no attenuation
        return mixer
    }

    // Once per frame, after the simulation step.
    func frame(listenerTransform: simd_float4x4) {
        listener.transform = listenerTransform
        engine.update()
    }
}
```

**The spatial mixer AU** (`kAudioUnitSubType_SpatialMixer`) is the layer for
a C++ engine that already mixes to a multichannel bed. Set its input layout to
the bed's, its output to stereo, the spatialization algorithm to "use output
type" so it renders for whatever is attached, and the bed's source mode to
ambience bed. The I/O unit below it is HAL output on macOS and RemoteIO on
iOS. Apple's sample prose names `kAudioChannelLayoutTag_MPEG_7_1_A` (8
channels) while its code passes `kAudioChannelLayoutTag_Atmos_7_1_4` (12
channels, `CoreAudioBaseTypes.h`); use the tag whose channel count matches the
buffer you supply.

**Personal spatial audio and head tracking** (iOS 18, macOS 15). The
`com.apple.developer.spatial-audio.profile-access` entitlement applies the
player's personalized profile to AVAudioEngine, the spatial mixer, and PHASE.
Head tracking with compatible AirPods needs
`com.apple.developer.coremotion.head-pose` plus a per-framework switch:
`AVAudioEnvironmentNode.isListenerHeadTrackingEnabled`,
`PHASEListener.automaticHeadTrackingFlags = .orientation`, or the spatial
mixer's `kAudioUnitProperty_SpatialMixerEnableHeadTracking`. Both entitlement
pages list macOS 15.

## Real-time audio-thread rules

The render callback runs on a real-time thread with a hard deadline. Apple's
signal-generator article states the rule: no allocation, no file I/O, no
locks, and no Swift or Objective-C runtime calls while rendering. Overloads
show up as glitches; the Audio System Trace template in Instruments shows
them (`apple-performance` covers driving Instruments).

**The OS 27 SDK makes the language rule explicit.** Every engine render
callback now has a real-time-safe twin: `AVAudioSourceNodeRenderBlockRealtimeSafe`
(`initWithRealtimeSafeRenderBlock:`, `initWithFormat:realtimeSafeRenderBlock:`),
`AVAudioSinkNodeReceiverBlockRealtimeSafe` (`initWithRealtimeSafeReceiverBlock:`),
and `AVAudioIONodeInputBlockRealtimeSafe`
(`setRealtimeSafeManualRenderingInputPCMFormat:inputBlock:`). Each is
`API_AVAILABLE(macos(27.0), ios(27.0), …)` and carries
`__SWIFT_UNAVAILABLE_MSG("Swift is not supported for use with audio realtime threads")`.
The headers call the real-time-safe initializer the preferred one whenever the
engine renders to a device or runs in real-time manual mode. So real-time
render code is C, Objective-C, or C++. `AUAudioUnit.osWorkgroup` and
`kAudioOutputUnitProperty_OSWorkgroup` carry the same Swift-unavailable
marking (macOS 11, iOS 14). Swift stays on the control side: building the
graph, setting parameters, UI.

**What `CA_REALTIME_API` does.** It is `[[clang::nonblocking]]` in C++11 and
later (`CoreAudioBaseTypes.h`), so clang's function-effect analysis can
check the callback. Runtime-checked with clang 21:

- **Off by default.** A `CA_REALTIME_API` function that calls `malloc` and
  `free`, takes a `std::lock_guard`, and builds a `std::vector` compiles with
  no diagnostic under default flags. Add `-Wfunction-effects` (or
  `-Werror=function-effects`) to the target's C++ flags; it then reports six
  diagnostics: `malloc`, `free`, and the constructor and destructor of both
  the lock guard and the vector.
- **What passes:** a relaxed `std::atomic<float>::load` and `std::memset`.
- **vDSP does not.** `vDSP.h` does not mark its functions `nonblocking`, so
  `vDSP_vsmul` inside a checked function warns. Wrap each vetted vDSP call in
  one small `CA_REALTIME_API` function with the warning silenced around that
  call only; the rest of the kernel stays checked (zero warnings, run logged).

The split Apple's signal-generator sample uses: a C++ kernel, an Objective-C
wrapper that hands the engine a render block calling the kernel, and Swift
only for wiring. On OS 27 the wrapper passes that block to
`initWithRealtimeSafeRenderBlock:`; on OS 26 to `initWithRenderBlock:`. The
wrapper must be Objective-C++ to call the C++ kernel. The kernel:

```cpp
#include <Accelerate/Accelerate.h>
#include <AudioToolbox/AudioToolbox.h>
#include <atomic>

// One vetted vDSP call, checked once by hand.
static inline void ramp_gain_rt(float *buf, float *gain, float step, vDSP_Length n) CA_REALTIME_API {
#pragma clang diagnostic push
#pragma clang diagnostic ignored "-Wfunction-effects"
    vDSP_vrampmul(buf, 1, gain, &step, buf, 1, n);
#pragma clang diagnostic pop
}

struct GainKernel {
    std::atomic<float> target{1.0f};   // written by the control thread
    float current = 1.0f;              // touched only on the render thread

    OSStatus render(AudioBufferList *io, UInt32 frames) CA_REALTIME_API {
        const float goal = target.load(std::memory_order_relaxed);
        const float step = (goal - current) / static_cast<float>(frames);
        for (UInt32 b = 0; b < io->mNumberBuffers; ++b) {
            float start = current;     // each channel ramps from the same value
            ramp_gain_rt(static_cast<float *>(io->mBuffers[b].mData), &start, step, frames);
        }
        current = goal;
        return noErr;
    }
};
```

`vDSP_vrampmul` writes the next ramp value back through its start pointer,
which is what lets a ramp resume across render calls.

Rules that follow from the pages:

- **Set up off the thread, update in place on it.** `vDSP_create_fftsetup`,
  `vDSP_biquad_CreateSetup`, and `vDSP_biquadm_CreateSetup` allocate (their
  `vDSP.h` comments say so), and `vDSP_DFT_zrop_CreateSetup` may allocate (its
  page). Build them at load. `vDSP_biquad_SetCoefficientsSingle` and
  `...Double` (macOS 12, iOS 15) retune a live setup without allocating, so
  they are the filter-sweep path on the render thread.
- **Swift `vDSP` overlay calls that return an array allocate** on every call.
  Near audio, use the `result:` forms or the C functions.
- **Parameter handoff:** the control side writes a target, the render side
  ramps toward it. The host-facing getter returns the target, never the value
  mid-ramp. With an AU, `AUParameterTree` parameters flagged `.flag_CanRamp`
  do this for you.
- **Format conversion inside the callback:**
  `AudioConverterFillComplexBufferRealtimeSafe` (OS 26, so usable at the
  floor) handles PCM-only work: interleaving, channel count, sample rate. If a
  conversion needs non-real-time work, such as a compressed decode, it returns
  `kAudioConverterErr_OperationNotSupported`. Decode at load instead.
- **Retry, never wait.** Apple's APIs return a cannot-do-in-current-context
  status rather than block when they would have to wait for a lock
  (`kAUGraphErr_CannotDoInCurrentContext` in the graph API,
  `.cannotDoInCurrentContext` from manual rendering). Retry on a later cycle
  or hand the work to another thread. Never spin or sleep the render thread.

**Audio workgroups.** Most games need none: the system already joins the
render thread to the output device's workgroup. Adopt them only when the game
runs its own real-time threads (a synth or mixer worker that must finish
inside the same I/O cycle). Read the device's workgroup from the output unit
with `kAudioOutputUnitProperty_OSWorkgroup`; `AudioUnitGetProperty` returns a
+1 reference that you release. Join each helper thread, leave before it
exits, and re-fetch after a device change. Threads on their own cadence get an
interval workgroup from `AudioWorkIntervalCreate`; it is the only public
interval creator, so a render or simulation loop cannot use one (see
`game-loop-and-threading.md`). Apple's asynchronous-workgroup sample uses a
`joinToken` it never declares and names a constant `kOneNanosecond` that
holds 1e9 nanoseconds per second; do not copy either.

```cpp
#include <AudioToolbox/AudioToolbox.h>
#include <cerrno>
#include <os/workgroup.h>

// Called once on each helper thread, after it is made real-time.
// The caller owns the token for the thread's lifetime.
static bool join_device_workgroup(AudioUnit output, os_workgroup_join_token_s *token,
                                  os_workgroup_t *out) {
    os_workgroup_t wg = nullptr;
    UInt32 size = sizeof(wg);
    if (AudioUnitGetProperty(output, kAudioOutputUnitProperty_OSWorkgroup,
                             kAudioUnitScope_Global, 0, &wg, &size) != noErr || !wg)
        return false;
    const int rc = os_workgroup_join(wg, token);   // EALREADY: in another group; EINVAL: cancelled
    if (rc != 0) { os_release(wg); return false; }
    *out = wg;   // later: os_workgroup_leave(wg, token); os_release(wg);
    return true;
}
```

## Spectrum analysis and FFT scaling

For audio-reactive visuals, a beat detector, or a spectrum HUD:

- **Window first.** Hann is the default; build the window once
  (`vDSP.window(ofType:usingSequence:count:isHalfWindow:)` or
  `vDSP_hann_window`) and multiply each block.
- **Prefer the DFT setup for odd sizes.** `vDSP_DFT_zrop_CreateSetup` takes a
  length, not a power of two. Its page allows f × 2ⁿ with f in {1, 3, 5, 15}
  and returns null otherwise. Runtime-checked: 480, 768, 1536, and 1920
  succeed; 1000 returns null.
- **Real input is packed.** `vDSP_ctoz` splits n real samples into n/2
  complex values; the result puts DC in `realp[0]` and Nyquist in `imagp[0]`.
  Special-case bin 0 before computing magnitudes.
- **vDSP does not scale results, and its header pseudocode is wrong about the
  inverse.** The `vDSP.h` comments for the real FFT write the forward as
  `scale = 2` and the inverse as `scale = 1./N`. The data-packing article says
  the real forward is ×2 and the real inverse is ×n. The run agrees with the
  article. Runtime-checked with `vDSP_fft_zrip` at n = 512 and 1024, and with
  the DFT at n = 480:
  - a unit-amplitude cosine at bin k comes back with |X[k]| = n, twice the
    textbook unscaled DFT value n/2;
  - DC comes back as 2 × the sample sum;
  - an unscaled forward then inverse returns the input × 2n.

  So, for an unwindowed block: amplitude of a real tone = |X[k]| / n; power
  from `vDSP_zvmags` divides by n²; a round trip divides by 2n. Forgetting
  the factor of 2 reads every band 6 dB hot. A window scales every reading
  by the mean of its samples, so divide by that too (compute it once with
  `vDSP_meanv`).
- **Reuse the setup.** One setup per size, built at load, reused every block.
  A setup made for a larger size works for smaller ones but runs them slower.
- **Port Apple's spectrogram sample with care.** It grows Swift arrays and
  builds a `CGImage` per buffer, which is fine on a capture queue and wrong on
  the render thread or in the frame loop. Copy samples into a preallocated
  ring buffer from the tap, run the transform on a worker, and upload
  magnitudes to a Metal texture.

```cpp
#include <Accelerate/Accelerate.h>
#include <cmath>

// Magnitudes of one windowed block of n real samples (n = 1 << log2n).
// setup, re, im, and mag are preallocated; mag has n/2 entries.
static void spectrum(FFTSetup setup, vDSP_Length log2n, const float *windowed,
                     float *re, float *im, float *mag) {
    const vDSP_Length n = vDSP_Length(1) << log2n, half = n / 2;
    DSPSplitComplex z = { re, im };
    vDSP_ctoz(reinterpret_cast<const DSPComplex *>(windowed), 2, &z, 1, half);
    vDSP_fft_zrip(setup, &z, 1, log2n, kFFTDirection_Forward);
    const float dc = re[0];
    im[0] = 0.0f;                         // imagp[0] held Nyquist, not part of bin 0
    vDSP_zvabs(&z, 1, mag, 1, half);
    const float scale = 1.0f / float(n);  // forward is x2 the textbook DFT: |X|/n is amplitude
    vDSP_vsmul(mag, 1, &scale, mag, 1, half);
    mag[0] = std::fabs(dc) * scale * 0.5f; // DC comes back as 2 x sum: mean = dc / 2n
}
```

Two page slips to avoid repeating: the `vDSP_vfltu32` summary says "unsigned
16-bit" while the signature takes `unsigned int`, and `vDSP.indexOfMinimum(_:)`
is described as returning the maximum. The single- and multichannel biquad
pages disagree on filter form (direct form 1 against direct form 2); nothing
here depends on which is right.

## AudioToolbox where it is still the right layer

- **Your own pack files.** `AudioFileStreamOpen` and
  `AudioFileStreamParseBytes` parse compressed audio from bytes you push in,
  from an archive or the network. Wait for
  `kAudioFileStreamProperty_ReadyToProducePackets`, then read the data format,
  magic cookie, packet size bound, and `_PacketTableInfo`. A file whose
  packet table sits after the audio data returns
  `kAudioFileStreamError_NotOptimized` and cannot produce packets, so write
  header-first files into the pack.
- **Gapless loops of compressed music.** The packet table's priming and
  remainder frames are the encoder padding to trim; a loop that clicks or gaps
  is usually untrimmed priming. CAF is Apple's container and avoids AIFF and
  WAVE's 32-bit size limits.
- **Load-time decode to the mixer's format** in a C++ engine:
  `ExtAudioFile` with `kExtAudioFileProperty_ClientDataFormat` set to the
  engine's format. Under AVAudioEngine, `AVAudioFile` with a processing format
  does the same.
- **The spatial mixer, voice I/O, and real-time format conversion**, above.
- **Raw unit parameters** (`kMultiChannelMixerParam_*` meters,
  `kAudioUnitSubType_PeakLimiter` on the master bus, the dynamics processor)
  through `AudioUnitSetParameter`, when you host the unit yourself or reach it
  through `withAudioUnit(_:)`. Check the AVFAudio node's own properties first.
- **System sounds.** `AudioServicesPlaySystemSound(_:)` with
  `kAudioServicesPropertyIsUISound` set so the sound follows the user's sound
  effects setting. On iPhone, `kSystemSoundID_Vibrate` vibrates on some
  devices and does nothing on others; Core Haptics replaces it.

## Core Haptics: where haptics can play

The sources disagree, and the SDK settles it.

| Source | Says |
|---|---|
| HIG, Designing for games | Core Haptics on iOS, iPadOS, tvOS, visionOS, and many controllers |
| HIG, Playing haptics | Controller haptics on iPadOS, macOS, tvOS, visionOS (iPhone omitted) |
| Preparing your app to play haptics | iPad, iPod touch, and Vision Pro have no haptics; the Mac is not mentioned |
| Games technologies overview | Core Haptics on iPhone and Apple TV; controller rumble through Game Controller |
| `CHHapticEngine.h` | `API_AVAILABLE(ios(13.0), macos(10.15), tvos(14.0))`. `init()` and `init(audioSession:)` fail with `CHHapticErrorCodeNotSupported` on a system without internal haptics |
| `GCDeviceHaptics.h` | `macos(11.0), ios(14.0), tvos(14.0)` for `GCController.haptics` and `createEngine(withLocality:)` |

What that means per device:

- **Mac:** no actuator Core Haptics can drive on its own. Runtime-checked on
  a Mac mini: `capabilitiesForHardware().supportsHaptics` is `false` and
  `CHHapticEngine()` throws `CHHapticError` code -4809, `.notSupported`. Not
  checked on a laptop with a Force Touch trackpad. A Mac game's haptics are a
  connected controller (`GCDeviceHaptics`) and, for UI only, the trackpad.
- **iPhone:** the built-in Taptic Engine through Core Haptics, plus
  controllers. The HIG's controller list leaves out iPhone; the header has
  `ios(14.0)`, so controller haptics work there too.
- **iPad:** no built-in haptics per the preparing page. Controllers only.
- **visionOS** is out of scope; the Buttons HIG page says the system plays no
  haptics there.

**Gate device haptics on `supportsHaptics`, but not controller haptics.**
The `GCDeviceHaptics` page says the `supportsHaptics` of an engine from
`createEngine(withLocality:)` describes the device, not the controller. Gate
controller rumble on `controller.haptics` being non-nil and its
`supportedLocalities`. A game that gates everything on `supportsHaptics`
turns controller rumble off wherever the device itself has no actuator: the
Mac mini above, and iPad per the preparing page.

```swift
import CoreHaptics
import GameController

enum HapticTarget {
    case device(CHHapticEngine)        // iPhone's built-in Taptic Engine
    case controller(CHHapticEngine)    // any platform, per controller
    case none                          // fall back to sound or a visual cue
}

func hapticTarget(for controller: GCController?) -> HapticTarget {
    if let haptics = controller?.haptics,
       haptics.supportedLocalities.contains(.default),
       let engine = haptics.createEngine(withLocality: .default) {
        return .controller(engine)
    }
    if CHHapticEngine.capabilitiesForHardware().supportsHaptics,
       let engine = try? CHHapticEngine() {
        return .device(engine)
    }
    return .none
}
```

The comment on `CHHapticEngine`'s initializers sends controller users to a
`hapticEngines` property on `GCController`; no such property exists in the
Game Controller headers, and the one to use is `haptics`.
`GCHapticsLocalityDefault` and `GCHapticsLocalityAll` are always supported
(the header guarantees both). For split effects, create one engine per
locality, for example `.leftHandle` as a woofer and `.rightHandle` as a
tweeter, or `.leftTrigger` and `.rightTrigger` where the controller has them.

**Mac trackpad haptics are not a waveform API.**
`NSHapticFeedbackManager.defaultPerformer.perform(_:performanceTime:)` plays
one of three fixed patterns: `.generic`, `.alignment` (a dragged object snaps
into line), and `.levelChange` (a pressure step). The page says to call it only
in response to a user action, ideally with matching visual feedback, and the
system drops it when no finger is on the trackpad. Use it for a level
editor's snap guides or a menu detent, never for gameplay rumble. Request
`defaultPerformer` each time; the device behind it can change.

```swift
import AppKit

func snapFeedback() {
    NSHapticFeedbackManager.defaultPerformer.perform(.alignment, performanceTime: .now)
}
```

On iPhone, use `UIFeedbackGenerator`'s subclasses only for their documented
meanings (notification, impact, selection); anything game-specific is a
Core Haptics pattern.

## Core Haptics: engine lifecycle and patterns

- **Keep a strong reference.** The engine is not a singleton, several may
  exist (one per controller locality, for example), and playback stops when
  the engine is released. Core Haptics is thread-safe.
- **Set `stoppedHandler` and `resetHandler` before `start()`.** The reset
  handler fires after the haptic server recovers; patterns and engine
  properties survive, players and registered audio resources do not. Restart,
  re-register, rebuild players. A restart inside the handler can still fail
  while the cause persists. Both handlers arrive on a non-main thread.
- **`stoppedHandler` reports external stops only**: `.audioSessionInterrupt`,
  `.applicationSuspended`, `.idleTimeout`, `.notifyWhenFinished`,
  `.engineDestroyed`, `.gameControllerDisconnect`, `.systemError`. An explicit
  `stop(completionHandler:)` reports through its completion instead. For a
  controller engine, `.gameControllerDisconnect` means drop it and build a new
  one when a controller connects (see `input.md`). `.systemError` is the case
  to carry on without haptics.
- **Engine start and stop are the expensive part; players are cheap.**
  Start once and leave it running during play. Make a fresh player per
  transient hit. Outside play, `notifyWhenPlayersFinished` returning
  `.stopEngine` saves power.
- **`playPattern(from:)` is fire and forget**: it plays an AHAP to the end,
  cannot be stopped, and layers over whatever is playing. Use an advanced
  player when you need stop, pause, seek, or `loopEnabled`.
- **Dynamic parameters:** intensity and audio-volume controls multiply (0 to
  1), so they only attenuate; sharpness, pitch, pan, and the envelope
  controls add (−1 to 1). `hapticSharpnessControl` affects continuous events
  only. Author at full intensity and scale down at run time. A dynamic
  parameter jumps; schedule a `CHHapticParameterCurve` for a glide.
- **Same-type events at the same instant blur together.** Layer kinds: a
  continuous rumble under transient taps.

Continuous rumble that follows gameplay, and per-hit taps:

```swift
import CoreHaptics

final class GameHaptics {
    let engine: CHHapticEngine
    private var rumble: (any CHHapticAdvancedPatternPlayer)?

    init(engine: CHHapticEngine) throws {
        self.engine = engine
        engine.stoppedHandler = { reason in
            // Called off the main thread. Restart before the next haptic,
            // or give up on .systemError and .gameControllerDisconnect.
            _ = reason
        }
        engine.resetHandler = {
            // Players are gone: restart, then rebuild them (on your own queue).
        }
        try engine.start()
    }

    func startRumble() throws {
        let event = CHHapticEvent(eventType: .hapticContinuous, parameters: [
            CHHapticEventParameter(parameterID: .hapticIntensity, value: 1.0),
            CHHapticEventParameter(parameterID: .hapticSharpness, value: 0.3),
        ], relativeTime: 0, duration: 100)
        let player = try engine.makeAdvancedPlayer(with: CHHapticPattern(events: [event], parameters: []))
        try player.start(atTime: CHHapticTimeImmediate)
        rumble = player
    }

    // Each frame: throttle in 0...1 scales the full-intensity rumble down.
    func setThrottle(_ throttle: Float) throws {
        try rumble?.sendParameters([
            CHHapticDynamicParameter(parameterID: .hapticIntensityControl, value: throttle, relativeTime: 0)
        ], atTime: CHHapticTimeImmediate)
    }

    // A collision: impact speed normalized against a tuned maximum.
    func hit(speed: Float, maxSpeed: Float) throws {
        let s = min(max(speed / maxSpeed, 0), 1)
        let tap = CHHapticEvent(eventType: .hapticTransient, parameters: [
            CHHapticEventParameter(parameterID: .hapticIntensity, value: s),
            CHHapticEventParameter(parameterID: .hapticSharpness, value: 0.4 + 0.6 * s),
        ], relativeTime: 0)
        try engine.makePlayer(with: CHHapticPattern(events: [tap], parameters: [])).start(atTime: CHHapticTimeImmediate)
    }
}
```

**AHAP files** are JSON with exactly two top-level keys, `Pattern` and
`Version`. Missing keys take defaults, out-of-range values clamp, and unknown
keys are ignored, so a misspelled key fails silently: validate AHAP in the
content pipeline. Parameter values are normalized to the device's range, so
1.0 for a time key means the maximum, not one second. Declare `.ahap` assets
with the system type `UTType.ahap` (`com.apple.haptics.ahap`, macOS 14,
iOS 17) rather than a custom one.

HIG rules that hold for every target: one meaning per pattern across the
whole game; match intensity and sharpness to the sound and animation; an
off switch, with the game fully playable without haptics; and check that
vibration does not disturb the camera, gyroscope, or microphone. The
Simulator plays no haptics; test on hardware.

AUGraph's one idea worth keeping in a hand-built C++ graph: edits go through
a queue to the render thread, and the single output unit is where start,
stop, and live edits are safe.
