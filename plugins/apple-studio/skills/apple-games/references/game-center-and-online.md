# Game Center and Online Play: GameKit, Cloud Saves, and the Network Framework

Scope: the online layer of a game. That is sign-in, the Game Center surfaces
(access point, achievements, leaderboards, challenges, activities), GameKit
matchmaking for real-time and turn-based play, saves that follow a player
between devices, and custom netcode on the Network framework. Presentation
rules for Game Center UI (placement, artwork, terminology) are in
`game-design.md`. Frame pacing and threads are in `game-loop-and-threading.md`.
Signing and notarization are in `app-release`.

## Distribution decides the architecture

Answer this question before you write any GameKit code: **how does the Mac
build reach players?**

A Mac app signed with **Developer ID** (downloaded from a website, sent to
friends, sold through a third-party store) **cannot use Game Center, In-App
Purchase, or Sign in with Apple.** Apple's macOS capability table gives those
three to Apple Developer Program members for App Store distribution only. The
Developer ID column is empty for them. The same table gives Developer ID all
three iCloud services (CloudKit, iCloud documents, key-value storage) and push
notifications. Those are restricted entitlements, so the Developer ID build
must embed a Developer ID provisioning profile at
`YourGame.app/Contents/embedded.provisionprofile` (`.provisionprofile` on
macOS, not `.mobileprovision`).

| Need | Mac App Store, iPhone, iPad | Developer ID Mac build |
|---|---|---|
| Achievements, leaderboards, challenges, activities | GameKit | Your own service, or none |
| Find and connect players | `GKMatchmaker`, `GKTurnBasedMatch` | Network framework: Bonjour on the LAN, or your own server |
| Cloud saves | GameSave (OS 26) or `GKSavedGame` | GameSave, CloudKit, or key-value storage, with the embedded profile |
| Purchases | StoreKit In-App Purchase | Not available. Use your own payment route |
| Account | Sign in with Apple, plus `fetchItems(forIdentityVerificationSignature:)` for your server | Your own accounts |
| Push | Yes | Yes, with the embedded profile |

`GKSavedGame` is a GameKit API. It is called on `GKLocalPlayer`, and GameKit
calls fail with `GKError.Code.notAuthenticated` until the player is signed in to
Game Center. For that reason it is not available to a Developer ID build. If
you plan to give a Mac game to friends by Developer ID and also ship it to the
App Store, use the right-hand column as the common core. Then add Game Center
as an extra layer on the App Store builds only. Do not build the reverse.

This machine has no Developer ID identity, so the Developer ID column is
documented behavior. It is not runtime-checked. Signing, the profile, and
notarization are in `app-release/references/direct-distribution.md`.

## Project setup: capabilities, sandbox, privacy strings

- **Game Center capability.** Adds `com.apple.developer.game-center`.
  Configure achievements, leaderboards, sets, challenges, and activities in a
  **GameKit Bundle** file (Xcode 16.3 and later). Test them locally in **Game
  Progress Manager** (Debug > GameKit, with Debug Mode enabled in the scheme).
  That needs iOS 18.4 or macOS 15.4 on a physical device. Then sync to App
  Store Connect. If you delete an item locally after a sync, the item stays in
  App Store Connect. Delete it there too.
- **App Sandbox on the Mac.** Enable **Incoming Connections (Server)** and
  **Outgoing Connections (Client)** under Network, or Game Center and
  multiplayer fail. Those settings are `com.apple.security.network.server` and
  `.client`. For TCP they control only who opens the connection. For **UDP they
  also control the direction of data**: with only the client entitlement, a
  sandboxed app can send UDP but cannot receive it. A UDP game needs both.
- **SharePlay from the matchmaker sheet on macOS** needs the Group Activities
  capability.
- **Privacy strings.** Set `NSGKFriendListUsageDescription` before you call
  any friends API (without it the call fails), `NSLocalNetworkUsageDescription`
  for LAN play, and `NSBonjourServices` listing every service type you
  advertise or browse (`_mygame._udp`). On macOS the friends list is a TCC
  service. Reset it for testing with `tccutil reset GameCenterFriends
  <bundle-id>`.
- **iCloud for saves.** GameSave and `GKSavedGame` both need the iCloud
  capability with **iCloud Documents** selected and a container (`iCloud.` plus
  reverse DNS). When you remove the capability in Xcode, iCloud stays enabled
  on the App ID. Disable it in the developer account.

## Authentication and the listener

Set `GKLocalPlayer.local.authenticateHandler` at launch. Do not wait for the
player to open a menu. GameKit can call the handler several times:

- **With a view controller.** Present it: sign-in is needed. On macOS the
  handler's type is `(NSViewController?, Error?)`. On iOS it is
  `(UIViewController?, Error?)`.
- **With neither.** The player is signed in. Check the restrictions, then
  register your listener **at once**. The system can launch or foreground the
  game to deliver a turn or an invite, and an event that arrives before you
  register is lost.
- **With an error.** The player declined or Game Center is off. Disable the
  Game Center features and keep the game playable.

```swift
import AppKit
import GameKit

@MainActor
final class GameCenterSession: NSObject, GKLocalPlayerListener {
    weak var window: NSWindow?
    private(set) var multiplayerAllowed = false

    func start() {
        GKLocalPlayer.local.authenticateHandler = { viewController, error in
            Task { @MainActor in          // the handler's thread is not documented
                if let viewController {
                    self.window?.contentViewController?.presentAsSheet(viewController)
                    return
                }
                let player = GKLocalPlayer.local
                guard error == nil, player.isAuthenticated else {
                    self.multiplayerAllowed = false   // Game Center off: game still runs
                    return
                }
                self.multiplayerAllowed = !player.isMultiplayerGamingRestricted
                player.register(self)                 // before any other GameKit call
            }
        }
    }
}
```

After each successful sign-in, also check `isUnderage` (hide explicit
content) and `isPersonalizedCommunicationRestricted` (disable voice, text, and
custom chat). Store player data under `gamePlayerID`, never the display name,
and only after `scopedIDsArePersistent()` returns `true`. If sign-in failed,
the IDs last only until the game quits. `teamPlayerID` changes when the game
moves to another team. Game Center is not an account system for your servers:
to prove a player's identity to your backend, call
`fetchItems(forIdentityVerificationSignature:)` and verify the signature on
the server.

## The access point replaces the dashboard view controller

**In the 26 SDKs `GKGameCenterViewController` is deprecated, and its
replacement is `GKAccessPoint`.** The dashboard article, the real-time
sample, and the `GKDialogController` page (the macOS route) still present the
view controller. Do not copy that path. Two more 26
deprecations: `GKAccessPoint.showHighlights` ("No longer supported", but the
`GKAccessPoint` class page still says to set it) and
`GKGameCenterViewControllerState.challenges`, which `GKChallengeDefinition`
replaces. The SDK wins over the page.

```swift
@MainActor
func showAccessPointOnMainMenu(in window: NSWindow) {
    let accessPoint = GKAccessPoint.shared
    accessPoint.location = .topLeading     // corners flip for right-to-left languages
    accessPoint.parentWindow = window
    accessPoint.isActive = true            // set placement first, then activate
}

@MainActor
func openDailyBoard() {
    GKAccessPoint.shared.trigger(leaderboardID: "daily.time",
                                 playerScope: .friendsOnly,
                                 timeScope: .today) { }
}

@MainActor
func openPlayTogether() async {
    await GKAccessPoint.shared.triggerForPlayTogether()
}
```

- `isActive = false` during gameplay, cutscenes, and intros. Observe
  `isPresentingGameCenter` and pause the simulation while it is `true`.
  Observe `frameInScreenCoordinates` to keep HUD elements clear of the
  control.
- The state triggers (`trigger(state:handler:)` with `.dashboard`,
  `.leaderboards`, `.achievements`, `.localPlayerProfile`,
  `.localPlayerFriendsList`) predate the floor. The ID triggers
  (`trigger(achievementID:)`, `trigger(leaderboardSetID:)`,
  `trigger(leaderboardID:playerScope:timeScope:)`, `trigger(player:)`) need
  iOS 18 or macOS 15.
- `triggerForPlayTogether`, `triggerForChallenges`,
  `trigger(challengeDefinitionID:)`, `trigger(gameActivityDefinitionID:)`,
  `trigger(gameActivity:)`, and `triggerForFriending` are **iOS 26 and macOS
  26 only**. The header marks them unavailable on tvOS and visionOS. A game
  that also ships there needs another entry point.
- A game that does its own controller focus must hit-test the access point's
  frame and call a trigger itself. The system does not do this for it.
- To send a friend request from your own UI, call
  `presentFriendRequestCreator(from:)`. It takes an `NSWindow?` on macOS
  (macOS 12) and a view controller on iOS.

## Achievements and leaderboards

- **Achievements.** `GKAchievement.loadAchievements()` returns only the
  achievements that already have progress. For any other achievement, create
  `GKAchievement(identifier:)`. Set `percentComplete` (0–100), then call
  `GKAchievement.report(_:)`. The budget is 100 achievements and 1,000 points.
  Spread them over several releases.
- **Scores are integers.** The display format in the GameKit Bundle formats
  the value. For example, Elapsed Time to the hundredth expects
  centiseconds, so submit 10000 for 1:40.00. Score ranges use the same units.
- **Submit with the class method.** It always writes to the current
  occurrence of a recurring board:

```swift
func finishRun(score: Int) async throws {
    try await GKLeaderboard.submitScore(score, context: 0,
                                        player: GKLocalPlayer.local,
                                        leaderboardIDs: ["daily.time"])
}
```

  The instance method `submitScore(_:context:player:)` on a loaded
  `GKLeaderboard` **fails when that occurrence has ended**. The
  recurring-leaderboards page says the instance method is "only" for
  recurring boards, but its own sample uses the class method. Use the class
  method. `context` is a free integer that is stored with the score (track,
  car, difficulty).
- **IDs are permanent.** Leaderboard IDs cannot change, and leaderboard sets
  are a one-way change. After you adopt sets, every new leaderboard must go
  in a set (up to 500 leaderboards in 100 sets, against 100 without sets).
  Choose the ID scheme before the first sync.
- **The pre-26 types are gone.** Do not use `GKScore` (use `GKLeaderboard`
  submissions), `GKLeaderboardViewController`, or
  `GKAchievementViewController`. The old `GKChallenge` family and
  `GKChallengeListener` are deprecated at 26.

## Challenges and activities (OS 26)

`GKChallengeDefinition`, `GKGameActivity`, `GKGameActivityDefinition`, and
`GKGameActivityListener` are all `API_AVAILABLE(ios(26.0), macos(26.0),
tvos(26.0), visionos(26.0))`. They supply the content that the Games app shows
and deep-links into the game.

**Challenges** sit on a leaderboard. No code is needed past the score
submission. A score submitted to a challenge's board counts toward that
challenge. **Every submission uses up one attempt**, so submit once at the end
of a run. Also submit when the player quits early. Never submit per point, at
launch, or from a menu. Submit the latest score even when it is not a
personal best, and set the board's Score Submission Type to Best Score. A
repeatable challenge needs a **recurring** board. Use
`hasActiveChallenges` on a definition to badge an entry point.

**Activities** route a player into a mode, carry a party code, and record
scores and achievement progress locally. Nothing posts until `end()`.
`setScore(on:to:)` and `setProgress(on:to:)` cost nothing to call each frame,
and a run the player abandons never posts.

The activities article gives four names that do not compile in Swift. Use the
SDK spellings:

| Article writes | SDK (`GKGameActivityDefinition.h`, `GKGameActivity.h`) |
|---|---|
| `associatedAchievementDescriptions` | `achievementDescriptions` (and `leaderboards`) |
| `activity.activityIdentifier` | `activity.activityDefinition.identifier`. `activity.identifier` is the instance ID |
| `GKGameActivity.start(_:partyCode:)` | `GKGameActivity.start(definition:partyCode:)` |
| `scoreForLeaderboard`, `setScoreOnLeaderboard` | Objective-C selectors. Swift: `score(on:)`, `setScore(on:to:)` |

```swift
final class ActivityRouter: NSObject, GKLocalPlayerListener {
    func player(_ player: GKPlayer, wantsToPlay activity: GKGameActivity) async -> Bool {
        switch activity.activityDefinition.identifier {
        case "com.example.game.daily-puzzle":
            return true    // load the puzzle; activity.partyCode is set if one exists
        default:
            return false
        }
    }
}

func hostParty(definitionID: String, typedCode: String) async throws -> GKGameActivity? {
    let definitions = try await GKGameActivityDefinition.all
    guard let definition = definitions.first(where: { $0.identifier == definitionID }),
          definition.supportsPartyCode else { return nil }
    let code = typedCode.uppercased()
    guard GKGameActivity.isValidPartyCode(code) else { return nil }
    let boards = try await definition.leaderboards
    _ = boards
    return try GKGameActivity.start(definition: definition, partyCode: code)
}
```

Party-code format, runtime-checked on this machine (see the record's
`task-8-write/runtime/game-center-and-online/runs.txt`):
`validPartyCodeAlphabet` has 20 characters, `23456789CFGHJMPQRVWX`. A valid code
has two halves of equal length, 2 to 6 characters each, joined by a dash
(`2MP4-9CMF`, `CF-GH`). A code made only of digits can use 0 through 9.
**`isValidPartyCode` rejects lowercase**, although
`start(definition:partyCode:)` documents that it uppercases the code. So
uppercase what the player types before you validate it.

A party code also works when you use your own networking.
`findPlayersForHostedMatch()` on the activity returns the players, and your
server connects them. On systems older than 26, or on other platforms, an
invite opens the definition's `fallbackURL` as
`{startActivityURL}?a={activityIdentifier}&c={partyCode}`. Back that URL with a
universal link.

## Real-time matches

`GKMatch` is a **peer-to-peer full mesh**. It suits small sessions with no
server. Use `chooseBestHostingPlayer` (call it on
every device at the same time) to put a host-authority model on top of the
mesh. When you need authority, anti-cheat, or many players, use a **hosted**
match: Game Center finds the players and returns `GKPlayer` values, not a
`GKMatch`, and your server does the transport.

```swift
final class MatchDriver: NSObject, GKMatchDelegate {
    func match(_ match: GKMatch, player: GKPlayer, didChange state: GKPlayerConnectionState) {
        if state == .connected, match.expectedPlayerCount == 0 {
            // Every slot is filled: start the simulation.
        }
    }
    func match(_ match: GKMatch, didReceive data: Data, fromRemotePlayer player: GKPlayer) {
        // Decode a snapshot or an event.
    }
}

func quickMatch(driver: MatchDriver) async throws -> GKMatch {
    let request = GKMatchRequest()
    request.minPlayers = 2
    request.maxPlayers = 4
    let match = try await GKMatchmaker.shared().findMatch(for: request)
    match.delegate = driver    // at once: automatched players may still be connecting
    return match
}

func sendSnapshot(_ snapshot: Data, on match: GKMatch) throws {
    try match.sendData(toAllPlayers: snapshot, with: .unreliable)
}
```

- `.unreliable` sends once, and packets can arrive out of order. Use it for
  per-tick state. `.reliable` retries until delivered, in order. Use it for
  outcomes and chat.
- Read size limits from `GKMatchRequest.maxPlayersAllowedForMatch(of:)`
  (`.peerToPeer`, `.hosted`, `.turnBased`). Do not hard-code them.
- On macOS, `GKMatchmakerViewController` is an `NSViewController`. Present it
  through `GKDialogController`. `GKDialogController` is not deprecated. Only
  the dashboard view controller it used to present is.
- Matchmaking rules (skill bands, teams, party queues) are configured on the
  server through the App Store Connect API (`gameCenterMatchmakingRuleSets`,
  `…Rules`, `…Queues`). The client sets only `GKMatchRequest.queueName` and
  `properties`. When rules are active, `playerGroup` and `playerAttributes` are
  ignored. Two corrections to the articles: the skill-level expression puts the
  thresholds array **before** the ages array, although the prose lists ages
  first. And the party-code rule goes to `/v1/gameCenterMatchmakingRules`,
  although the prose names the rule-sets endpoint. The team article's
  `properties["gc"]["team"]` is pseudo-code. The value is a `[String: Any]`
  and needs casts.
- **Voice.** `GKVoiceChat` and `GKMatch.voiceChat(withName:)` are deprecated
  as of iOS 18 and macOS 15 ("No longer supported"). Use
  `GKMatchmaker.startGroupActivity(playerHandler:)` (SharePlay over FaceTime)
  for voice, or your own audio path (`audio-and-haptics.md`).
- Testing needs an App Store Connect app record, two physical devices, and a
  different Apple Account signed in to each.

## Turn-based matches

Game Center stores the match state and forwards it, and it can notify players
while the game is not running. Nearly every event arrives at
`player(_:receivedTurnEventFor:didBecomeActive:)`. Turn-based matchmaking
**does not use matchmaking rules**. It uses only `minPlayers`, `maxPlayers`,
`playerGroup`, `playerAttributes`, and `recipients`.

**The sample has a bug.** The next-participants filter in "Starting
turn-based matches" is written `($0.status != .done) || ($0 !=
match.currentParticipant)`. That keeps both finished players and the current
player. The intended filter is `&&`:

```swift
enum TurnError: Error { case stateTooLarge }

func passTurn(_ match: GKTurnBasedMatch, state: Data) async throws {
    guard state.count <= match.matchDataMaximumSize else { throw TurnError.stateTooLarge }
    let next = match.participants.filter {
        $0.status != .done && $0 != match.currentParticipant
    }
    let oneWeek: TimeInterval = 7 * 24 * 60 * 60   // GKTurnTimeoutDefault's value
    try await match.endTurn(withNextParticipants: next,
                            turnTimeout: oneWeek,
                            match: state)
}
```

`GKTurnTimeoutDefault` is a C global `var` (one week, per `GKTurnBasedMatch.h`).
Swift 6 language mode rejects a reference to it as shared mutable state, so
spell the interval out.

- **`matchDataMaximumSize` has no published number.** The symbol page and
  `GKTurnBasedMatch.h` give only the property, and the page says that an
  oversized send is an error. Read the property at runtime. Store only what a
  player needs to resume, not a full world snapshot.
- List several next participants when more than two people play. Game Center
  moves to the next one if a player times out (the maximum timeout is 90
  days).
- Keep `matchID`, not the `GKTurnBasedMatch` object, which goes stale. Call
  `load(withID:)` again before you act. It is your turn when
  `match.currentParticipant?.player == GKLocalPlayer.local`.
- Invitations go out only when the creator ends the first turn. Until then,
  show placeholder opponents.
- Only the current participant can write match data. A player who quits in
  turn calls `participantQuitInTurn`, and out of turn calls
  `participantQuitOutOfTurn`. **Exchanges** let waiting players trade out of
  turn. The current participant must merge them with
  `saveMergedMatch(_:withResolvedExchanges:)` before ending the match.
- `sendReminder(to:localizableMessageKey:arguments:)` is rate-limited to once
  every 10 minutes (`GKServerTurnBasedMaxSessionOtherError`). Disable the
  button for that period.

## Saves across devices

| Option | Platforms (SDK) | Shape | Choose it when |
|---|---|---|---|
| **GameSave** `GameSaveSyncedDirectory` | iOS, iPadOS, macOS, visionOS 26. Not tvOS | A directory of your files, synced over iCloud Drive, with conflict and offline handling and system alerts | The default for a new game on OS 26. The capability table allows its iCloud Documents entitlement in a Developer ID build, with the embedded profile |
| **`GKSavedGame`** | iOS and macOS (header: `API_UNAVAILABLE(tvos, watchos)`) | Named blobs on `GKLocalPlayer` | Existing code, or a game below OS 26. Needs Game Center, so not Developer ID |
| **`NSUbiquitousKeyValueStore`** | All, tvOS included | 1,024 keys and 1 MB total, plist types | Settings and small flags, or an Apple TV build |
| **CloudKit** | All | Records, a public database | Structured or shared data: ghosts, user levels, your own leaderboard |

GameSave behavior to design around:

- `openDirectory(containerIdentifier:)` starts syncing in the background and
  returns at once. With `nil` it uses the first container listed in
  `com.apple.developer.icloud-container-identifiers`.
- `finishSyncing(statusDisplay:)` shows the system progress and
  conflict-resolution alerts. If iCloud Drive is off, it tells the player and
  switches to local saving. Use `finishSyncing()` if you draw your own UI.
- **Once the directory is ready, syncing pauses** until you `close()` the
  directory or it is deallocated. To push a save mid-session, close the
  directory and open it again, which is the documented route.
  `triggerPendingUpload()` is listed next to `close()` under "Finishing with a
  directory". Call it, then `close()`, when the game quits.

```swift
import GameSave

@MainActor
final class SaveStore {
    private var directory: GameSaveSyncedDirectory?

    func open(showingProgressIn window: NSWindow) async -> URL? {
        let directory = GameSaveSyncedDirectory.openDirectory(containerIdentifier: nil)
        self.directory = directory
        await directory.finishSyncing(statusDisplay: window)
        switch directory.state {
        case .ready(let url), .offline(let url), .local(let url):
            return url              // read and write your own files here
        case .conflicted(let versions):
            if let newest = versions.max(by: { $0.modifiedDate < $1.modifiedDate }) {
                directory.resolveConflicts(with: newest)
            }
            return nil              // check the state again after resolving
        case .syncing, .error, .closed:
            return nil
        @unknown default:
            return nil
        }
    }

    func checkpoint() {
        directory?.close()          // resumes syncing to iCloud
        directory = nil
    }
}
```

Use a versioned, platform-neutral format, and make it a file package, so iCloud
uploads only the sub-files that changed. Never put caches or downloaded assets
in the synced directory: they count against the player's quota and backups.
`GKSavedGame` reports conflicts through
`player(_:hasConflictingSavedGames:)` on the registered listener. Resolve them
with `resolveConflictingSavedGames(_:with:)`. File types for save packages
are in `assets.md`.

## Custom multiplayer on the Network framework

Use the Network framework for your own TCP, UDP, QUIC, or TLS game
protocols. Keep `URLSession` for HTTP backends. On a Developer ID Mac build,
the Network framework is the multiplayer layer.

**Choose the API by your floor and your language:**

- **Swift, OS 26 or later: `NetworkConnection`, `NetworkListener`, and
  `NetworkBrowser`** (all `macOS 26.0, iOS 26.0`). Protocol stacks are
  declared in a result builder (`QUIC`, `TCP`, `TLS`, `UDP`, `TLV`,
  `WebSocket`, `Coder` for `Codable` messages), and send and receive are
  `async`. This API is newer than most training data, so check every spelling
  against the SDK. The Swift `DTLS` struct is **macOS 27 / iOS 27**, not 26.
- **Swift below 26: `NWConnection`, `NWListener`, `NWBrowser`,
  `NWConnectionGroup`.**
- **C or C++ engine: the `nw_*` C API.** It has the same transport, and it
  needs no Swift.

**QUIC is the best default transport for real-time state.**
`QUICDatagram` carries unreliable RFC 9221 datagrams for snapshots, and QUIC
streams carry reliable events, both on one encrypted connection. Where L4S is
enabled (iOS 17 and later, for some users), Apple supports it on both sender
and receiver only for QUIC. TCP gets the receiver side only, and raw UDP gets
no congestion control from Apple at all.

```swift
import Foundation
import Network

func streamSnapshots(host: String, port: UInt16, snapshots: AsyncStream<Data>) async throws {
    let endpoint = NWEndpoint.hostPort(host: NWEndpoint.Host(host),
                                       port: NWEndpoint.Port(integerLiteral: port))
    try await withNetworkConnection(to: endpoint, using: {
        QUIC(alpn: ["mygame/1"]).maxDatagramFrameSize(1200)
    }) { connection in
        let datagrams = try await connection.datagrams
        for await snapshot in snapshots {
            // Keep each snapshot within connection.usableDatagramFrameSize.
            try await datagrams.send(snapshot)
        }
    }
}
```

A LAN game that wants DTLS rather than QUIC must use different code on each
OS version:

```swift
func lanParameters() -> NWParameters {
    // OS 26 path: DTLS through the classic NWParameters.
    NWParameters(dtls: NWProtocolTLS.Options(), udp: NWProtocolUDP.Options())
}

func sendOverDTLS(_ payload: Data, to endpoint: NWEndpoint) async throws {
    if #available(macOS 27, iOS 27, *) {
        try await withNetworkConnection(to: endpoint, using: { DTLS() }) { connection in
            try await connection.send(payload)
        }
    } else {
        let connection = NWConnection(to: endpoint, using: lanParameters())
        connection.start(queue: .global(qos: .userInitiated))
        connection.send(content: payload, completion: .contentProcessed { _ in })
    }
}
```

**C API knobs worth knowing** (all predate the floor unless noted):
`nw_connection_get_maximum_datagram_size` (size packets from it, not from a
guessed MTU), `nw_connection_batch` (flush one tick's packets in a batch),
`nw_content_context_set_expiration_milliseconds` (drop a stale snapshot that
has not started sending), `nw_ip_options_set_calculate_receive_time` (kernel
receive timestamps for jitter measurement), and
`nw_connection_create_new_data_transfer_report` (smoothed RTT and
retransmits). Call `nw_connection_set_queue` before `nw_connection_start`, and
on your own serial queue, never the render thread. Two newer calls:

```cpp
#include <Network/Network.h>
#include <cerrno>
#include <cstdint>

// Tune initial send rate from the link (OS 26). Do not gate connects on it.
const char* linkLabel(nw_path_t path) {
    switch (nw_path_get_link_quality(path)) {
    case nw_link_quality_good:     return "good";
    case nw_link_quality_moderate: return "moderate";
    case nw_link_quality_minimal:  return "minimal";
    default:                       return "unknown";
    }
}

// Cap a background TCP download so it leaves room for game traffic (OS 27).
int capDownload(nw_connection_t ready, uint64_t bytesPerSecond) {
    if (__builtin_available(macOS 27.0, iOS 27.0, *)) {
        nw_protocol_definition_t tcp = nw_protocol_copy_tcp_definition();
        nw_protocol_metadata_t meta = nw_connection_copy_protocol_metadata(ready, tcp);
        nw_release(tcp);
        if (meta == nullptr) return EINVAL;    // not established yet
        int err = nw_tcp_set_max_pacing_rate(meta, bytesPerSecond);
        nw_release(meta);
        return err;                            // 0, or a POSIX errno
    }
    return ENOTSUP;                            // OS 26: throttle in the app
}
```

`nw_tcp_set_max_pacing_rate` is `API_AVAILABLE(anyappleos(27.0))`. A rate of 0
or `UINT64_MAX` turns pacing off. Rates under 12,500 bytes per second are
raised to 12,500. Its documentation tells you to get the metadata from
`nw_connection_access_established_protocol_metadata`, which is not in the
SDK. Use `nw_connection_copy_protocol_metadata` on a ready connection, as
above. `nw_path_get_link_quality` is OS 26. Its header says to use it to set
starting values, and not to gate connection attempts on it.

**LAN play and local network privacy** (macOS 15 and later, iOS 14 and later):

- Outgoing TCP, sending UDP, any multicast or broadcast, `.local` DNS names,
  and every Bonjour operation trigger the Local Network alert. Accepting a TCP
  connection and receiving unicast UDP do not.
- The system may deny the first operation before the player answers the
  alert. The Network framework waits and retries by itself. Detect a refusal
  with `NWPath.UnsatisfiedReason.localNetworkDenied` (`waiting` state), or
  `nw_path_unsatisfied_reason_local_network_denied` in C.
- **Multicast and broadcast on iOS need
  `com.apple.developer.networking.multicast`**, and Apple must approve the
  request for it. The entitlement also covers browsing arbitrary Bonjour
  types. **macOS does not need it.** Prefer Bonjour discovery
  (`NWBrowser`, `NetworkBrowser` with `Bonjour`) to a home-made UDP broadcast
  beacon. It avoids the entitlement, and it avoids the hard-coded `en0`
  assumption.
- On macOS the privilege follows the code signature. Sign test builds with an
  Apple-issued identity, not "Sign to Run Locally". Reset the privilege in
  System Settings (the remove button needs macOS 27.2). Earlier versions have
  no reset, so test in a fresh user account or a VM. The simulator has no
  local network privacy. Test on a device.
- For TLS between players on a LAN, a pre-shared key derived from the join
  code (`sec_protocol_options_add_pre_shared_key`) is more practical than a
  local certificate authority, which needs a root certificate on every client.

Portable C or C++ netcode can hide main-thread blocking, and the watchdog kills
a process that blocks. `gethostbyname` is never safe on the main thread.
`getaddrinfo` is safe only with `AI_NUMERICHOST`. Replace
`SCNetworkReachability` with `NWPathMonitor` started on your own queue. For
UDP debugging, capture with `tcpdump` on the Mac, or with `rvictl -s <UDID>`
for an iPhone over USB. Find the Wi-Fi interface with `networksetup
-listallhardwareports` rather than assuming `en0`.

## Classic pitfalls

- **Planning Game Center for a Developer ID Mac build.** It is not available.
  Decide the distribution channel first.
- **Copying the articles' dashboard code.** `GKGameCenterViewController`,
  `showHighlights`, and `.challenges` are deprecated in the 26 SDKs. Use the
  `GKAccessPoint` triggers.
- **Typing the activities article's names.** `associatedAchievementDescriptions`,
  `activityIdentifier`, and `start(_:partyCode:)` do not compile.
- **Copying the turn-based `||` filter.** It passes the turn back to the
  current player or to a finished one. Use `&&`.
- **Registering the listener late.** Turn and invite events that arrive
  before `register(_:)` are lost.
- **Submitting a challenge score per point.** Each submission uses up an
  attempt.
- **Enabling only outgoing connections in the Mac sandbox.** Game Center
  fails, and UDP replies never arrive.
- **Holding a GameSave directory open for the whole session.** Nothing syncs
  until it closes.
- **Validating a typed party code before uppercasing it.**
- **Writing new voice chat on `GKVoiceChat`.** It is deprecated as of iOS 18 and
  macOS 15.
- **Assuming the Swift `DTLS` stack is OS 26.** It is OS 27. On OS 26, use
  `NWParameters(dtls:udp:)` or QUIC.
