Scope: *the GPU decides what runs*. That covers compute passes and how to size them, indirect
arguments and indirect command buffers (ICBs), object and mesh shaders, acceleration structures
and ray tracing, and when Metal Performance Shaders (MPS), MPSGraph, or a machine-learning pass
saves you writing a kernel. The frame, the queue, and the full barrier rules belong to
`command-model.md`. Pipeline compilation belongs to `pipelines-and-render-passes.md`. MSL
semantics (address spaces, atomics, SIMD-group functions) belong to `shading-language.md`, and
tile shaders belong to `apple-gpu-tbdr.md`.

Family names below are the *Metal Feature Set Tables* (May 21, 2026) rows. The Metal 4 model
starts at Apple7 (A14, M1). M3 and M4 are Apple9, and A19 and M5 are Apple10. Where a doc page
and the tables disagree on a gate, this file follows the tables and says so.

## Pick the mechanism first

| The work | Reach for | Gate (tables) |
|---|---|---|
| Data-parallel math, post effects, simulation | A compute pass on `MTL4ComputeCommandEncoder` | Metal 4 model, Apple7 |
| A GPU result decides how big the next dispatch or draw is | Indirect arguments (`dispatchThreadgroups(indirectBuffer:threadsPerThreadgroup:)`) | Apple3 |
| Thousands of static draws you would otherwise re-encode | A CPU-encoded ICB | Apple3 |
| Per-object culling or LOD every frame, decided on the GPU | A GPU-encoded ICB | Apple3; ICB memory barriers in render ICBs Apple9 |
| Culling or generating geometry *below* object granularity (meshlets, grass, hair) | Object + mesh shaders | Apple7; indirect mesh draws and ICBs holding mesh draws Apple9 |
| Visibility, shadows, reflections, AI line of sight, sound occlusion | Acceleration structures + intersectors | Apple6; hardware ray tracing Apple9 |
| A standard image filter or a GEMM you do not want to write | MPS (Metal 3 command buffer) or MPSGraph | MPS from Apple2 |
| Running a Core ML model inside the frame | `MTL4MachineLearningCommandEncoder` | Metal 4 model, Apple7 |
| A small network fused into your own shader | Metal Performance Primitives tensor ops in MSL | Metal 4 model, Apple7 |

Escalate only as far as profiling demands. The *Metal by Tutorials* ladder holds: plain draws,
then instancing, then a CPU ICB, then a GPU ICB, then mesh shaders. Each step costs setup and
debugging time and gains nothing without the matching workload. The book warns that GPU encoding
without real culling or LOD can run *slower* than CPU encoding.

## Compute passes in Metal 4

**One encoder covers three pass kinds.** `MTL4ComputeCommandEncoder`, from
`MTL4CommandBuffer.makeComputeCommandEncoder()`, holds dispatches (`.dispatch` stage), copies,
fills, mip generation and ICB maintenance (`.blit` stage), and acceleration-structure builds
(`.accelerationStructure` stage). Metal 4 has no separate blit or acceleration-structure
encoder. Keep related work in one pass, because every pass boundary has a fixed setup cost on
Apple GPUs.

**Dispatches in one Metal 4 compute pass run concurrently by default.** This is the opposite of
the Metal 3 default, where `MTLComputePassDescriptor.dispatchType` is `.serial`. Two dispatches
in one pass, or a copy and a dispatch, overlap unless you put an intrapass barrier
(`barrier(afterEncoderStages:beforeEncoderStages:visibilityOptions:)`) between them. Code ported
from Metal 3 that relied on serial order corrupts data silently. Apple's porting guide is
explicit that Apple GPUs exploit missing synchronization aggressively, so code that looked fine
on an Intel or AMD Mac breaks on Apple silicon.

**Resources are untracked.** Metal 4 ignores `hazardTrackingMode` for work on an
`MTL4CommandQueue`. Every write-then-read between passes needs a barrier, a fence, or an event.
`command-model.md` owns the scope ladder; in this file, the rule is simply that the GPU-driven
patterns below always need one more barrier than the Metal 3 sample you are porting.

**Binding goes through an argument table.** There is no `setBuffer` and no `setBytes`. Bind
buffers by `gpuAddress` with `setAddress(_:index:)`, and textures, acceleration structures, and
ICBs by `gpuResourceID`. Small constants live in a per-frame buffer slice, not inline bytes.
`setThreadgroupMemoryLength(_:index:)` takes a multiple of 16 bytes (the tables' threadgroup
memory length alignment is 16 B on every family).

**Residency is yours, and so is lifetime.** Anything a dispatch reaches must sit in a residency
set attached to the command buffer or the queue. That includes indirect-argument buffers, the
ICB, every buffer its commands reference, the scratch buffer of an acceleration-structure build,
and the acceleration structures themselves. The SDK makes `MTLComputePipelineState` and
`MTLRenderPipelineState` conform to `MTLAllocation`, and the SDK header for `executeCommands`
requires you to add any pipeline state an ICB references to a residency set. A Metal 4 command buffer does
not retain what it references, and API Validation's unretained-resource check does not cover
`MTL4CommandBuffer`, so free nothing until the GPU signals completion.

**An out-of-bounds device or threadgroup access can fault an Apple GPU** and end the command
buffer. A discrete GPU may have tolerated it. Run Shader Validation before blaming the driver
(`gpu-debugging-and-profiling.md`).

```swift
/// One compute pass: upload parameters with a copy, then run a kernel that reads them.
/// The barrier is required: copies and dispatches in one Metal 4 pass overlap.
func encodeUploadThenFilter(commandBuffer: any MTL4CommandBuffer,
                            pipeline: any MTLComputePipelineState,
                            table: any MTL4ArgumentTable,
                            staging: any MTLBuffer, params: any MTLBuffer,
                            source: any MTLTexture, destination: any MTLTexture) {
    guard let pass = commandBuffer.makeComputeCommandEncoder() else { return }
    pass.copy(sourceBuffer: staging, sourceOffset: 0,
              destinationBuffer: params, destinationOffset: 0, size: staging.length)
    pass.barrier(afterEncoderStages: .blit, beforeEncoderStages: .dispatch,
                 visibilityOptions: .device)

    table.setTexture(source.gpuResourceID, index: 0)
    table.setTexture(destination.gpuResourceID, index: 1)
    table.setAddress(params.gpuAddress, index: 0)
    pass.setComputePipelineState(pipeline)
    pass.setArgumentTable(table)
    pass.dispatchThreads(threadsPerGrid: MTLSize(width: destination.width,
                                                 height: destination.height, depth: 1),
                         threadsPerThreadgroup: pipeline.requiredThreadsPerThreadgroup)
    pass.endEncoding()
}
```

## Sizing dispatches

**Read the shape from the pipeline, never from a constant.** `threadExecutionWidth` is the
SIMD-group width, and it varies across GPUs, Mac GPUs especially, so never hardcode 32.
`maxTotalThreadsPerThreadgroup` depends on the GPU and on the kernel's register and
threadgroup-memory use. It is fixed once the pipeline exists, but two pipelines on one device
can report different values. The tables' 1,024 threads per threadgroup (Apple4 and later) is a
theoretical ceiling. The largest 2D group is `w × (max / w) × 1`. Make the total a multiple of
the SIMD width. In MSL, take `[[threads_per_simdgroup]]` rather than assuming a width; the spec
marks `thread_execution_width` deprecated since Metal 3.

**`dispatchThreads(threadsPerGrid:threadsPerThreadgroup:)` is the default on the Metal 4
path.** It takes a total thread count, and Metal builds smaller edge threadgroups, so the kernel
needs no bounds check for the grid edge. Nonuniform threadgroups are an Apple4 feature, so every
Metal 4 device has them. Use `dispatchThreadgroups(threadgroupsPerGrid:threadsPerThreadgroup:)`
only when the kernel needs uniform groups (shared-memory tiling). Then round up with
`(n + w - 1) / w` and exit early past the data. The book adds that Simulator lacks nonuniform
threadgroups.

**Fix the threadgroup size at compile time when the kernel depends on it.** Three places can
pin it, and they must agree or pipeline creation fails:

- `[[required_threads_per_threadgroup(x, y, z)]]` on the kernel (MSL 4.0);
- `MTL4ComputePipelineDescriptor.requiredThreadsPerThreadgroup` (also on
  `MTLComputePipelineDescriptor` and the tile pipeline descriptors);
- `MTLCompileOptions.requiredThreadsPerThreadgroup`, for source you compile at runtime (macOS
  and iOS 26).

Once it is set, every dispatch's `threadsPerThreadgroup` must equal it. The descriptor property
is optional except for pipelines that use cooperative tensors, where it is required. The MSL 4.1
spec places `requiredThreadsPerThreadgroup` on `MTLDevice`; the SDK has no such property, and
the SDK wins. The compiled value reads back from `MTLComputePipelineState.requiredThreadsPerThreadgroup`.

`[[max_total_threads_per_threadgroup(n)]]`, `MTL4ComputePipelineDescriptor.maxTotalThreadsPerThreadgroup`,
and `MTLCompileOptions.maxTotalThreadsPerThreadgroup` cap the size instead. An attribute value
above `MTLDevice.maxThreadsPerThreadgroup` fails pipeline creation. For functions compiled into
a dynamic library,
`-fmax-total-threads-per-threadgroup` keeps the library compatible with the pipeline that links
it. `threadGroupSizeIsMultipleOfThreadExecutionWidth` is a promise you make so the compiler can
drop edge handling. Set it only if every dispatch keeps it.

`MTL4ComputePipelineDescriptor` also exposes `contentionRelief`, `forwardProgressUsage`, and
`optimizeForPersistentKernel`. Their pages carry no semantics yet, so leave them at their
defaults rather than guess.

```swift
/// Compile a compute pipeline whose kernel assumes 16 x 16 groups.
func makeFilterPipeline(device: any MTLDevice, library: any MTLLibrary) throws
    -> any MTLComputePipelineState {
    let compiler = try device.makeCompiler(descriptor: MTL4CompilerDescriptor())
    let function = MTL4LibraryFunctionDescriptor()
    function.library = library
    function.name = "filterTile"
    let descriptor = MTL4ComputePipelineDescriptor()
    descriptor.computeFunctionDescriptor = function
    descriptor.requiredThreadsPerThreadgroup = MTLSize(width: 16, height: 16, depth: 1)
    return try compiler.makeComputePipelineState(descriptor: descriptor,
                                                 dynamicLinkingDescriptor: nil,
                                                 compilerTaskOptions: nil)
}

/// A shape for kernels that do not pin their size.
func widestGroup(for pipeline: any MTLComputePipelineState) -> MTLSize {
    let w = pipeline.threadExecutionWidth
    return MTLSize(width: w, height: pipeline.maxTotalThreadsPerThreadgroup / w, depth: 1)
}
```

## Kernel rules that bite on Apple GPUs

- **Threadgroup barriers are mandatory even when the group is one SIMD-group wide.** Apple GPUs
  reorder memory operations, so a missing barrier corrupts data. Apple's porting page writes
  `simd_barrier(mem_threadgroup)` and cites MSL §6.8.1. In MSL 4.1 the function is
  `simdgroup_barrier`, the flag is `mem_flags::mem_threadgroup`, and synchronization is §6.10.1.
- **Divergence inside a SIMD group costs both paths.** Branch on values that are uniform per
  SIMD group where you can.
- **Device memory is only threadgroup-coherent by default.** Work queues or single-pass
  reductions that hand data across threadgroups within one dispatch need `coherent(device)`
  buffers and real synchronization (MSL 3.2, Apple silicon). `shading-language.md` has the
  memory-order rules.
- **Atomic gates come from the tables, not the language version.** Floating-point atomics are
  Apple7. 64-bit atomics are Apple9; Apple8 has `ulong` min and max only, and only on macOS.
  On `device atomic_ulong` the language offers only `atomic_min_explicit` and
  `atomic_max_explicit`, which is enough for a packed depth-and-ID visibility buffer. MSL 4.1
  adds threadgroup `atomic_float` add and subtract, and acquire and release ordering (Apple7).
- **Threadgroup memory is 32 KB on Apple4 and later**, shared with imageblock memory when a
  compute pass reserves tile memory.
- **A plain `device int` that many threads increment loses updates.** The book's vertex counter
  read 2 instead of 15,949, and a different wrong number each run. Use `atomic_int` with
  `atomic_fetch_add_explicit`.
- **Small jobs may not pay for the dispatch.** The book's 15,949-vertex z-flip took 0.00215 s on
  the CPU against 0.00145 s on the GPU of an M1 MacBook Pro. Time both before moving tiny loops.

## Indirect arguments: let the GPU size the next command

When a GPU pass computes how much work the next pass does, keep the number on the GPU. Reading it
back stalls the frame; Apple's guidance is to have the GPU build the work instead.

- **Dispatch:** `dispatchThreadgroups(indirectBuffer:threadsPerThreadgroup:)` reads an
  `MTLDispatchThreadgroupsIndirectArguments` (three `UInt32` group counts), and
  `dispatchThreads(indirectBuffer:)` reads `MTLDispatchThreadsIndirectArguments`.
- **Draw:** `drawPrimitives(primitiveType:indirectBuffer:)` and
  `drawIndexedPrimitives(primitiveType:indexType:indexBuffer:indexBufferLength:indirectBuffer:)`
  on `MTL4RenderCommandEncoder`, with the `MTLDrawPrimitivesIndirectArguments` and
  `MTLDrawIndexedPrimitivesIndirectArguments` layouts.
- **Mesh:** `drawMeshThreadgroups(indirectBuffer:threadsPerObjectThreadgroup:threadsPerMeshThreadgroup:)`
  needs Apple9.

Every Metal 4 indirect argument is an `MTLGPUAddress`, not a buffer and offset, and it must be
4-byte aligned. The buffer must be in a residency set. The arguments need not exist when you
encode; they must be written before the consuming command executes. Metal 4 does not track
that dependency, so a barrier must order the producing `.dispatch` before the consuming command's
first stage.

## Indirect command buffers

An ICB is a resource (`MTLIndirectCommandBuffer`) that holds encoded commands you replay any
number of times. You can fill it from several CPU threads, or from a kernel on the GPU. It holds
render commands or compute commands, never both, and executing one kind from the other encoder
is illegal.

**Creating one.** Build an `MTLIndirectCommandBufferDescriptor`, then call
`makeIndirectCommandBuffer(descriptor:maxCommandCount:options:)`.

- Declare only the `commandTypes` you will encode. Metal sizes every slot for the largest type
  you allow.
- Set `inheritBuffers` explicitly. With `inheritPipelineState = true` the commands take the
  pipeline set on the parent encoder.
- Size `maxCommandCount` by draws (submeshes), not by models.
- The book calls 25 bind slots per stage far too many for shipping. Tighten the
  `max*BufferBindCount` values once your indices settle.

**Pipelines must opt in.** `supportIndirectCommandBuffers` on `MTL4RenderPipelineDescriptor`,
`MTL4ComputePipelineDescriptor`, and `MTL4MeshRenderPipelineDescriptor` is an
`MTL4IndirectCommandBufferSupportState` (`.enabled`, `.disabled`), not the `Bool` the Metal 3
descriptors and the book use. A pipeline that runs inside an ICB without it fails validation.

**Maintenance runs in the `.blit` stage of a compute pass.** `resetCommands(buffer:range:)`,
`optimizeCommands(buffer:range:)` (strips empty commands and redundant state), and
`copyCommands(sourceBuffer:sourceRange:destinationBuffer:destinationIndex:)`. After optimizing a
range, start any execute range at the beginning of the optimized region, not inside it.

**Executing.** `executeCommands(buffer:range:)` on `MTL4RenderCommandEncoder` or
`MTL4ComputeCommandEncoder`, or `executeCommands(buffer:indirectBuffer:)` when the GPU writes
the range as an `MTLIndirectCommandBufferExecutionRange`. Apple's GPU-encoding article names an
`executeIndirectCommandBuffer` method. It does not exist; the Metal 3 spelling is
`executeCommandsInBuffer(_:range:)`.

**The execute command belongs to no stage.** You cannot place a barrier that waits for an
entire ICB to finish. Each command inside it keeps the stages it would have if you had encoded
it directly, so order around the *contents*. Within a compute ICB, dispatches are always
concurrent. Place barriers yourself with `setBarrier()` on the CPU or `set_barrier()` in MSL;
they do not leak into the parent encoder.

**Gates that move by family.** ICBs need Apple3, with no length limit. Memory barriers inside
compute ICBs are Apple3, and inside render ICBs Apple9. ICBs containing mesh draws need Apple9.
Encoding cull mode, winding, fill mode, depth bias, depth clip, or depth-stencil state per
command inside an ICB (the MSL `set_cull_mode` family) needs **Apple10**. The MSL spec labels
that state plain "Metal 4"; the tables win. Apple's *Modern rendering with Metal* sample cannot
run in Simulator because it uses ICBs, so test ICB paths on devices.

**Shader Validation instruments ICBs only when pipeline and buffer inheritance are both on.**
Keep an inheriting debug configuration if you rely on it.

### GPU encoding: the per-frame shape

The pattern that pays: a kernel culls objects and writes one draw per survivor, and the render
pass replays the result. In one compute pass, reset the range (`.blit`), barrier, dispatch the
culling kernel (`.dispatch`), barrier, and optionally optimize (`.blit`). Then the render pass
places a consumer barrier on `.dispatch` and `.blit` before `.vertex` and `.fragment`, and
executes. Metal 4 tracks none of these dependencies, so each barrier is required. This
end-to-end Metal 4 shape compiles but is not runtime-checked here.

```swift
func makeDrawICB(device: any MTLDevice, maxDraws: Int) -> (any MTLIndirectCommandBuffer)? {
    let descriptor = MTLIndirectCommandBufferDescriptor()
    descriptor.commandTypes = [.drawIndexed]
    descriptor.inheritPipelineState = true
    descriptor.inheritBuffers = false   // the culling kernel sets each draw's buffers
    descriptor.maxVertexBufferBindCount = 1
    descriptor.maxFragmentBufferBindCount = 0
    return device.makeIndirectCommandBuffer(descriptor: descriptor,
                                            maxCommandCount: maxDraws,
                                            options: .storageModePrivate)
}

func encodeCulledScene(commandBuffer: any MTL4CommandBuffer,
                       renderPass: MTL4RenderPassDescriptor,
                       icb: any MTLIndirectCommandBuffer,
                       cull: any MTLComputePipelineState, cullTable: any MTL4ArgumentTable,
                       draw: any MTLRenderPipelineState, drawTable: any MTL4ArgumentTable,
                       drawCount: Int, residency: any MTLResidencySet) {
    residency.addAllocation(icb)
    residency.addAllocation(draw)          // pipelines an ICB uses must be resident too
    residency.commit()
    commandBuffer.useResidencySet(residency)

    guard let compute = commandBuffer.makeComputeCommandEncoder() else { return }
    compute.resetCommands(buffer: icb, range: 0..<drawCount)
    compute.barrier(afterEncoderStages: .blit, beforeEncoderStages: .dispatch,
                    visibilityOptions: .device)
    compute.setComputePipelineState(cull)
    compute.setArgumentTable(cullTable)
    compute.dispatchThreads(threadsPerGrid: MTLSize(width: drawCount, height: 1, depth: 1),
                            threadsPerThreadgroup: MTLSize(width: cull.threadExecutionWidth,
                                                           height: 1, depth: 1))
    compute.barrier(afterEncoderStages: .dispatch, beforeEncoderStages: .blit,
                    visibilityOptions: .device)
    compute.optimizeCommands(buffer: icb, range: 0..<drawCount)
    compute.endEncoding()

    guard let render = commandBuffer.makeRenderCommandEncoder(descriptor: renderPass,
                                                              options: []) else { return }
    render.barrier(afterQueueStages: [.dispatch, .blit], beforeStages: [.vertex, .fragment],
                   visibilityOptions: .device)
    render.setRenderPipelineState(draw)
    render.setArgumentTable(drawTable, stages: [.vertex, .fragment])
    render.executeCommands(buffer: icb, range: 0..<drawCount)
    render.endEncoding()
}
```

The kernel side. The ICB reaches MSL only as a `command_buffer` member of an argument-buffer
struct. The documented host route fills that member with
`MTLArgumentEncoder.setIndirectCommandBuffer(_:index:)`. Writing `icb.gpuResourceID` into a
Tier 2 struct is the Metal 4-style alternative, and it is not runtime-checked here.

```metal
struct CullArgs {
    command_buffer icb;
};

struct DrawRecord {
    float4 sphere;        // world-space center (xyz) and radius (w)
    uint   indexCount;
    uint   firstIndex;
    uint   baseVertex;
};

kernel void cullAndEncode(device const CullArgs   &args      [[buffer(0)]],
                          device const DrawRecord *records   [[buffer(1)]],
                          device const uint       *indices   [[buffer(2)]],
                          device const float4     *positions [[buffer(3)]],
                          constant float4         *planes    [[buffer(4)]],
                          constant uint           &count     [[buffer(5)]],
                          uint i [[thread_position_in_grid]])
{
    if (i >= count) return;                 // no bounds check on command_buffer indices
    DrawRecord r = records[i];
    bool visible = true;
    for (int p = 0; visible && p < 6; ++p) {
        visible = dot(planes[p].xyz, r.sphere.xyz) + planes[p].w > -r.sphere.w;
    }
    render_command cmd(args.icb, i);
    if (!visible) { cmd.reset(); return; }  // a reset command draws nothing
    cmd.set_vertex_buffer(positions, 0);
    cmd.draw_indexed_primitives(primitive_type::triangle, r.indexCount,
                                indices + r.firstIndex, 1, r.baseVertex, i);
}
```

MSL rules for that kernel (spec §6.17):

- Only the last `draw_*` call on a command takes effect.
- A slot the CPU never initialized must be `reset()` before use.
- `cmdB = cmdA` makes both names point at one slot. Use `copy_command`, which works only between
  ICBs built from matching descriptors.
- Pipeline states reach a shader only through argument buffers.
- Cast indices to the submesh's real index type. The book traced a garbage-geometry bug to a
  16-bit buffer read as 32-bit.

The book also advises developing GPU encoding against an iPhone or iPad, because a mismatch can
lock up the Mac you develop on.

## Object and mesh shaders

Mesh shading replaces both tessellation and most compute-then-draw geometry pipelines. Metal 4
removes tessellation from the render encoder and names mesh shaders as its replacement. The book
names the case for them: generation, culling, and drawing stay in one render encoder, with no
compute-to-render switch and no intermediate vertex buffers in memory.

**Gates.** Mesh shading is Apple7 in the tables. Apple's LOD sample pairs `.apple7` with "A15 or
later"; the tables put Apple7 at A14, and the tables win. Hardware-accelerated mesh shading is
Apple9. Indirect mesh draws and ICBs containing mesh draws need Apple9. Simulator has no mesh
shaders. In a render pipeline, mesh shading cannot be combined with function pointers or ray
tracing, and Metal IR linking there works only through `MTLLinkedFunctions.privateFunctions`.

**Limits (tables).**

- Mesh threadgroups per mesh grid: 1,024 on Apple7–8, 1,048,575 on Apple9, and 4,194,303 on
  Apple10. The book's "1,024" is the Apple7–8 figure only.
- Object grid size: unlimited.
- Payload: 16,384 B. It drops by 16 B when the mesh function takes `[[threadgroups_per_grid]]`
  or `[[threads_per_grid]]`, and by another 16 B while the Metal debugger shows that mesh's
  geometry.

Mesh indices are `uchar`, so one meshlet addresses at most 256 vertices. Budget threads early:
the book's grass, at 15 × 15 tiles × 100 blades, already launches over 720,000 threads.

**Culling lives in the object stage.** An object threadgroup that never calls
`mesh_grid_properties::set_threadgroups_per_grid` launches no mesh grid at all. That is the
per-meshlet cull a vertex shader cannot do. Per-primitive culling uses a `[[primitive_culled]]`
field in the primitive struct.

**Host side.** Use `MTL4MeshRenderPipelineDescriptor`, with `objectFunctionDescriptor`,
`meshFunctionDescriptor`, and `fragmentFunctionDescriptor`. Compile it with
`MTL4Compiler.makeRenderPipelineState(descriptor:dynamicLinkingDescriptor:compilerTaskOptions:)`.
Compared with the Metal 3 descriptor, it has no buffer-mutability hints and no binary-archive
field.

- `payloadMemoryLength` at 0 (the default) sizes the payload from the object function's declared
  `[[payload]]` type. If that type is a pointer, Metal reserves one element, so set the length
  when the payload is an array behind a pointer. The book says to set it whenever an object
  function writes a payload; the symbol page's default covers the by-reference case.
- `requiredThreadsPerObjectThreadgroup` and `requiredThreadsPerMeshThreadgroup` pin the group
  sizes, like the compute case above.
- Draw with `drawMeshThreadgroups(threadgroupsPerGrid:threadsPerObjectThreadgroup:threadsPerMeshThreadgroup:)`,
  and bind the argument table to `[.object, .mesh, .fragment]`. If the pipeline has no object
  function, the draw does not touch the `.object` stage.

```swift
func makeMeshletPipeline(compiler: any MTL4Compiler, library: any MTLLibrary,
                         colorFormat: MTLPixelFormat) throws -> any MTLRenderPipelineState {
    func function(_ name: String) -> MTL4LibraryFunctionDescriptor {
        let f = MTL4LibraryFunctionDescriptor()
        f.library = library
        f.name = name
        return f
    }
    let descriptor = MTL4MeshRenderPipelineDescriptor()
    descriptor.objectFunctionDescriptor = function("meshletCull")
    descriptor.meshFunctionDescriptor = function("meshletEmit")
    descriptor.fragmentFunctionDescriptor = function("meshletShade")
    descriptor.colorAttachments[0].pixelFormat = colorFormat
    descriptor.requiredThreadsPerObjectThreadgroup = MTLSize(width: 32, height: 1, depth: 1)
    descriptor.requiredThreadsPerMeshThreadgroup = MTLSize(width: 128, height: 1, depth: 1)
    return try compiler.makeRenderPipelineState(descriptor: descriptor,
                                                dynamicLinkingDescriptor: nil,
                                                compilerTaskOptions: nil)
}

func drawMeshlets(render: any MTL4RenderCommandEncoder, pipeline: any MTLRenderPipelineState,
                  table: any MTL4ArgumentTable, meshletCount: Int) {
    render.setRenderPipelineState(pipeline)
    render.setArgumentTable(table, stages: [.object, .mesh, .fragment])
    render.drawMeshThreadgroups(
        threadgroupsPerGrid: MTLSize(width: (meshletCount + 31) / 32, height: 1, depth: 1),
        threadsPerObjectThreadgroup: MTLSize(width: 32, height: 1, depth: 1),
        threadsPerMeshThreadgroup: MTLSize(width: 128, height: 1, depth: 1))
}
```

The object stage below compacts survivors with a threadgroup atomic rather than a SIMD prefix
sum, so it does not assume the SIMD width equals the object group size.

```metal
struct Meshlet {
    float4 sphere;
    uint   vertexOffset;
    uint   vertexCount;     // <= 64
    uint   triangleOffset;
    uint   triangleCount;   // <= 124
};

struct MeshletPayload { uint meshlet[32]; };

struct MeshVertex    { float4 position [[position]]; };
struct MeshPrimitive { bool culled [[primitive_culled]]; };

using MeshletMesh = metal::mesh<MeshVertex, MeshPrimitive, 64, 124, topology::triangle>;

[[object, max_total_threadgroups_per_mesh_grid(32)]]
void meshletCull(object_data MeshletPayload &payload [[payload]],
                 mesh_grid_properties grid,
                 device const Meshlet *meshlets  [[buffer(0)]],
                 constant float4 *planes         [[buffer(1)]],
                 constant uint &meshletCount     [[buffer(2)]],
                 uint gid  [[thread_position_in_grid]],
                 uint lane [[thread_index_in_threadgroup]])
{
    threadgroup atomic_uint survivors;
    if (lane == 0) atomic_store_explicit(&survivors, 0u, memory_order_relaxed);
    threadgroup_barrier(mem_flags::mem_threadgroup);

    bool visible = gid < meshletCount;
    for (int p = 0; visible && p < 6; ++p) {
        float4 s = meshlets[gid].sphere;
        visible = dot(planes[p].xyz, s.xyz) + planes[p].w > -s.w;
    }
    if (visible) {
        payload.meshlet[atomic_fetch_add_explicit(&survivors, 1u, memory_order_relaxed)] = gid;
    }
    threadgroup_barrier(mem_flags::mem_threadgroup);
    if (lane == 0) {   // zero survivors launches no mesh threadgroups at all
        uint n = atomic_load_explicit(&survivors, memory_order_relaxed);
        grid.set_threadgroups_per_grid(uint3(n, 1, 1));
    }
}

[[mesh]]
void meshletEmit(MeshletMesh out,
                 const object_data MeshletPayload &payload [[payload]],
                 device const Meshlet *meshlets         [[buffer(0)]],
                 device const packed_float3 *positions  [[buffer(3)]],
                 device const uchar *triangles          [[buffer(4)]],
                 constant float4x4 &viewProjection      [[buffer(5)]],
                 uint tg   [[threadgroup_position_in_grid]],
                 uint lane [[thread_index_in_threadgroup]])
{
    Meshlet m = meshlets[payload.meshlet[tg]];
    if (lane < m.vertexCount) {
        MeshVertex v;
        v.position = viewProjection * float4(float3(positions[m.vertexOffset + lane]), 1.0);
        out.set_vertex(lane, v);
    }
    if (lane < m.triangleCount) {
        uint t = (m.triangleOffset + lane) * 3;
        out.set_index(lane * 3 + 0, triangles[t + 0]);
        out.set_index(lane * 3 + 1, triangles[t + 1]);
        out.set_index(lane * 3 + 2, triangles[t + 2]);
        out.set_primitive(lane, MeshPrimitive{ false });
    }
    if (lane == 0) out.set_primitive_count(m.triangleCount);
}
```

Meshlets of roughly 64 to 256 vertices, with precomputed bounds, let the object stage cull or
pick LOD for parts of a dense model. Hash a deterministic seed from the coordinates for
procedural placement such as grass. MSL has no random function, and a stable hash keeps blades
in place between frames. Porting the book's tessellated terrain means regenerating its LOD grid
in an object and mesh pipeline. Its edge-factor technique (factor from camera distance to each
edge's midpoint, so neighbours agree and no cracks open) carries over.

## Ray tracing

**Gates (tables).**

- Ray tracing in compute and render pipelines: Apple6.
- Hardware ray tracing: Apple9 (*Improving your game's graphics performance and settings*).
  Prefer it when present.
- Apple9 also brings intersection function buffers, acceleration-structure build options,
  row-major-matrix acceleration structures, per-component motion interpolation, and direct
  access to on-chip intersection results.
- "Address-driven acceleration structure builds" are a Metal 4 row at Apple9. Every `MTL4…`
  acceleration-structure descriptor takes its inputs as `MTL4BufferRange` GPU addresses. Read
  that row as gating the Metal 4 build path, and on Apple7–8 build through
  `MTLAccelerationStructureCommandEncoder` (see the Metal 3 section). That reading is an
  inference: this Mac is Apple9, and the Apple7–8 path is not runtime-checked here.
- Traversal depth: an intersector can traverse 32 acceleration-structure levels and an
  intersection query 16, both counting the primitive level.

**Building on the Metal 4 path.**

- Describe the geometry with `MTL4PrimitiveAccelerationStructureDescriptor` and its `MTL4…`
  geometry descriptors. Describe instances with `MTL4InstanceAccelerationStructureDescriptor`.
  Use `MTL4IndirectInstanceAccelerationStructureDescriptor` when a kernel writes the instance
  and motion-transform counts; give it the maximum counts up front.
- Size the build with `device.accelerationStructureSizes(descriptor:)`, allocate with
  `makeAccelerationStructure(size:)`, and encode
  `build(destinationAccelerationStructure:descriptor:scratchBuffer:)` on the compute encoder.
- The scratch buffer, every input buffer, and every primitive acceleration structure an instance
  structure references must be resident.
- Finish all primitive builds before building an instance structure over them. That means a
  `.accelerationStructure` → `.accelerationStructure` barrier in the same pass.
- A built structure keeps no reference to its input buffers.
- Do not start tracing until the build has finished. Apple's page says to schedule the command
  buffer that traces after the build's command buffer completes. Within one queue, a barrier on
  `.accelerationStructure` is the Metal 4 way to express that.
- Refit when vertices move and topology does not. It is much cheaper than a rebuild, but
  traversal quality degrades with how far the geometry moved, and adding or removing geometry
  rules it out.
- Bind the structure with `setResource(_:bufferIndex:)` and its `gpuResourceID`.

```swift
func buildTriangleBLAS(device: any MTLDevice, commandBuffer: any MTL4CommandBuffer,
                       residency: any MTLResidencySet,
                       vertices: any MTLBuffer, indices: any MTLBuffer,
                       triangleCount: Int) -> (any MTLAccelerationStructure)? {
    let geometry = MTL4AccelerationStructureTriangleGeometryDescriptor()
    geometry.vertexBuffer = MTL4BufferRange(bufferAddress: vertices.gpuAddress,
                                            length: UInt64(vertices.length))
    geometry.vertexFormat = .float3
    geometry.vertexStride = MemoryLayout<SIMD3<Float>>.stride
    geometry.indexBuffer = MTL4BufferRange(bufferAddress: indices.gpuAddress,
                                           length: UInt64(indices.length))
    geometry.indexType = .uint32
    geometry.triangleCount = triangleCount

    let descriptor = MTL4PrimitiveAccelerationStructureDescriptor()
    descriptor.geometryDescriptors = [geometry]

    let sizes = device.accelerationStructureSizes(descriptor: descriptor)
    guard let blas = device.makeAccelerationStructure(size: sizes.accelerationStructureSize),
          let scratch = device.makeBuffer(length: sizes.buildScratchBufferSize,
                                          options: .storageModePrivate) else { return nil }
    residency.addAllocations([blas, scratch, vertices, indices])
    residency.commit()

    guard let pass = commandBuffer.makeComputeCommandEncoder() else { return nil }
    pass.build(destinationAccelerationStructure: blas, descriptor: descriptor,
               scratchBuffer: MTL4BufferRange(bufferAddress: scratch.gpuAddress,
                                              length: UInt64(scratch.length)))
    pass.endEncoding()
    return blas   // keep `scratch` alive until the GPU finishes this command buffer
}
```

**Per-primitive data** (`primitiveDataBuffer`, `primitiveDataElementSize`, `primitiveDataStride`
on the geometry descriptor; the `MTL4` descriptor takes an `MTL4BufferRange`) copies a small
payload per triangle into the structure at build time. It replaces the primitive-ID indirection
that dominates small intersection functions. Keep it to hot, instance-invariant fields, because
it grows structure memory and build, copy, and refit time.

**Shader side** (MSL §2.17 and §6.19, `<metal_raytracing>`; `shading-language.md` has the
types).

- An *intersector* calls intersection functions from a function table per hit type. An
  *intersection query* hands every candidate back to your code. Apple advises intersectors for
  speed. Intersectors work in vertex and fragment shaders only on Apple-silicon GPUs; queries
  suit code ported from other APIs.
- Intersection tags must match in set and order across the table, result, intersector or
  query, and intersection functions. A mismatch is a compile error or undefined behaviour.
- For shadow and AO rays, `accept_any_intersection(true)` stops at the first hit.
- `assume_geometry_type` defaults to triangles and bounding boxes, so curves are skipped until
  you add `geometry_type::curve`.
- `triangle_barycentric_coord.x` weights vertex 1, `.y` weights vertex 2, and vertex 0 gets
  `1 - x - y`.
- The payload is copied into each intersection function and back out after it, so keep it
  small. Writes an intersection function makes persist even for rejected hits, so keep those
  functions free of side effects.

```metal
kernel void shadowRays(raytracing::primitive_acceleration_structure scene [[buffer(0)]],
                       device const float3 *origins          [[buffer(1)]],
                       constant float3 &toLight              [[buffer(2)]],
                       device float *visibility              [[buffer(3)]],
                       constant uint &rayCount               [[buffer(4)]],
                       uint i [[thread_position_in_grid]])
{
    if (i >= rayCount) return;
    raytracing::ray r(origins[i], toLight, 1e-3f, INFINITY);
    raytracing::intersector<raytracing::triangle_data> shadow;
    shadow.accept_any_intersection(true);
    auto hit = shadow.intersect(r, scene);
    visibility[i] = hit.type == raytracing::intersection_type::none ? 1.0f : 0.0f;
}
```

Do not route new code to MPS's ray intersector. `MPSRayIntersector` is deprecated (iOS 12–17,
macOS 10.14–14), and current ray tracing is Metal's own acceleration structures. Ray tracing is
also cheap line-of-sight for gameplay: AI visibility and sound occlusion.

## MPS and MPSGraph: when not to write the kernel

**MPS image kernels encode only onto a Metal 3 `MTLCommandBuffer`.** Every
`MPSUnaryImageKernel` and `MPSBinaryImageKernel` subclass works that way: blur, Sobel,
histogram, statistics, Lanczos scale, distance transform, and the rest. `MPSMatrixMultiplication`
does too. Only the `MPSNDArray` kernels take an `MTL4ComputeCommandEncoder`
(`encode(withMTL4CommandEncoder:sourceArray:destinationArray:)`), and MPSGraph runs on an
`MTL4CommandQueue` through `runAsync(on:feeds:targetTensors:targetOperations:executionDescriptor:)`.
A Metal 4 renderer that wants MPS bloom has two choices:

- keep an `MTLCommandQueue` beside the `MTL4CommandQueue`, and order the two with an `MTLEvent`,
  which works across both queue kinds; or
- write the filter as your own kernel. The book's profile found its MPS bloom encoders among the
  longest items on the frame timeline, so measure either way.

```swift
/// MPS on a Metal 3 side queue, fenced against the Metal 4 queue with one event.
func gaussianBlurOnSideQueue(device: any MTLDevice, sideQueue: any MTLCommandQueue,
                             mainQueue: any MTL4CommandQueue, event: any MTLEvent,
                             frame: UInt64, source: any MTLTexture,
                             destination: any MTLTexture) {
    mainQueue.signalEvent(event, value: frame * 2)            // after the producing commit
    guard let commandBuffer = sideQueue.makeCommandBuffer() else { return }
    commandBuffer.encodeWaitForEvent(event, value: frame * 2)
    MPSImageGaussianBlur(device: device, sigma: 4)
        .encode(commandBuffer: commandBuffer, sourceTexture: source, destinationTexture: destination)
    commandBuffer.encodeSignalEvent(event, value: frame * 2 + 1)
    commandBuffer.commit()
    mainQueue.waitForEvent(event, value: frame * 2 + 1)        // before the consuming commit
}
```

MPS rules that cost people time:

- Check `MPSSupportsMTLDevice(_:)` first.
- A kernel is bound to one device; `copy(with:device:)` moves it to another.
- A kernel opens and ends its own encoder, so end yours before calling it.
- Kernels are not thread-safe. Never let two kernels encode into one command buffer at once,
  and give each thread its own copy.
- In-place filtering is never guaranteed. Use
  `encode(commandBuffer:inPlaceTexture:fallbackCopyAllocator:)` with an allocator.
- Compressed formats work as sources only.
- Destinations need `.shaderRead` and `.shaderWrite` usage.
- A kernel that touches the drawable needs `MTKView.framebufferOnly = false`.
- Apple's Objective-C image-filter sample does not compile as written. Do not copy it.

Apple's MPS tuning numbers apply to any Metal frame loop:

- an empty command buffer can take up to 2.5 ms to round-trip through `waitUntilCompleted()`;
- overlapping CPU encoding with GPU execution can raise throughput up to 10×;
- chained multipass filters can run up to 2× faster in tiles of about 512 KB.

What else exists: `MPSSVGFDenoiser` (a ray-tracing denoiser), `MPSTemporalAA`, matrix kernels
including quantized matmul, and MPSGraph. MPSGraph compiles a tensor graph to an
`MPSGraphExecutable` that can target the GPU, the CPU, or the Neural Engine, and that you can
serialize to a `.mpsgraphpackage` so launch skips graph compilation. Use MPSGraph for inference
that is not per-frame shading. The older `MPSNNGraph` and MPS CNN layers still ship; prefer
MPSGraph, Core ML, or the Metal 4 routes below for new work.

## Machine-learning passes: what exists and when

The first two routes are Metal 4 model, Apple7. The ML encoder route also needs Xcode 26 or
later, which ships `metal-package-builder`.

1. **`MTL4MachineLearningCommandEncoder` runs a whole Core ML model on the GPU timeline**, in the
   same command buffer as render and compute work, with no CPU round trip.
   - Convert the model at development time with `xcrun metal-package-builder` into an
     `.mtlpackage`, whose entry function is `main`.
   - Compile it with `MTL4Compiler.makeMachineLearningPipelineState(descriptor:)`.
   - Bind `MTLTensor` inputs and outputs through an argument table. Match tensor bindings by
     name, because their order is not fixed.
   - Call `dispatchNetwork(intermediatesHeap:)` with a placement heap of at least
     `intermediatesHeapSize`.
   - Each distinct set of dynamic input dimensions needs its own pipeline state.
   - Order the pass with barriers on `.machineLearning`.
   - The encoder runs existing models only; build or edit networks in Core ML or MPSGraph.
2. **Metal Performance Primitives tensor ops run inside your own kernel or shader** (MSL §2.22
   and chapter 7). Use `tensor_ops::matmul2d`, `convolution2d`, and cooperative tensors, with
   activations fused into the same dispatch.
   - The pipeline must set `requiredThreadsPerThreadgroup`.
   - Pass static extents to `slice()` when you know the tile size.
   - Apple GPUs need no hand-written staging through threadgroup memory for these ops.
   - Apple10 GPUs have a per-core neural accelerator that runs them in hardware.
   - The spec misspells `matmul2d` as `matmuld2d`; the header spells it correctly.
3. **MPSGraph** for inference off the frame's critical path (above).

**Choosing.** Apple's neural-irradiance sample states the trade. In-shader tensor ops win when
you need per-pixel control, such as skipping empty pixels, or fusion. The ML encoder wins when
running a packaged model simply matters more; in that sample it was the slower path, because it
could not skip empty pixels. For one small op such as a single matmul, use a shader.

Tensors created with `MTLTensorUsage.machineLearning` need row strides and buffer offsets in
64-byte multiples (tables). Extents list the innermost dimension first, and −1 marks a dynamic
dimension.

```swift
/// An ML pass whose output a later render pass samples in its fragment stage.
func encodeNetwork(commandBuffer: any MTL4CommandBuffer,
                   network: any MTL4MachineLearningPipelineState,
                   table: any MTL4ArgumentTable, intermediates: any MTLHeap,
                   consumer: MTL4RenderPassDescriptor) {
    guard let ml = commandBuffer.makeMachineLearningCommandEncoder() else { return }
    ml.setPipelineState(network)
    ml.setArgumentTable(table)
    ml.dispatchNetwork(intermediatesHeap: intermediates)
    ml.endEncoding()

    guard let render = commandBuffer.makeRenderCommandEncoder(descriptor: consumer,
                                                              options: []) else { return }
    render.barrier(afterQueueStages: .machineLearning, beforeStages: .fragment,
                   visibilityOptions: .device)
    // ... draws that read the network's output tensor ...
    render.endEncoding()
}
```

| Metal 4 | Metal 3 equivalent | What changes when you port down |
|---|---|---|
| `MTL4ComputeCommandEncoder` (dispatch, blit, AS stages) | `MTLComputeCommandEncoder` + `MTLBlitCommandEncoder` + `MTLAccelerationStructureCommandEncoder` | Three passes instead of one |
| Concurrent dispatches, intrapass barriers | Serial by default; `makeComputeCommandEncoder(dispatchType: .concurrent)` plus `memoryBarrier(scope:)` | Serial mode orders dispatches for you |
| Untracked resources | Device resources bound directly are tracked by default; heap resources and argument-buffer contents are not | Fewer barriers; tracking costs CPU time |
| `setArgumentTable` + `gpuAddress` | `setBuffer(_:offset:index:)`, `setBytes(_:length:index:)` | Inline bytes exist again (≤ 4 KB) |
| Residency sets | `useResource(_:usage:)`, `useHeap(_:)` per encoder; a GPU-encoded ICB needs `useResource(icb, usage: .write)` | A non-resident resource fails the command buffer |
| `dispatchThreads(threadsPerGrid:threadsPerThreadgroup:)` | `dispatchThreads(_:threadsPerThreadgroup:)` | Label change |
| `resetCommands(buffer:range:)`, `optimizeCommands(buffer:range:)` on compute | `resetCommandsInBuffer(_:range:)`, `optimizeIndirectCommandBuffer(_:range:)` on blit | Separate blit pass |
| `executeCommands(buffer:range:)` | `executeCommandsInBuffer(_:range:)` | Same semantics |
| `supportIndirectCommandBuffers = .enabled` | `supportIndirectCommandBuffers = true` | Enum versus `Bool` |
| `MTL4…AccelerationStructure…Descriptor` with `MTL4BufferRange` | `MTL…AccelerationStructure…Descriptor` with `MTLBuffer` and offsets | Buffers, not addresses |
| `build(destinationAccelerationStructure:descriptor:scratchBuffer:)` | `build(accelerationStructure:descriptor:scratchBuffer:scratchBufferOffset:)` | Separate AS encoder |
| `MTL4MeshRenderPipelineDescriptor` | `MTLMeshRenderPipelineDescriptor` via `makeRenderPipelineState(descriptor:options:)` | Mesh shading still needs Apple7 |
| Mesh shaders | Tessellation (`drawPatches`, factor buffers; Apple3, factor 64 from Apple4) | Tessellation exists only here |
| `MTL4MachineLearningCommandEncoder`, tensors | None; use MPSGraph or Core ML | — |
| MPS image kernels on a side `MTLCommandQueue` | MPS encodes straight into your command buffer | No event bridge |

The book's tessellation chapter gates factor 64 at Apple5. The tables say Apple4.

```swift
/// Metal 3: two dependent dispatches in one concurrent pass.
func encodeTwoStepsMetal3(queue: any MTLCommandQueue, pipeline: any MTLComputePipelineState,
                          data: any MTLBuffer, count: Int) {
    guard let commandBuffer = queue.makeCommandBuffer(),
          let pass = commandBuffer.makeComputeCommandEncoder(dispatchType: .concurrent)
    else { return }
    let group = MTLSize(width: pipeline.threadExecutionWidth, height: 1, depth: 1)
    pass.setComputePipelineState(pipeline)
    pass.setBuffer(data, offset: 0, index: 0)
    pass.dispatchThreads(MTLSize(width: count, height: 1, depth: 1), threadsPerThreadgroup: group)
    pass.memoryBarrier(scope: .buffers)   // concurrent mode needs it, as Metal 4 always does
    pass.dispatchThreads(MTLSize(width: count, height: 1, depth: 1), threadsPerThreadgroup: group)
    pass.endEncoding()
    commandBuffer.commit()
}
```

## Classic pitfalls

- **Porting a serial Metal 3 compute pass without adding intrapass barriers.** Metal 4
  dispatches overlap by default.
- **Hardcoding a SIMD width of 32**, or a threadgroup size that a heavier kernel's
  `maxTotalThreadsPerThreadgroup` no longer allows.
- **Setting `requiredThreadsPerThreadgroup` in one place and dispatching another size**, or
  pinning it in MSL and on the descriptor with different values.
- **Forgetting that an ICB execute belongs to no stage.** Barrier on the stages its commands
  use, not on the execute.
- **Leaving the ICB, its referenced buffers, or its pipelines out of the residency set.** The
  failures are missing geometry, pink textures, or a GPU fault, not a validation message.
- **Moving cull mode or depth state into an ICB on pre-Apple10 hardware**, trusting the MSL
  spec's plain "Metal 4" label.
- **Assuming mesh shaders need A15 because a sample says so.** The tables put mesh shading at
  Apple7 (A14). The Simulator has none.
- **Building an instance acceleration structure before its primitive builds finish**, or
  tracing before the build has completed.
- **Calling an MPS image filter on an `MTL4CommandBuffer`.** It does not take one. Bridge with
  an event, or write the kernel.
- **Trusting a doc spelling**: `executeIndirectCommandBuffer`, `simd_barrier`,
  `MTLDevice.requiredThreadsPerThreadgroup`, and `matmuld2d` do not exist.
