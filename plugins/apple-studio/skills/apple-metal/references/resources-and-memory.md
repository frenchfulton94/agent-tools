## Three Metal 4 rules that break Metal 3 habits

1. **Nothing is hazard-tracked.** Metal applies no hazard tracking to work on an
   `MTL4CommandQueue`, even for a resource created `.tracked`. A `hazardTrackingMode`
   setting is dead weight on the Metal 4 path. Every write that a later read depends on
   needs a barrier, fence, or event (`command-model.md`).
2. **Command buffers don't retain.** An `MTL4CommandBuffer` holds no reference to the
   resources it uses. Freeing a staging buffer before the GPU has read it is a
   use-after-free on the GPU timeline, and API Validation does not catch it
   (`command-model.md`). See "Lifetime" below.
3. **Residency is explicit and set-based.** Metal 4 encoders have no `useResource` or
   `useHeap`. A resource the GPU touches must sit in a residency set attached to the
   command buffer or the queue. Shader Validation reports a Metal 4 "resource not
   resident" error when it isn't.

## Choosing a storage mode (Apple silicon)

| Data | Mode | Why |
|---|---|---|
| Written by the CPU every frame (constants, instance data, CPU-skinned or simulated vertices) | `.shared` | One allocation both sides see; the default for buffers and textures on Apple silicon. |
| Loaded once, then only read by the GPU (textures) | `.private` | Leaves Metal free to pick a GPU-friendly layout and apply lossless compression. Fill it by copy or by the IO queue. |
| Produced by the GPU (render targets that later passes sample, compute outputs, streamed textures) | `.private` | No CPU access needed. |
| Produced and consumed inside one render pass (depth, MSAA color, G-buffer) | `.memoryless` | Lives in tile memory only. Textures only; no `.load`/`.store`. Details: `apple-gpu-tbdr.md`. |

- **`.managed` is deprecated** in the macOS 27 SDK ("no effect on Apple Silicon, use
  Shared storage instead") and was never available on iOS. Apple-silicon code never
  calls `didModifyRange` or `synchronize(resource:)`.
- **Don't infer capability from `storageMode`.** The default differs by hardware.
  Apple's guidance is to branch on `supportsFamily(_:)`, not on what mode a resource
  came back with.
- **Shared means shared hazards.** The CPU must not write a shared buffer region the GPU
  may still be reading. Give each frame in flight its own slot (`command-model.md`).
- **There is no CPU pointer into a texture**, shared or not. `replace(region:...)` and
  `getBytes` are the only CPU paths. After a CPU `replace` into a shared texture the GPU
  will read for a while, encode `optimizeContents(forGPUAccess:)` on the compute encoder.
  Metal may ignore that call on some hardware.
- Texture memory is **uninitialized** at creation. A texture's format, size, and layout
  are fixed for its life; only its contents change.

## Usage flags decide whether compression happens

Set `MTLTextureDescriptor.usage` to exactly what the texture does. Narrow usage is a
bandwidth lever, not a formality.

- On Apple-family GPUs from family 5, Metal stops applying **lossless** compression to a
  texture whose usage includes `.unknown`, `.shaderWrite`, or `.pixelFormatView`. A
  buffer-backed texture (`MTLBuffer.makeTexture(descriptor:offset:bytesPerRow:)`) and a
  block-compressed format also skip it.
- `.renderTarget` and `.shaderWrite` are different things: rendering to a texture does
  not need `.shaderWrite`.
- An sRGB/linear view of the same texture needs no `.pixelFormatView`; only a change in
  component count, size, or order does.
- **Lossless compression saves bandwidth, not memory.** The SDK header says so in as
  many words. Only **lossy** compression (`compressionType = .lossy`, Apple8 and later)
  shrinks the allocation. Lossy needs `.private` storage and
  `allowGPUOptimizedContents == true`, and excludes `.pixelFormatView`, `.shaderWrite`,
  `.shaderAtomic`, 1D textures, texture buffers, and (per the Feature Set Tables) packed
  16-bit, compressed, YUV, depth/stencil, `RG11B10Float`, and `RGB9E5Float` formats. It
  suits stored intermediate targets, such as post-process chains, that tolerate small
  error.
- `allowGPUOptimizedContents = false` opts out of both kinds of compression. Use it only
  on a shared texture whose CPU readback speed matters more than GPU speed.

## Uploading in Metal 4: copies live on the compute encoder

Metal 4 has no blit encoder. `MTL4ComputeCommandEncoder` carries buffer-to-texture
copies, mip generation, and content optimization, in its `.blit` stage. Commands in that
encoder can overlap, and the docs promise ordering only between copies to overlapping
regions, so make a command that reads a copy's output wait with an **intrapass
barrier**. A later pass that samples the result needs a **consumer barrier** on `.blit`.

```swift
import Metal

/// A texture that is loaded once and only sampled afterwards.
func makeStaticTexture(device: any MTLDevice, width: Int, height: Int) -> (any MTLTexture)? {
    let d = MTLTextureDescriptor.texture2DDescriptor(
        pixelFormat: .rgba8Unorm_srgb, width: width, height: height, mipmapped: true)
    d.storageMode = .private
    d.usage = [.shaderRead]   // no .shaderWrite or .pixelFormatView: keeps lossless compression
    return device.makeTexture(descriptor: d)
}

/// Copies level 0 from a CPU-filled staging buffer, then builds the mip chain on the GPU.
/// The caller keeps `staging` alive until the GPU has finished (see "Lifetime").
func encodeUpload(staging: any MTLBuffer, bytesPerRow: Int,
                  into texture: any MTLTexture,
                  commandBuffer: any MTL4CommandBuffer) {
    guard let copies = commandBuffer.makeComputeCommandEncoder() else { return }
    copies.copy(sourceBuffer: staging, sourceOffset: 0,
                sourceBytesPerRow: bytesPerRow, sourceBytesPerImage: 0,
                sourceSize: MTLSize(width: texture.width, height: texture.height, depth: 1),
                destinationTexture: texture, destinationSlice: 0, destinationLevel: 0,
                destinationOrigin: MTLOrigin(x: 0, y: 0, z: 0))
    // Mip generation reads level 0, so it must wait for the copy inside this pass.
    copies.barrier(afterEncoderStages: .blit, beforeEncoderStages: .blit,
                   visibilityOptions: .device)
    copies.generateMipmaps(texture: texture)
    copies.endEncoding()
}

/// First thing in the render pass that samples the uploaded texture.
func waitForUploads(_ render: any MTL4RenderCommandEncoder) {
    render.barrier(afterQueueStages: .blit, beforeStages: .fragment,
                   visibilityOptions: .device)
}
```

- `generateMipmaps(texture:)` needs `mipmapLevelCount > 1` and a color-renderable or
  color-filterable format. Its filter is implementation-defined, so results differ
  between GPUs. Bake mips offline when they must match across devices.
- For buffers, the compute encoder's `copy(sourceBuffer:sourceOffset:destinationBuffer:destinationOffset:size:)`
  is the shared-to-private copy. On Apple silicon a buffer the CPU fills once can simply
  stay `.shared`; the private copy pays off for textures, where layout and compression
  change.
- Skip the staging step for disk data: the IO queue loads straight into a private
  texture (see "Streaming from disk").

## CPU and GPU struct layout

The commonest resource bug is a struct the two sides lay out differently. In MSL a
`float3` is 16 bytes with 16-byte alignment, and `float3x3` is 48 bytes. Use
`packed_float3` (12 bytes, 4-byte aligned) in shared structs or pad the CPU side, and
assert the size in the shader so a mismatch fails the build:

```metal
#include <metal_stdlib>
using namespace metal;

struct Particle {
    packed_float3 position;   // 12 bytes, 4-byte aligned
    float         radius;     // completes the first 16 bytes
    float3        velocity;   // 16 bytes, 16-byte aligned
};
static_assert(sizeof(Particle) == 32, "must match the CPU-side struct");
```

Two more contracts from the MSL 4.1 spec: a pointer argument is assumed aligned to its
pointee's natural alignment, so a misaligned bind offset is undefined; and separate
`device` buffer arguments to one function are assumed not to overlap, so binding two
overlapping ranges of one `MTLBuffer` to two arguments breaks the compiler's
assumptions. Constant-buffer bind offsets must also meet the per-family minimum
alignment in the Feature Set Tables (4 B on Apple GPUs; the Simulator needs 256 B).

## Lifetime: release only after the GPU is done

Because an `MTL4CommandBuffer` doesn't retain, the engine owns every resource's
lifetime. Tie each release to the shared-event value of the last frame that used the
resource; the frames-in-flight event in `command-model.md` already provides that value.

```swift
import Metal

/// Keeps objects alive until the GPU passes the frame that last used them.
final class DeferredRelease {
    private var pending: [(frame: UInt64, objects: [AnyObject])] = []

    func hold(_ objects: [AnyObject], untilFrame frame: UInt64) {
        pending.append((frame, objects))
    }

    /// Call once per frame with the value the frame event has reached on the GPU.
    func collect(completedFrame: UInt64) {
        pending.removeAll { $0.frame <= completedFrame }
    }
}
```

Feed `collect` the frame event's `signaledValue` once per frame.

The same rule applies to removing a resource from a residency set, to `endResidency()`,
and to unmapping sparse tiles: do it after the last command buffer that reads the
resource has completed, not when you stop encoding uses of it.

## Heaps

A heap is one allocation you sub-allocate from. Creating the heap is slow; allocating
from it is cheap, even mid-frame. Every resource in a heap shares its storage mode and
CPU cache mode, and purgeability is set on the heap, not its resources.

| Type | Who places resources | Use for | Gotcha |
|---|---|---|---|
| `.automatic` (default) | Metal | Transient resources written often | `makeAliasable()` works only here. |
| `.placement` | You, by byte offset | Long-lived level data; explicit aliasing; placement sparse tiles | Offsets and sizes are yours; overlap aliases silently. |
| `.sparse` | Metal 3 sparse tile pool | Metal 3 sparse textures only | Residency sets reject sparse heaps; not a Metal 4 path. |

```swift
import Metal

/// Sizes one placement heap for a fixed set of textures and places them back to back.
func makeLevelHeap(device: any MTLDevice,
                   descriptors: [MTLTextureDescriptor]) -> (heap: any MTLHeap, textures: [any MTLTexture])? {
    var offsets: [Int] = []
    var size = 0
    for d in descriptors {
        d.storageMode = .private                 // must match the heap's storage mode
        let sa = device.heapTextureSizeAndAlign(descriptor: d)
        size = (size + sa.align - 1) / sa.align * sa.align   // round up to this texture's alignment
        offsets.append(size)
        size += sa.size
    }
    let hd = MTLHeapDescriptor()
    hd.type = .placement
    hd.storageMode = .private
    hd.size = size
    guard let heap = device.makeHeap(descriptor: hd) else { return nil }
    heap.label = "level textures"
    var textures: [any MTLTexture] = []
    for (d, offset) in zip(descriptors, offsets) {
        guard let t = heap.makeTexture(descriptor: d, offset: offset) else { return nil }
        textures.append(t)
    }
    return (heap, textures)
}
```

- Size textures with `heapTextureSizeAndAlign(descriptor:)`. The
  `makeTexture(descriptor:offset:)` page points at `heapBufferSizeAndAlign` for
  textures; that is a doc slip. The size includes the mip chain: on an M4 Pro a
  mipmapped 256×256 RGBA8 texture came back as 352,768 bytes with 128-byte alignment.
- A placement resource aliases anything else in `[offset, offset + size)`. Aliasing is a
  feature (two passes' intermediates that are never live together can share bytes), but
  the hand-off between aliases needs a barrier or fence, and the new owner must not
  assume the old bytes.
- On an automatic heap, `makeAliasable()` hands a dead resource's memory to the next
  allocation. The resource can't be revived, and reading it afterward is undefined.
  Order the next allocation's first use after the old one's last use with an event or
  fence.
- `maxAvailableSize(alignment:)` reports the largest allocation that fits now, which
  measures fragmentation. Rebuild a scratch heap only when it comes back too small.
- Split heaps by lifetime: one per level or zone for loaded data, one scratch heap for
  per-frame transients. That split is also the residency split (next section).
- Merge many small buffers used together into one buffer or one heap. Compare a
  buffer's `length` with `allocatedSize`, because Metal can round small allocations up.

## Residency sets

In Metal 4 a residency set is the only way to make a resource resident. The rules for
sets are in `command-model.md`, "Residency": queue sets against command-buffer sets, the
32-set limit, staged edits, thread safety, and `requestResidency()`. One rule matters
for memory layout:

- **A heap entry makes the whole heap resident**, and so does adding any one resource
  that came from a heap. Residency granularity is therefore your heap granularity.
  Split heaps by lifetime, so that a zone's set holds only that zone's heaps.

```swift
import Metal

/// One residency set per streamed zone. Warm the next zone while the current one plays.
final class ZoneResidency {
    let set: any MTLResidencySet

    init(device: any MTLDevice, label: String, heaps: [any MTLHeap]) throws {
        let d = MTLResidencySetDescriptor()
        d.label = label
        d.initialCapacity = heaps.count
        set = try device.makeResidencySet(descriptor: d)
        set.addAllocations(heaps)   // each heap makes everything in it resident
        set.commit()                // staged changes apply only here
    }

    /// At a loading screen, or while the previous zone still plays.
    func prepare() { set.requestResidency() }

    func activate(on queue: any MTL4CommandQueue) { queue.addResidencySet(set) }

    /// Only after the last command buffer that touches this zone has completed.
    func retire(from queue: any MTL4CommandQueue) {
        queue.removeResidencySet(set)
        set.endResidency()
    }
}
```

## Texture views and view pools

- `makeTextureView(pixelFormat:)` shares storage and reinterprets it. Formats are
  compatible within a bit width, and between sRGB and linear forms of one compressed
  format. A layout-changing view needs `.pixelFormatView` on the parent, which costs
  lossless compression, so prefer a swizzle or an sRGB/linear view where one fits.
- Model I/O loads every USD texture as linear `.rgba8Unorm`, base color included; the fix is
  a `.rgba8Unorm_srgb` view of the base color only. *Metal by Tutorials* adds
  `.pixelFormatView` for that view because the Simulator's validation rejected it
  without. The `pixelFormatView` symbol page says an sRGB-only view doesn't need the
  flag, and the docs win: leave it off on devices and keep the lossless compression.
- **`MTLTextureViewPool`** (Metal 4, Apple7 and later) makes lightweight views that
  aren't full `MTLTexture` objects. A pool from `makeTextureViewPool(descriptor:)` owns a
  contiguous range of `MTLResourceID`s that starts at `baseResourceID`, so slot *k* is
  base + *k*. That suits bindless texture arrays indexed by offset. The pool holds 128 M
  entries on Apple7–8 and 256 M on Apple9–10 (Feature Set Tables). A slot can later hold
  a view of a different texture, but a slot that frames in flight still read is a
  hazard: retire it like any other resource.

```swift
import Metal

/// Publishes a bindless slot that exposes only the mips that have streamed in.
func publishView(pool: any MTLTextureViewPool, slot: Int,
                 texture: any MTLTexture, firstResidentLevel: Int) -> MTLResourceID {
    let v = MTLTextureViewDescriptor()
    v.pixelFormat = texture.pixelFormat
    v.textureType = texture.textureType
    v.levelRange = firstResidentLevel..<texture.mipmapLevelCount
    v.sliceRange = 0..<1
    return pool.setTextureView(texture: texture, descriptor: v, index: slot)
}
```

`MTLTextureViewDescriptor.minLOD` clamps a view's level of detail without changing its
level range, but it needs OS 27; gate it with `#available(macOS 27.0, iOS 27.0, *)`.

| ASTC (LDR), ETC2/EAC, PVRTC | Apple2 | ASTC is the cross-device choice on iPhone and iPad. |
| ASTC HDR | Apple6 | |
| BC1–BC7 | Apple9 | Apple7 and Apple8 have it on every Mac and some iPads: check `supportsBCTextureCompression`. |

- Ship ASTC for iPhone and iPad. A Mac-only build may use BC; a universal asset pipeline
  either ships both or picks ASTC, because every Apple-silicon Mac is Apple7 or later.
- Use the smallest format that holds the data: single-channel `.r8Unorm` for height and
  masks, 16-bit only where accuracy demands it (G-buffer normals).
- Maximum 2D size is 16,384 px on Apple3–Apple9 and 32,768 px on Apple10. A 16K RGBA8
  texture is 1 GiB before its mips, which is what sparse textures are for.

## Mipmaps and mip streaming

- `mipmapLevelCount` defaults to 1. A full chain has `floor(log2(maxDimension)) + 1`
  levels and costs about a third more memory. Apple's mipmapped-texture sample computes
  `ceil(log2(...))`, which is one level short for power-of-two sizes; a 256×256 texture
  needs 9 levels (confirmed: `texture2DDescriptor(..., mipmapped: true)` returns 9).
- Metal neither fills mips nor tracks which ones you filled. `MTKTextureLoader`'s
  `.allocateMipmaps` allocates every level but fills only level 0; `.generateMipmaps`
  fills them.
- An MSL `constexpr sampler` defaults to `mip_filter::none`, which reads only mip 0. Set
  the mip filter or minified textures shimmer and waste bandwidth.
- **Every level is allocated at creation.** Streaming mips into an ordinary texture saves
  load time and bandwidth, not memory; only sparse textures save memory. Load the small
  levels first (from level 3 down is about 2% of the chain's data), then clamp sampling
  to what has arrived. The clamp options, cheapest first:
  - `MTLSamplerDescriptor.lodMinClamp`, which applies even to explicit-LOD samples;
  - a texture view whose level range starts at the first resident level (above);
  - per-sample `min_lod_clamp(level)` in MSL, which needs `mac2` or `apple6`.

## Sparse textures in Metal 4: placement sparse

The Metal 3 sparse path (a `.sparse` heap mapped through `MTLResourceStateCommandEncoder`)
doesn't carry into Metal 4: residency sets reject sparse heaps, and Metal 4 has no
resource-state encoder. The Metal 4 path is **placement sparse**:

- The texture descriptor sets `placementSparsePageSize` to a non-zero `MTLSparsePageSize`;
  that alone makes the texture placement sparse. The texture is created from the device
  and owns no tile memory.
- Physical tiles come from a `.placement` heap whose `maxCompatiblePlacementSparsePageSize`
  is at least the texture's page size. That heap is an ordinary allocation, so it goes in
  a residency set.
- `MTL4CommandQueue.updateMappings(texture:heap:operations:)` maps and unmaps on the
  queue's timeline. Regions are in **tiles**, not pixels. For the mip tail, the level is
  `firstMipmapInTail`, `origin.y` is 0, and `size.height` is 1. After mapping, the
  consumer must barrier on `.resourceState`, the stage that stands for every sparse
  mapping update.
- Gate: Metal 4 and Apple8 per the Feature Set Tables, plus some Apple7 devices including
  every Apple7 Mac. The runtime query `supportsPlacementSparse` exists only from OS 26.4.

Checked on an M4 Pro (Apple9) under macOS 27.0.1: a 4096×4096 RGBA8 placement sparse
texture made by `device.makeTexture(descriptor:)` reported `sparseTextureTier` tier 2,
mip tail at level 6, and an `allocatedSize` of 704 KB against 64 MB plus mips for a dense
copy. A residency set accepted its placement heap.

```swift
import Metal

func supportsMetal4Sparse(_ device: any MTLDevice) -> Bool {
    guard device.supportsFamily(.metal4) else { return false }
    if #available(macOS 26.4, iOS 26.4, *) { return device.supportsPlacementSparse }
    return device.supportsFamily(.apple8)   // conservative before 26.4: skips the Apple7 devices that have it
}

/// A placement sparse texture plus a placement heap that holds its physical tiles.
func makeStreamedTexture(device: any MTLDevice, size: Int,
                         tileBudget: Int) -> (texture: any MTLTexture, tiles: any MTLHeap)? {
    let td = MTLTextureDescriptor.texture2DDescriptor(
        pixelFormat: .rgba8Unorm, width: size, height: size, mipmapped: true)
    td.storageMode = .private
    td.usage = [.shaderRead]
    td.placementSparsePageSize = .size64          // non-zero: placement sparse
    guard let texture = device.makeTexture(descriptor: td) else { return nil }

    let hd = MTLHeapDescriptor()
    hd.type = .placement
    hd.storageMode = .private
    hd.maxCompatiblePlacementSparsePageSize = .size64   // at least the texture's page size
    hd.size = tileBudget * device.sparseTileSizeInBytes(sparsePageSize: .size64)
    guard let tiles = device.makeHeap(descriptor: hd) else { return nil }
    return (texture, tiles)
}

/// Maps a tile region to consecutive heap tiles starting at `heapTile`.
func mapTiles(_ region: MTLRegion, level: Int, heapTile: Int,
              texture: any MTLTexture, tiles: any MTLHeap, queue: any MTL4CommandQueue) {
    let op = MTL4UpdateSparseTextureMappingOperation(
        mode: .map, textureRegion: region,        // in tiles, not pixels
        textureLevel: level, textureSlice: 0, heapOffset: heapTile)
    queue.updateMappings(texture: texture, heap: tiles, operations: [op])
}

/// In the next pass that samples the texture.
func waitForMappings(_ render: any MTL4RenderCommandEncoder) {
    render.barrier(afterQueueStages: .resourceState, beforeStages: .fragment,
                   visibilityOptions: .device)
}
```

The 26.0–26.3 fallback to `.apple8` is an inference from the tables, not a documented
rule. The sparse articles were written for the Metal 3 path; these rules from them still
hold:

- A newly mapped tile holds garbage until you write it. Unmapped regions read as zero
  and writes to them are dropped, so shaders keep working.
- On the Metal 3 path a full sparse heap skips the rest of a mapping request with no
  error. With placement sparse you pass each `heapOffset` yourself, so keep your own
  tile allocator and never hand out an offset past the heap's tile count.
- Map the mip tail at creation and keep it mapped, so a sample always finds data.
- Never remap a region a pass in flight reads or writes; order the two with a barrier or
  event. Return a tile to your allocator only after the unmap and after the frames that
  sampled it have completed.
- Evict with an LRU that skips tiles frames in flight still use, and never evict a
  coarser tile that a finer resident tile depends on: the chain must stay contiguous
  down to the tail.
- Sparse textures can't be bound with `write` or `read_write` access, and Shader
  Validation doesn't track the residency of sparse backing pages.
- **The SDK drops the access-counter feedback loop the docs describe.** The streaming
  sample and the sparse articles pick tiles to map with the blit encoder's
  `getTextureAccessCounters`. The current SDK marks it deprecated as of macOS and iOS
  26.4, with the message "Access counters are no longer supported in Metal", and
  `MTL4ComputeCommandEncoder` has no counterpart. The SDK wins: drive mapping from your
  own feedback, such as the wanted level per tile written by the shader
  (`calculate_clamped_lod`, Apple7 or Mac2) or a CPU estimate from distance and screen
  size.

In the shader, sample sparsely and fall back to the always-mapped tail:

```metal
#include <metal_stdlib>
using namespace metal;

fragment half4 streamedAlbedo(float2 uv [[stage_in]],
                              texture2d<half> albedo [[texture(0)]],
                              constant uint &tailLevel [[buffer(0)]])
{
    constexpr sampler s(filter::linear, mip_filter::linear);
    sparse_color<half4> c = albedo.sparse_sample(s, uv);
    if (c.resident()) {
        return c.value();
    }
    return albedo.sample(s, uv, min_lod_clamp(float(tailLevel)));
}
```

## Streaming from disk: the IO command queue

`MTLIOCommandQueue` loads file data straight into buffers and textures, private ones
included, with no CPU staging copy. It works on Metal 3 and Metal 4 alike (Apple2 and
later), and orders against an `MTL4CommandQueue` through a shared event.

```swift
import Metal

/// A bulk queue for level data and a high-priority queue for latency-sensitive loads.
func makeStreamingQueues(device: any MTLDevice) throws -> (bulk: any MTLIOCommandQueue,
                                                           urgent: any MTLIOCommandQueue) {
    let d = MTLIOCommandQueueDescriptor()
    d.type = .concurrent
    d.priority = .normal
    let bulk = try device.makeIOCommandQueue(descriptor: d)
    d.priority = .high        // changing the descriptor doesn't touch queues already made
    let urgent = try device.makeIOCommandQueue(descriptor: d)
    return (bulk, urgent)
}

/// Loads one RGBA8 mip level from a pack file; the render queue waits on the GPU, not the CPU.
func streamLevel(_ level: Int, of texture: any MTLTexture, from file: any MTLIOFileHandle,
                 at fileOffset: Int, io: any MTLIOCommandQueue,
                 render: any MTL4CommandQueue, loaded: any MTLSharedEvent, ticket: UInt64) {
    let w = max(1, texture.width >> level), h = max(1, texture.height >> level)
    let cb = io.makeCommandBuffer()
    cb.load(texture, slice: 0, level: level,
            size: MTLSize(width: w, height: h, depth: 1),
            sourceBytesPerRow: w * 4, sourceBytesPerImage: w * h * 4,
            destinationOrigin: MTLOrigin(x: 0, y: 0, z: 0),
            sourceHandle: file, sourceHandleOffset: fileOffset)
    cb.signalEvent(loaded, value: ticket)
    cb.commit()
    render.waitForEvent(loaded, value: ticket)
}
```

- **Use `makeIOFileHandle(url:)` and `makeIOFileHandle(url:compressionMethod:)`.** The
  resource-loading article still uses `makeIOHandle`, which the SDK deprecated at
  macOS 14 and iOS 17. The handle, the queue, and its command buffers must all come
  from one device.
- A queue-level `waitForEvent` holds **all** later work on that queue. Issue it in the
  frame that first samples the data, and keep drawing with the resident lower mips until
  then, rather than waiting every frame.
- Load what the first frame needs first and stream the rest. Start several IO command
  buffers and `tryCancel()` the ones the player outran. Put sound effects and other
  latency-sensitive loads on the high-priority queue. An IO command buffer holds at most
  8,192 commands (Feature Set Tables).
- Compress at build time and ship the compressed file. The codecs are
  `MTLIOCompressionMethod` cases (`.zlib`, `.lzfse`, `.lz4`, `.lzma`, `.lzBitmap`):

```swift
import Metal

/// Build-time tool: writes `bytes` to a pack file the IO queue can decompress at load.
func writePack(_ bytes: [UInt8], to path: String) -> Bool {
    guard let ctx = MTLIOCreateCompressionContext(path, .lz4,
                                                  MTLIOCompressionContextDefaultChunkSize()) else {
        return false
    }
    bytes.withUnsafeBytes { MTLIOCompressionContextAppendData(ctx, $0.baseAddress!, $0.count) }
    return MTLIOFlushAndDestroyCompressionContext(ctx) == .complete
}
```

## Purgeable caches

`setPurgeableState(.volatile)` lets the system discard a resource's contents under
pressure, and a volatile or empty resource doesn't count toward the app's footprint. It
is the right state for anything you might want again but could rebuild: decoded
textures for the last zone, shadow caches, impostor atlases.

- Before reuse, call `setPurgeableState(.nonVolatile)`. It returns the **prior** state;
  if that is `.empty`, the contents are gone and must be regenerated.
- `.keepCurrent` queries without changing. `.empty` says you are discarding the contents.
- Resources inside a heap follow the heap's purgeable state, so mark the heap.

## Budgeting unified memory

On Apple silicon the GPU's resources and the simulation's heap come from the same RAM,
and both count toward one footprint.

- **iOS and iPadOS terminate the app** past a per-device limit, so test on every model
  you support. `os_proc_available_memory()` reports the bytes left before that limit; it
  doesn't exist on macOS, changes constantly, and shouldn't be cached. The
  `com.apple.developer.kernel.increased-memory-limit` entitlement raises the limit on
  some devices.
- **macOS:** `recommendedMaxWorkingSetSize` approximates how much the GPU can hold
  without losing performance (37.4 GiB, about 78%, on a 48 GB M4 Pro), and
  `currentAllocatedSize` is what the device holds now.
- **Instruments' Allocations track omits `.private` Metal resources.** Metal memory
  shows under `VM: IOAccelerator` and drawables under `VM: IOSurface`. Compressed or
  swapped memory counts at its uncompressed size, so the OS compressor doesn't save you
  from the limit.
- **Bandwidth is shared too.** Heavy GPU traffic can starve the CPU's memory access, and
  the simulation slows with no CPU hotspot to show for it. Narrow usage flags, store
  only attachments a later pass reads, and prefer compressed formats.
- Budget textures by math before art arrives: RGBA8 with mips is about 21.3 MiB at
  2048² and 5.3 MiB at 1024². Color maps matter most, then normals; shrink metallic,
  roughness, and AO first.
- Levers in order of payoff: compressed formats and smaller assets on smaller devices;
  `.memoryless` for transient attachments; heap aliasing for intermediates that are
  never live together; volatile caches; sparse textures for anything huge. Under
  pressure, also drop shadow and SSAO resolution, and release `MTLFunction` objects
  while keeping their pipeline states.

## Simulator

The Simulator runs on the Mac's GPU, exposes roughly Apple2-level features (far below
Metal 4's Apple7 floor), and does no memory-footprint analysis, so make every memory
decision on a device. Its resource rules differ and no Metal API reports them; branch
on `#if targetEnvironment(simulator)`. Depth, stencil, and MSAA textures and all heaps
must be `.private`; there is no 2× MSAA and only combined depth-stencil formats;
constant buffers are capped at 64 KB, 256 B offset alignment, and 14 per pipeline; and
buffer-backed textures use a different alignment (`minimumLinearTextureAlignment(for:)`)
and can't be render targets.

## Maintaining older code: Metal 3

The Metal 3 path applies on GPU families below Apple7 (A13 and earlier; Apple6 is the
last Metal 3-only family) and on any OS release before 26.0. Gate at runtime: OS first,
then family, and pick one resource strategy for the whole renderer.

Snippets in this section compile at the file's macOS 26.0 floor; they are not compile-checked against earlier OS releases.

```swift
import Metal

enum ResourcePath { case metal4, metal3 }

func resourcePath(for device: any MTLDevice) -> ResourcePath {
    if #available(macOS 26.0, iOS 26.0, *), device.supportsFamily(.metal4) {
        return .metal4
    }
    return .metal3
}

/// Metal 3: resources reached only through an argument buffer need per-encoder residency.
func makeResidentMetal3(_ encoder: any MTLRenderCommandEncoder,
                        heap: any MTLHeap, writable: any MTLTexture) {
    encoder.useHeap(heap, stages: .fragment)          // marks everything in the heap read-only
    encoder.useResource(writable, usage: [.read, .write], stages: .fragment)  // writes need their own call
}

/// Metal 3 sparse mapping. On macOS the method is an optional protocol requirement.
func mapMetal3(_ commandBuffer: any MTLCommandBuffer, texture: any MTLTexture,
               region: MTLRegion, level: Int) {
    guard let rs = commandBuffer.makeResourceStateCommandEncoder() else { return }
    rs.updateTextureMapping?(texture, mode: .map, region: region, mipLevel: level, slice: 0)
    rs.endEncoding()
}
```

| Metal 3 | Metal 4 |
|---|---|
| `useResource(_:usage:stages:)`, `useHeap(_:stages:)` per encoder; a missing one fails the command buffer | Residency sets on the queue or command buffer. On OS 15/18 and later a Metal 3 `MTLCommandQueue` accepts residency sets too, so one residency design can serve both paths. |
| `.tracked` resources ordered automatically (device resources tracked by default, heap resources untracked) | No tracking at all; barriers, fences, events |
| `MTLCommandBuffer` retains what it references | `MTL4CommandBuffer` retains nothing; deferred release |
| `MTLBlitCommandEncoder` copies, `generateMipmaps(for:)`, `optimizeContentsForGPUAccess` | Same commands on `MTL4ComputeCommandEncoder`, in the `.blit` stage, with intrapass barriers |
| `.sparse` heap plus `MTLResourceStateCommandEncoder.updateTextureMapping` | Placement sparse texture, `.placement` heap, `MTL4CommandQueue.updateMappings`, barrier on `.resourceState` |
| `getTextureAccessCounters` for tile feedback | None; deprecated at 26.4 on both paths |
| `MTLArgumentEncoder` (Tier 1, or Tier 2 before iOS 16 / macOS 13) | Argument tables and `gpuAddress`/`gpuResourceID` written directly (`command-model.md`) |
| `.managed` storage on Intel and discrete GPUs, with `didModifyRange` and `synchronize(resource:)` | Not applicable; `.managed` is deprecated in the macOS 27 SDK |

Two porting notes. Heap resources were already untracked in Metal 3, so heap-based code
usually has its fences in place; code that leaned on tracked device resources needs a
barrier wherever Metal used to infer an order. And a residency set takes no usage
flags, so the Metal 3 split between `useHeap` (read-only) and `useResource` with
`.write` has nothing to port to.
