# Task 3 triage: `accessibility.md` snippet failures

Source: `authoring/apple-studio/records/2026-09-30-phase9-adaptive-layout/survey/typecheck-apple-design-baseline.log`, lines 4-5 (failure #1) and 179 (failure #2).

| # | Snippet | Compiler error (quoted) | Classification | Reason |
|---|---------|--------------------------|-----------------|--------|
| 1 | `Slider(value: $guess.red)` (accessibility.md:29-37) | `<snippet>:1:1: error: expressions are not allowed at the top level` and `<snippet>:1:15: error: cannot find '$guess' in scope` | **Framing artifact, plus a reference defect** | Framing: `$guess` is never declared anywhere in the snippet or surrounding prose, and the `Slider`/`Image` chains sit at top level with no enclosing `View`/function — none of the harness's wrapping modes (parse-as-library, with-prior, with-prior+ctx, top-level, wrapped-in-func) give it a declaration context or a `guess` binding, so it fails in every mode the same way. Reference defect: even once wrapped and given a real `@State` binding, the snippet calls `.accentColor(_:)`, which is deprecated as of iOS 27.2/macOS 27.2 (etc.) in favor of `.tint(_:)` — confirmed live via `docc.py "swiftui/view/accentcolor(_:)"` in `task-1-docc/live-check.log` line 8 (`DEPRECATED: iOS 27.2, ... — Use the asset catalog's accent color or 'tint(_:)' instead.`). Fix must both give the snippet a real declaration context and drop the deprecated API. |
| 2 | `@Environment(\.accessibilityReduceMotion) private var reduceMotion` (accessibility.md:63-69) | `<snippet>:2:1: error: property wrappers are not yet supported in top-level code` and `<snippet>:5:28: error: cannot find 'staticGlyph' in scope` / `:5:51: error: cannot find 'animatedGlyph' in scope` | **Framing artifact, plus a reference defect** | Framing: the `@Environment` property wrapper sits at top level with no enclosing type, which Swift rejects outright ("property wrappers are not yet supported in top-level code"); `staticGlyph`/`animatedGlyph` are referenced but never defined anywhere in the snippet. Reference defect: independent of the framing fix, the body expression `reduceMotion ? AnyView(staticGlyph) : AnyView(animatedGlyph)` uses a ternary wrapping both branches in `AnyView` to unify their types — this erases view identity (SwiftUI treats the two branches as the same erased type across state changes, defeating diffing/animation identity) where an `if`/`else` inside a `@ViewBuilder` body is the idiomatic SwiftUI form and preserves per-branch identity. Fix must both give the snippet a real declaration context and replace the `AnyView` ternary with `if`/`else`. |

Both failures are classified identically: a framing artifact (undeclared bindings / top-level property wrapper with no enclosing declaration, an artifact of how the snippet was excerpted for prose, not a claim about API behavior) compounded by a genuine reference defect (a deprecated API in #1, an anti-pattern that erases view identity in #2). Both parts are fixed together in Steps 2-3 of the brief: each snippet becomes a complete, minimal `struct ... View` so the compiler has a real context, `.accentColor(.red)` is replaced with `.tint(.red)`, and the `AnyView` ternary is replaced with an `if`/`else` in the `@ViewBuilder` body.
