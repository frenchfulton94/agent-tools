# Notes m07

## command-model.md

- The May 21, 2026 Feature Set Tables list **only Apple GPU families (Apple2..Apple10)**; no Mac2/Intel/AMD column exists any more. The "Metal" column is a programming-model axis: the "Metal 3" model is the combined Metal 1/2/3 API surface on every Apple family; the "Metal 4" model starts at Apple7. Rows read "Metal 3 & 4" or "Metal 4" — pdf:fst#all [symbols: MTLGPUFamily] [gate: Metal 4 = Apple7+]
- Family map: A13 = Apple6 (Metal 3 model only); A14 and M1 = Apple7; A15, A16, M2 = Apple8; A17 Pro, A18, M3, M4 = Apple9; A19 and M5 = Apple10. So the Metal 4 path needs an A14/M1 or later device — pdf:fst#all [symbols: MTLGPUFamily.apple7, MTLGPUFamily.apple10] [gate: Apple7+]
- Rows that exist only in the Metal 4 model (all Apple7+): argument tables, command allocators, decoupled command queues and command buffers, command barriers, dedicated compilation contexts, pipeline dataset serialization, flexible render pipeline state, machine learning encoding, tensors, performance counter heaps. Placement sparse buffers/textures: Metal 4, Apple8 (some Apple7 including every Apple7 Mac; test `MTLDevice.supportsPlacementSparse`). Address-driven acceleration structure builds: Metal 4, Apple9 — pdf:fst#all [symbols: MTL4ArgumentTable, MTL4CommandAllocator, MTL4CommandQueue, MTLDevice.supportsPlacementSparse] [gate: Metal 4; Apple7 / Apple8 / Apple9]
- Residency sets are available in both models from Apple6, limited to 32 per queue and 32 per command buffer — pdf:fst#all [symbols: MTLResidencySet] [gate: Apple6]
- Per-stage binding limits double as `MTL4ArgumentTable` limits: 31 buffers, 128 textures (Apple6+; 96 on Apple4/5; 31 on Apple2/3), 16 samplers, 31 threadgroup-memory slots, 31 vertex attributes. Inline `constexpr` samplers written in MSL count against the 16. `setBytes`-style inline data is capped at 4 KB — pdf:fst#all [symbols: MTL4ArgumentTableDescriptor.maxBufferBindCount, MTL4ArgumentTableDescriptor.maxTextureBindCount] [gate: Apple6+ for 128 textures]
- Render-encoder memory barriers on Apple3..Apple10 cannot name `.fragment` or `.tile` in the *after* stages, nor use `MTLBarrierScope.renderTargets`, for `memoryBarrier(scope:after:before:)` and `memoryBarrier(resources:after:before:)`. ICB-encoded memory barriers: compute Apple3, render Apple9 — pdf:fst#all [symbols: MTLRenderCommandEncoder.memoryBarrier(scope:after:before:), MTLBarrierScope.renderTargets, MTLRenderStages.fragment] [gate: Apple3..Apple10]
- Numbers: 32,768 fences max; 8192 commands per IO command buffer; counter sample buffers 32 KB each, 32 of them; performance counter heaps 32 per process (Metal 4, Apple7+) — pdf:fst#all [symbols: MTLFence, MTLIOCommandBuffer, MTL4CounterHeap] [gate: Apple7 for counter heaps]
- Lifetime split is the frame-loop rule: device, queue, libraries, pipeline states, and meshes are created once at startup; each frame makes only the command buffer and encoder(s). Building pipelines or loading buffers inside the frame causes stutter — book:metal-by-tutorials/chapters/ch01-hello-metal.md [symbols: MTLCreateSystemDefaultDevice, makeCommandQueue] [book: ch01 differs: the book makes a fresh `MTLCommandBuffer` per frame from `commandQueue.makeCommandBuffer()` and commits it with `commandBuffer.commit()`. Metal 4 creates `device.makeMTL4CommandQueue()` once and reusable `MTL4CommandBuffer`s via `device.makeCommandBuffer()`, encodes between `beginCommandBuffer(allocator:)` and `endCommandBuffer()` using an `MTL4CommandAllocator` per frame in flight (`device.makeCommandAllocator()`, `reset()` once the GPU finishes that frame), and submits with `MTL4CommandQueue.commit(_:options:)`. The "create cheap things per frame" principle holds; the objects differ]
- Drawable present differs in Metal 4: there is no `present(_:)` on `MTL4CommandBuffer`. Call `MTL4CommandQueue.waitForDrawable(_:)` before committing work that targets the drawable, `signalDrawable(_:)` after the last such commit, then `drawable.present()`. `signalDrawable` fails if called twice or after `present` — book:metal-by-tutorials/chapters/ch01-hello-metal.md [symbols: MTL4CommandQueue.waitForDrawable(_:), MTL4CommandQueue.signalDrawable(_:), MTLDrawable.present()] [gate: Metal 4, OS 26] [book: ch01 differs: book uses `commandBuffer.present(drawable)` then `commit()`, the Metal 3 spelling]
- Binding differs: `MTL4RenderCommandEncoder` has no `setVertexBuffer`; bind GPU addresses in an `MTL4ArgumentTable` (`setAddress(_:index:)`, `setAddress(_:attributeStride:index:)`, `setTexture`, `setSamplerState`) and attach it with `setArgumentTable(_:stages:)`. The book's `setVertexBuffer(_:offset:index:)` "index = argument-table slot" idea maps onto the table index — book:metal-by-tutorials/chapters/ch01-hello-metal.md [symbols: MTL4ArgumentTable, MTL4RenderCommandEncoder.setArgumentTable(_:stages:)] [book: ch01 differs: book uses `MTLRenderCommandEncoder.setVertexBuffer(_:offset:index:)`]
- Indexed draws in Metal 4 take a GPU address and byte length for the index buffer: `drawIndexedPrimitives(primitiveType:indexCount:indexType:indexBuffer:indexBufferLength:)` with `indexBuffer: MTLGPUAddress`. Buffers must also be resident (residency set on queue or command buffer; `MTKView.residencySet` exists for the view's own textures) — book:metal-by-tutorials/chapters/ch01-hello-metal.md [symbols: MTL4RenderCommandEncoder.drawIndexedPrimitives(primitiveType:indexCount:indexType:indexBuffer:indexBufferLength:), MTLGPUAddress, MTKView.residencySet, MTL4CommandBuffer.useResidencySet(_:)] [book: ch01 differs: book passes `indexBuffer: MTLBuffer` + `indexBufferOffset` and never mentions residency]

## pipelines-and-render-passes.md

- Variable rasterization rate: shader side constructs `rasterization_rate_map_decoder(constant rasterization_rate_map_data&)` and calls `map_screen_to_physical_coordinates` / `map_physical_to_screen_coordinates` (per layer). The buffer must be filled by `MTLRasterizationRateMap copyParameterDataToBuffer:offset:`; the data type is incomplete (no sizeof/pointer arithmetic). iOS Metal 2.2, macOS 2.3. Useful beyond VR for cheap periphery shading — pdf:msl-4.1#ch6 [symbols: rasterization_rate_map_decoder, rasterization_rate_map_data, MTLRasterizationRateMap, copyParameterDataToBuffer:offset:] [gate: iOS 2.2, macOS 2.3]
- Pipeline gates: function specialization Apple2; binary archives Apple3; render and compute dynamic libraries Apple6; function pointers in compute and render pipelines Apple6; up to 65,536 function constants. Function pointers and ray tracing inside render pipelines cannot be combined with mesh shading; mesh pipelines may link Metal IR only through `MTLLinkedFunctions.privateFunctions` — pdf:fst#all [symbols: MTLBinaryArchive, MTLLinkedFunctions.privateFunctions] [gate: Apple3 / Apple6]
- Render-target numbers: 8 color attachments per pass; MSAA tops out at 4 samples on Apple2..Apple9 and **8 samples on Apple10**; tile size 32x32 (no MSAA or 2x), 32x16 (4x), 16x16 (8x, Apple10 only) — pdf:fst#all [gate: Apple10 for 8x]
- Format capabilities that change render decisions (verified on PDF pages 12–15): R32Float, RG32Float, RGBA32Float are "All" (filter + blend + resolve) only from Apple9; Apple7/8 iPads may expose filtering through `MTLDevice.supports32BitFloatFiltering`. Depth32Float and Depth32Float_Stencil8 become filterable at Apple9; Depth16Unorm is filterable everywhere; Depth32Float_Stencil8 never supports sparse — pdf:fst#all [symbols: MTLPixelFormatDepth32Float, MTLPixelFormatDepth32Float_Stencil8, MTLDevice.supports32BitFloatFiltering] [gate: Apple9]
- Other render gates: programmable blending, memoryless targets, dual-source blending, deferred store action, programmable sample positions, MSAA blits — Apple2; MSAA depth resolve and combined store+resolve — Apple3; layered rendering Apple5 (to MSAA textures Apple7); multiple viewports Apple5 (16 viewports/scissors); stencil feedback and stencil resolve Apple5; border color Apple7; primitive ID and barycentrics Apple7; vertex amplification Apple6 (max count 2 on Apple6, 8 from Apple7); variable rasterization rate Apple6; fragment visibility count accumulation Apple7; color attachment mapping Apple7; depth bounds testing, sampler LOD bias, sampler min/max reduction, pre-raster per-vertex values — Apple10 — pdf:fst#all [gate: as listed]
- Tessellation is listed for the Metal 3 model only (Apple3; indirect tessellation arguments and tessellation in ICBs Apple5): the Metal 4 model column omits it — pdf:fst#all [gate: Metal 3 model only]
- Fragment `[[stage_in]]` budget: 124 scalar components on Apple4+ (60 on Apple2/3); vectors count per component — pdf:fst#all
- Descriptor-then-immutable-object pattern and "one pipeline state per shader/vertex-layout combination, all built up front" — book:metal-by-tutorials/chapters/ch01-hello-metal.md [symbols: MTLRenderPipelineDescriptor, makeRenderPipelineState(descriptor:)] [book: ch01 differs: Metal 4 compiles through an `MTL4Compiler` (`device.makeCompiler(descriptor:)`) from an `MTL4RenderPipelineDescriptor` whose shaders are `MTL4LibraryFunctionDescriptor` (`name` + `library`) set on `vertexFunctionDescriptor`/`fragmentFunctionDescriptor`, via `makeRenderPipelineState(descriptor:dynamicLinkingDescriptor:compilerTaskOptions:)` (sync or async). The book uses `device.makeRenderPipelineState(descriptor:)` with `vertexFunction`/`fragmentFunction` from `library.makeFunction(name:)`. `vertexDescriptor` and `colorAttachments[0].pixelFormat` keep the same names on the MTL4 descriptor]
- Shader source compiled from a Swift string only fails at runtime (`makeLibrary(source:options:)`); ship `.metal` files so Xcode compiles them at build time — book:metal-by-tutorials/chapters/ch01-hello-metal.md [symbols: makeLibrary(source:options:)] [book: ch01 agrees]
- `MTKView.currentRenderPassDescriptor` can be nil on a given frame; return early from `draw(in:)` instead of crashing. Read it (it acquires the drawable) as late as possible. Metal 4 path: `MTKView.currentMTL4RenderPassDescriptor` returns an `MTL4RenderPassDescriptor` for `MTL4CommandBuffer.makeRenderCommandEncoder(descriptor:options:)` — book:metal-by-tutorials/chapters/ch01-hello-metal.md [symbols: MTKView.currentRenderPassDescriptor, MTKView.currentMTL4RenderPassDescriptor, MTL4RenderPassDescriptor] [book: ch01 agrees on nil handling; differs on the descriptor type for Metal 4]

## apple-gpu-tbdr.md

- Imageblock gates: macOS Metal 2.3 on Apple silicon only; iOS Metal 2 — pdf:msl-4.1#ch6 [symbols: imageblock] [gate: Apple silicon; macOS Metal 2.3]
- Imageblock queries: `get_width/height/num_samples`, `get_num_colors(coord)`, `get_color_coverage_mask(coord, color_index)`; MSAA imageblocks can store per unique color (color rate) instead of per sample, and a color-rate write must use `write(data, coord, color_coverage_mask)` — pdf:msl-4.1#ch6 [symbols: get_num_colors, get_color_coverage_mask, imageblock_data_rate]
- Implicit layout (`imageblock<T, imageblock_layout_implicit>`, members tagged `[[color(n)]]`): use `read/write(coord[, index, data_rate])` and `slice(color_index[, size])`. Explicit layout (`imageblock<T>`): take `threadgroup_imageblock T* data(coord[, index, data_rate])` and `slice(member[, size])`; `data(coord)` on an MSAA block means sample 0 — pdf:msl-4.1#ch6 [symbols: imageblock_layout_implicit, imageblock_layout_explicit, threadgroup_imageblock, imageblock_slice]
- Writing a tile out: `texture.write(img_blk.slice(...), coord[, lod])` for 1D/2D/2D MSAA/arrays/cube/3D; the slice region starts at (0,0); out-of-bounds slice writes are *undefined* (unlike ordinary texture writes, which are ignored), and MSAA modes of slice and texture must match. Spec example: one thread (lid 0,0) issues the slice write after a `threadgroup_barrier(mem_flags::mem_threadgroup_imageblock)` — pdf:msl-4.1#ch6 [symbols: imageblock_slice, mem_threadgroup_imageblock]
- Tile-shading gates: memoryless render targets Apple2; imageblocks, tile shaders, imageblock sample coverage control, post-depth coverage, raster order groups (max 8 per fragment function), nonuniform threadgroup sizes — Apple4; nonsquare tile dispatch Apple5 — pdf:fst#all [gate: Apple4]
- On-chip budget: threadgroup memory and imageblock memory come from one pool. Threadgroup max 32 KB (Apple4+); explicit imageblock 32 KB; implicit imageblock 128 KB on Apple4..Apple8 and **256 KB on Apple9/10**. Per-pixel, per-sample imageblock size with several color targets: explicit 64 B; implicit 64 B (Apple3–5), 128 B (Apple6+) — pdf:fst#all [gate: Apple9 for 256 KB]
- `A8Unorm` is incompatible with explicit-layout imageblocks; use an R8Unorm view or implicit layout — pdf:fst#all [symbols: MTLPixelFormatA8Unorm]

## resources-and-memory.md

- Texture size limits: 1D/2D/cube max 16,384 px on Apple3..Apple9, **32,768 px on Apple10**; 3D max 2048 per axis; arrays 2048 layers; texture buffers 256 M px, also bounded by `maxBufferLength` divided by pixel size. Texture-to-buffer copy alignment 16 B; constant buffer offset alignment 4 B; threadgroup memory length alignment 16 B — pdf:fst#all [symbols: MTLDevice.maxBufferLength] [gate: Apple10 for 32K]
- Compression gates: ASTC, ETC/EAC, PVRTC Apple2; HDR ASTC Apple6; BC formats Apple9 (Apple7/8: every Mac, some iPads — check `MTLDevice.supportsBCTextureCompression`); compressed volume textures Apple3; lossy texture compression Apple8 (not usable with packed 16-bit, compressed, YUV, depth/stencil formats, `RG11B10Float`, `RGB9E5Float`); universal texture compression Apple10 — pdf:fst#all [symbols: MTLDevice.supportsBCTextureCompression, MTLTextureDescriptor.compressionType] [gate: Apple6 / Apple8 / Apple9 / Apple10]
- Sparse: color textures Apple6 with automatic heap backing (automatic backing excludes sparse buffers and 1D/1DArray/TextureBuffer); depth/stencil sparse Apple8 (some Apple7, all Apple7 Macs, via placement heaps); Metal 4 placement sparse buffers/textures Apple8 — pdf:fst#all [symbols: MTLDevice.supportsPlacementSparse] [gate: Apple6 / Apple8]
- Heaps and placement heaps Apple2; fast resource loading (IO queues) Apple2; nonprivate depth/stencil textures Apple2; texture swizzle Apple2; texture view pools (both models) Apple7 with 128 M entries on Apple7/8 and 256 M on Apple9/10 — pdf:fst#all [symbols: MTLHeap, MTLTextureViewPool] [gate: Apple7 for view pools]
- Argument buffers: tier 1 Apple2, tier 2 Apple6. From Apple6 a stage can reach unlimited buffers and 1 M textures through argument buffers; samplers 128 (Apple6), 996 (Apple7/8), 500 K (Apple9/10). Writable texture arrays Apple6; read/write textures Apple4 (check `MTLDevice.readWriteTextureSupport`) — pdf:fst#all [symbols: MTLDevice.readWriteTextureSupport] [gate: Apple6]
- Atomic-capable formats: `R32Uint`/`R32Sint` from Apple6; `RG32Uint` (for `ulong` textures) from Apple8 on macOS only, Apple9 everywhere, and only where 64-bit atomics exist; texture-buffer R32 formats get atomics wherever texture atomics exist — pdf:fst#all [symbols: MTLPixelFormatR32Uint, MTLPixelFormatRG32Uint] [gate: Apple6 / Apple9]
- `MTLTensor` layout limits: rank 0..16 (packed 2/4/8-bit formats 1..16); packed formats need row size a multiple of 32 elements, row stride a multiple of 512 (2-bit), 256 (4-bit) or 128 (8-bit float) elements, a 128-byte buffer offset, and support block scaling via a `MTLTensorPlaneType.scales` plane of `MetalFloat8UE8M0`. Tensors with `MTLTensorUsage.machineLearning` also need row stride and buffer offset in 64-byte multiples — pdf:fst#all [symbols: MTLTensorExtents, MTLTensorUsage.machineLearning, MTLTensorPlaneType.scales] [gate: Metal 4, Apple7]

## shading-language.md

- MSL 4.1 adds placement `new` (header `<metal_common>`) with `thread`, `threadgroup`, and `device` overloads; the constructed type must spell its address space, as in `new (ptr) device int` — pdf:msl-4.1#ch6 [symbols: operator new] [gate: Metal 4.1, all OS]
- Fast vs precise: for `float`, `clamp`/`saturate`, `distance`/`length`/`normalize`, and most math functions exist in fast and precise forms. `-ffast-math` chooses the default; `metal::fast::` and `metal::precise::` pick one explicitly per call. Fast forms leave NaN handling undefined; precise follow IEEE 754 — pdf:msl-4.1#ch6 [symbols: metal::fast, metal::precise, fast::sin, precise::cos]
- Bit interleave (Morton order) is now built in: `interleave(even, odd)` / `interleave(vec<TiuN,2>)` and `deinterleave(v)` for uchar->ushort, ushort->uint, uint->ulong pairs. Useful for tile/cluster binning and Z-order texture addressing in compute — pdf:msl-4.1#ch6 [symbols: interleave, deinterleave] [gate: Metal 4.1]
- `mul24`/`mad24` give defined results only when operands fit in signed [-2^23, 2^23-1] or unsigned [0, 2^24-1]; outside that the product is implementation-defined — pdf:msl-4.1#ch6 [symbols: mul24, mad24] [gate: Metal 2.1]
- NaN rules worth knowing: `fmax`/`fmin` return the non-NaN argument when one is NaN; `fmedian3` drops NaNs as missing data (two NaNs: returns the other value). `nextafter` needs Metal 3.1 — pdf:msl-4.1#ch6 [symbols: fmax, fmin, fmedian3, nextafter]
- Named constants come in three precisions: `M_PI_F`/`MAXFLOAT` (float), `M_PI_H`/`MAXHALF` (half), `M_PI_BF`/`MAXBFLOAT` (bfloat) — pdf:msl-4.1#ch6 [symbols: M_PI_F, M_PI_H, M_PI_BF, MAXBFLOAT] [gate: Metal 1.2 for float/half]
- SIMD-group matrices (`simdgroup_float8x8`, `simdgroup_load`, `simdgroup_store`, `simdgroup_multiply_accumulate`, `make_filled_simdgroup_matrix`) still exist, but the 4.1 spec now tells you to prefer tensors (spec §2.22) plus Metal Performance Primitives (ch7) for matrix work — pdf:msl-4.1#ch6 [symbols: simdgroup_matrix, simdgroup_multiply_accumulate]
- Barriers and SIMD/quad functions are legal in `[[kernel]]`, `[[fragment]]`, and `[[visible]]` functions they call; barrier docs also name mesh and object stages — pdf:msl-4.1#ch6
- `threadgroup_barrier` and `simdgroup_barrier` gained an overload `(mem_flags, memory_order = memory_order_seq_cst, thread_scope = thread_scope_threadgroup|thread_scope_simdgroup)` in 4.1. On Apple silicon a thread that has returned stops counting toward a barrier (early-out threads do not deadlock), but every live thread that enters a conditional/loop containing a barrier must still hit it — pdf:msl-4.1#ch6 [symbols: threadgroup_barrier, simdgroup_barrier, thread_scope_threadgroup, thread_scope_simdgroup] [gate: Metal 4.1 for the scoped overload]
- `mem_flags` values: `mem_none` (execution barrier only), `mem_device`, `mem_threadgroup`, `mem_texture` (orders `read_write` texture access), `mem_threadgroup_imageblock`, `mem_object_data` (mesh pipeline payload) — pdf:msl-4.1#ch6 [symbols: mem_flags]
- SIMD-group permute/reduce functions exchange data without threadgroup memory or barriers. Gates: shuffles/broadcast macOS Metal 2 / iOS Metal 2.2; ballot/all/any/is_first macOS 2.1 / iOS 2.2; reductions and prefix sums (`simd_sum`, `simd_prefix_exclusive_sum`, `simd_max`, `simd_and`...) macOS 2.1 / iOS+iPadOS 2.3; `simd_shuffle_and_fill_up/down` (with optional `modulo` of 2,4,8,16,32) Metal 2.4 everywhere. Element type excludes bool, bfloat, long, ulong — pdf:msl-4.1#ch6 [symbols: simd_shuffle_down, simd_shuffle_xor, simd_ballot, simd_sum, simd_prefix_exclusive_sum, simd_shuffle_and_fill_down] [gate: see FST for per-GPU support]
- `simd_all(e)` checks only active threads; `simd_ballot(e).all()` also requires every lane to be active. `simd_vote` holds 64 bits; on narrower SIMD widths the top bits are undefined, so mask before testing — pdf:msl-4.1#ch6 [symbols: simd_vote, simd_all, simd_ballot, vote_t]
- `simd_is_helper_thread()` / `quad_is_helper_thread()` may fail to compile outside a fragment function (or something it calls) — pdf:msl-4.1#ch6
- Quad-groups: in fragment shaders lane 0..3 = upper-left, upper-right, lower-left, lower-right of the 2x2; in kernels quads just partition the SIMD-group. Helper threads exist only to supply derivatives, then go inactive. Quad `modulo` must be 2 or 4. iOS at Metal 2 only had `quad_broadcast`/`quad_shuffle*`/`quad_shuffle_xor`; reductions need iOS 2.3 — pdf:msl-4.1#ch6 [symbols: quad_shuffle, quad_broadcast, quad_sum, quad_ballot, quad_vote]
- Graphics functions (`<metal_graphics>`) are fragment-only. Helper-thread stores and atomics to buffers/textures have no effect — pdf:msl-4.1#ch6
- Derivatives (`dfdx`, `dfdy`, `fwidth`) are undefined in non-uniform control flow. Since Metal 2.3, `discard_fragment` no longer makes control flow non-uniform: the fragment keeps executing for derivative purposes but its outputs and any later buffer/texture writes are dropped; writes made *before* the discard persist — pdf:msl-4.1#ch6 [symbols: discard_fragment, dfdx, dfdy, fwidth] [gate: Metal 2.3]
- `get_num_samples()` / `get_sample_position(i)` let you shade per pixel but alpha-test per sample; positions honour custom ones set via `setSamplePositions:count:` on the render pass descriptor — pdf:msl-4.1#ch6 [symbols: get_num_samples, get_sample_position]
- Pull-model interpolation: `interpolant<T,P>` with `interpolate_at_center/centroid/offset/sample`; offset is in [0,1) on a 1/16-pixel grid; P fixes perspective-correctness. Metal 2.3 — pdf:msl-4.1#ch6 [symbols: interpolant, interpolate_at_offset, interpolate_at_sample] [gate: Metal 2.3]
- Texture access attributes gate calls: `sample`/`gather` need `access::sample`; `read` needs sample, read or read_write; `write` needs write or read_write. `sample_compare`/`gather_compare` are depth-texture only. Texel `offset` argument range is -8..+7 — pdf:msl-4.1#ch6
- LOD options: `level`, `bias`, `gradient2d/3d/cube`, `min_lod_clamp` (Metal 2.2). Streaming pattern the spec itself describes: allocate full mip chain, stream smallest mips first, raise `min_lod_clamp` coverage as larger mips land. Outside fragment shaders, implicit-LOD sample/gather use LOD 0 — pdf:msl-4.1#ch6 [symbols: min_lod_clamp, level, bias, gradient2d] [gate: Metal 2.2]
- `gather` returns xyzw counter-clockwise starting lower-left — pdf:msl-4.1#ch6 [symbols: gather]
- Out-of-bounds texture writes are dropped; OOB reads return 0 for format components and defaults (0, alpha 1) for missing components; for depth/stencil formats the missing-component default is undefined — pdf:msl-4.1#ch6
- Metal 4.1 texture reads: `read`, `sparse_read`, `block_read`, `sparse_block_read` accept a `sampler` to get clamp-to-edge on out-of-range coordinates (coords only, not face/array/lod), and an integer `offset` (-8..+7) for 2D, 2D array, 3D, 2D depth, 2D depth array; offset also applies to texture atomics. Coordinate type becomes `int` in the sampler overloads — pdf:msl-4.1#ch6 [symbols: read(sampler s, int coord, ...)] [gate: Metal 4.1]
- Multipixel reads (Metal 4.1): `block_read<W,H>` returns `block_color<T,W,H>` with `value<X,Y>()`; `sparse_block_read` returns `sparse_block_color` with per-pixel `resident<X,Y>()`. Only 2x1 or 1x2 blocks (1D and texture buffer: 2x1 only) — pdf:msl-4.1#ch6 [symbols: block_read, block_color, sparse_block_read, sparse_block_color] [gate: Metal 4.1]
- Texture atomics: Metal 3.1 on 1D/1D array/2D/2D array/3D/texture buffer, int/uint need `MTLPixelFormatR32Uint`/`R32Sint`, ulong (`atomic_min`/`atomic_max` only) needs `MTLPixelFormatRG32Uint`; Metal 4 adds cube and cube array. Check FST for GPU support — pdf:msl-4.1#ch6 [symbols: atomic_load, atomic_store, atomic_exchange, atomic_compare_exchange_weak, atomic_fetch_add, atomic_min, atomic_max] [gate: Metal 3.1; cube Metal 4]
- Sampling `ulong` textures is not supported — pdf:msl-4.1#ch6
- Sparse texture functions (`sparse_sample`, `sparse_read`, ...) return `sparse_color<T>` with `resident()` and `value()`. Sparse 1D textures and 1D arrays are not supported on Apple silicon — pdf:msl-4.1#ch6 [symbols: sparse_color, sparse_sample] [gate: macOS Metal 2.3, iOS 2.2]
- `calculate_unclamped_lod` / `calculate_clamped_lod` (fragment-only) report the LOD a fetch would use; fractional part is the mip blend weight. Use for streaming feedback — pdf:msl-4.1#ch6 [symbols: calculate_clamped_lod, calculate_unclamped_lod]
- Metal 4.1 sampler-read spellings take signed coords and an optional offset, e.g. 2D `read(sampler s, int2 coord, int2 offset = 0, uint lod = 0)`; cube forms take `(sampler, int2 coord, uint face, ...)` with no offset; MSAA forms `(sampler, int2 coord, uint sample)`; texture buffer `read(sampler s, int coord)`. Texture atomics on 2D/2D array/3D gain `(int2|int3 coord, offset, ...)` overloads. The spec labels several sparse sampler-read overloads "multi-pixel read"; they return a single `sparse_color`, so treat that label as a typo — pdf:msl-4.1#ch6 [symbols: texture2d::read, sparse_read, atomic_fetch_add] [gate: Metal 4.1]
- No `block_read` is listed for 3D textures (Table 6.22 covers 1D, 2D, cube, depth 2D/cube and their arrays, and texture buffers) — pdf:msl-4.1#ch6 [symbols: block_read] [gate: Metal 4.1]
- Cube face index: 0 +X, 1 -X, 2 +Y, 3 -Y, 4 +Z, 5 -Z (used by `read`/`write`/atomics on `texturecube`) — pdf:msl-4.1#ch6
- `sample_compare` returns a filtered blend of per-texel pass/fail (hardware PCF), `float` only, depth textures only. Old macOS (Metal 2.2 and earlier) limits on `sample_compare` LOD options, `bias`, `gradient*`, and non-zero write `lod` are lifted on Apple silicon from Metal 2.3 — pdf:msl-4.1#ch6 [symbols: sample_compare, gather_compare, depth2d]
