# Notes g02

## game-design.md

- Apple's text-size floor and default per platform (pt, default/minimum): iOS and iPadOS 17/11, macOS 13/10, tvOS 29/23, visionOS 17/12, watchOS 16/12. These apply to custom fonts too; thin custom weights need sizes above them. Test game text on every platform the game ships on — /design/human-interface-guidelines/typography
- World-space labels (names over characters or objects, status toasts) need a backing shape such as a shaded lozenge plus at least the minimum size; Apple's own wrong/right game example is exactly bare small text vs. text on a pill — /design/human-interface-guidelines/typography
- Avoid Ultralight, Thin, and Light weights for game UI; prefer Regular through Bold, especially at small sizes — /design/human-interface-guidelines/typography
- When the player raises text size, scale what matters, not everything: Apple's game example is character dialog over transient hit-damage numbers. Keep the hierarchy intact as sizes grow — /design/human-interface-guidelines/typography
- Do not bundle Apple's system fonts in the game; reach them through `Font.Design` (`.default` for SF, `.serif` for New York). Custom fonts must reimplement Dynamic Type and Bold Text themselves — /design/human-interface-guidelines/typography [symbols: Font.Design, Font.Design.default, Font.Design.serif, Font.leading(_:)]
- Unity games get Dynamic Type through Apple's Unity plug-ins (github.com/apple/unityplugins); where those do not fit, the game must offer its own text-size control — /design/human-interface-guidelines/typography
- Mac-first gotcha: macOS has no Dynamic Type at all (it exists on iOS, iPadOS, tvOS, visionOS, watchOS). A Mac game that wants scalable text needs an in-game text-size setting. Mac UI chrome matches system controls through `NSFont` role fonts — /design/human-interface-guidelines/typography [symbols: NSFont.controlContentFont(ofSize:), NSFont.labelFont(ofSize:), NSFont.menuFont(ofSize:), NSFont.messageFont(ofSize:), NSFont.titleBarFont(ofSize:), NSFont.systemFont(ofSize:), NSFont.boldSystemFont(ofSize:), NSFont.userFixedPitchFont(ofSize:)] [gate: macOS]
- Reference sizes: macOS Body is 13 pt on a 16 pt line, Headline 13 pt Bold; iOS default (Large) Body is 17/22, Large Title 34/41; iOS AX5 Body reaches 53/62; tvOS Body is 29/36 Medium. Emphasis comes from symbolic traits: SwiftUI `Text.bold()`, UIKit `UIFontDescriptor.SymbolicTraits.traitBold` — /design/human-interface-guidelines/typography [symbols: Text.bold(), UIFontDescriptor.SymbolicTraits.traitBold]
- Large-size layout: avoid truncation, let labels take more lines (`UILabel.numberOfLines`), switch to stacked layouts and fewer columns at accessibility sizes (`UIContentSizeCategory.isAccessibilityCategory`) — /design/human-interface-guidelines/typography [symbols: UILabel.numberOfLines, UIContentSizeCategory.isAccessibilityCategory] [gate: iOS, iPadOS]
- visionOS game text: prefer flat 2D text over extruded 3D text for anything that must be read; with no backing surface, use bold rather than drop shadows; billboard labels anchored to 3D objects so they rotate about the y-axis to face the wearer — /design/human-interface-guidelines/typography [gate: visionOS]

## audio-and-haptics.md

- AVAudioEngine is the default game audio stack on all Apple platforms: a graph of `AVAudioNode`s (player, mixer, effect units, source/sink, environment) feeding `AVAudioOutputNode`; it covers file and buffer playback, taps at any node, built-in and custom AU effects, stereo and 3D mixing, and MIDI/sampler playback — /documentation/AVFAudio/audio-engine [symbols: AVAudioEngine, AVAudioNode, AVAudioPlayerNode, AVAudioMixerNode, AVAudioMixing, AVAudioInputNode, AVAudioOutputNode, AVAudioIONode, AVAudioSequencer, AVAudioUnitSampler]
- 3D positional audio inside AVAudioEngine is `AVAudioEnvironmentNode` with per-source `AVAudio3DMixing` properties, distance attenuation (`AVAudioEnvironmentDistanceAttenuationParameters`) and reverb (`AVAudioEnvironmentReverbParameters`); listener pose is `AVAudio3DPoint` plus `AVAudio3DVectorOrientation` or `AVAudio3DAngularOrientation`. PHASE is the heavier alternative for geometry-aware games — /documentation/AVFAudio/audio-engine [symbols: AVAudioEnvironmentNode, AVAudio3DMixing, AVAudioEnvironmentDistanceAttenuationParameters, AVAudioEnvironmentReverbParameters, AVAudio3DPoint, AVAudio3DVectorOrientation, AVAudio3DAngularOrientation]
- New in the OS 27 SDK and surprising: realtime-safe twins of every engine render callback, typed with `CA_REALTIME_API` (clang `nonblocking`, so the compiler's function-effect analysis can flag locks and allocation inside them). `AVAudioSourceNodeRenderBlockRealtimeSafe` / `-initWithRealtimeSafeRenderBlock:` / `-initWithFormat:realtimeSafeRenderBlock:`, `AVAudioSinkNodeReceiverBlockRealtimeSafe` / `-initWithRealtimeSafeReceiverBlock:`, and `AVAudioIONodeInputBlockRealtimeSafe` / `-setRealtimeSafeManualRenderingInputPCMFormat:inputBlock:`. Headers say the realtime-safe initializer is the preferred one whenever the engine renders to a device or runs in realtime manual mode. All are marked `__SWIFT_UNAVAILABLE_MSG("Swift is not supported for use with audio realtime threads")` — Apple now states in the SDK that realtime render code belongs in C/ObjC/C++, not Swift — /documentation/AVFAudio/audio-engine (checked against MacOSX.sdk AVAudioSourceNode.h, AVAudioSinkNode.h, AVAudioIONode.h, CoreAudioTypes/CoreAudioBaseTypes.h) [symbols: AVAudioSourceNodeRenderBlockRealtimeSafe, AVAudioSinkNodeReceiverBlockRealtimeSafe, AVAudioIONodeInputBlockRealtimeSafe, CA_REALTIME_API] [gate: macOS 27, iOS 27, tvOS 27, visionOS 27, watchOS 27]
- Built-in effect nodes to reach for before writing DSP: `AVAudioUnitEQ`, `AVAudioUnitDistortion`, `AVAudioUnitDelay`, `AVAudioUnitReverb` (realtime `AVAudioUnitEffect` subclasses), and `AVAudioUnitTimePitch` / `AVAudioUnitVarispeed` (`AVAudioUnitTimeEffect`; time-pitch changes rate and pitch independently, varispeed couples them — the cheap engine-RPM/slow-motion choice). Third-party AUs are found with `AVAudioUnitComponentManager` — /documentation/AVFAudio/audio-units [symbols: AVAudioUnit, AVAudioUnitEQ, AVAudioUnitDistortion, AVAudioUnitDelay, AVAudioUnitReverb, AVAudioUnitEffect, AVAudioUnitTimePitch, AVAudioUnitVarispeed, AVAudioUnitTimeEffect, AVAudioUnitGenerator, AVAudioUnitMIDIInstrument, AVAudioUnitComponentManager]
- Procedural audio pattern Apple ships: DSP kernel in C++, an ObjC wrapper exposing an `AVAudioSourceNodeRenderBlock`, Swift only for the UI/engine wiring (`AVAudioSourceNode(renderBlock:)`, attach, connect to `mainMixerNode`). The render-thread rule Apple states: no allocation, no file I/O, no locks, and no Swift or Objective-C runtime calls while rendering — /documentation/AVFAudio/building-a-signal-generator [symbols: AVAudioSourceNode, AVAudioSourceNodeRenderBlock, AVAudioEngine.mainMixerNode, AUInternalRenderBlock] [gate: sample needs macOS 14 / iOS 17]
- Smooth every live parameter change (frequency, amplitude) with a ramp — the sample uses a 100 ms ramp — or the step causes audible zipper artifacts; band-limit synthesized saw/square/triangle (harmonics up to Nyquist) to avoid aliasing — /documentation/AVFAudio/building-a-signal-generator
- OS 27 Swift-concurrency surface for AVAudioEngine (sample is macOS 27 / Xcode 27; SDK marks the APIs macOS/iOS/tvOS/watchOS/visionOS 27): `AVReadOnlyAudioPCMBuffer` is a `Sendable` struct you can pass across actors; `AVAudioFile.read(frameCount:)` returns one; `AVAudioPlayerNode.scheduleBuffer(_:atTime:options:completionCallbackType:completionHandler:)` accepts one; `AVAudioNode.installAudioTap(onBus:bufferSize:format:tapProvider:)` (throws) hands a `@Sendable` tap a read-only buffer whose `channelData(_:)` returns a non-escapable `ChannelData` enum (`.int16/.int32/.float` of `Span`). Pattern: an actor loads and analyzes files off the main actor; the main actor owns the engine — /documentation/AVFAudio/building-an-audio-sequencer-to-arrange-and-play-clips (checked against MacOSX.sdk AVFAudio arm64e-apple-macos.swiftinterface) [symbols: AVReadOnlyAudioPCMBuffer, AVReadOnlyAudioPCMBuffer.ChannelData, AVAudioFile.read(frameCount:), AVAudioNode.installAudioTap(onBus:bufferSize:format:tapProvider:), AVAudioPlayerNode.scheduleBuffer(_:atTime:options:completionCallbackType:completionHandler:)] [gate: OS 27]
- OS 27 deprecates the non-throwing engine calls: `connect(_:to:format:)` and the bus variant are replaced by throwing `connectNode(_:to:format:)` / `connectNode(_:to:fromBus:toBus:format:)`; `AVAudioPlayerNode.play()` / `play(at:)` by throwing `playAudio()` / `playAudio(at:)`. Swift raw-unit properties are deprecated in favor of scoped borrows: `AVAudioNode.auAudioUnit` → `withAUAudioUnit(_:)`, `AVAudioUnit.audioUnit` and `AVAudioIONode.audioUnit` → `withAudioUnit(_:)`, `AVAudioEngine.musicSequence` → `withMusicSequence(_:)` — /documentation/AVFAudio/building-an-audio-sequencer-to-arrange-and-play-clips (headers: AVAudioEngine.h, AVAudioPlayerNode.h; swiftinterface) [symbols: AVAudioEngine.connectNode(_:to:format:), AVAudioPlayerNode.playAudio(), AVAudioPlayerNode.playAudio(at:), AVAudioNode.withAUAudioUnit(_:), AVAudioUnit.withAudioUnit(_:), AVAudioIONode.withAudioUnit(_:), AVAudioEngine.withMusicSequence(_:)] [gate: OS 27 deprecation; older targets keep connect/play]
- Gotcha for adaptive/layered game music: do not use `AVAudioPlayerNode`'s `.loops` option for long-running synchronized loops — it accumulates floating-point drift. Schedule one iteration at a time at an explicit `AVAudioTime(hostTime:)` and reschedule the next at the previous end host time (sample polls every 50 ms and reschedules within 100 ms of the boundary) — /documentation/AVFAudio/building-an-audio-sequencer-to-arrange-and-play-clips [symbols: AVAudioPlayerNode.scheduleBuffer, AVAudioTime(hostTime:), AVAudioTime.hostTime(forSeconds:)]
- Quantize stingers/music transitions to a bar grid: compute the next bar boundary from transport start and tempo and start at that host time; a ~2% snap tolerance lets near-boundary launches start now. Per-track `AVAudioMixerNode` into the main mixer lets clips be swapped without disconnecting what is playing; graph is PlayerNode > `AVAudioUnitVarispeed` (rate = mainTempo/clipBPM) > track mixer > main mixer — /documentation/AVFAudio/building-an-audio-sequencer-to-arrange-and-play-clips [symbols: AVAudioMixerNode, AVAudioUnitVarispeed.rate, AVAudioEngine.disconnectNodeOutput(_:), AVAudioEngine.detach(_:)]
- Start a node at volume 0 and raise it to avoid clicks from a non-zero-crossing start; the engine smooths volume changes over one render buffer, about 5 ms — /documentation/AVFAudio/building-an-audio-sequencer-to-arrange-and-play-clips [symbols: AVAudioPlayerNode.volume]
- Audio-thread to UI handoff without locks or Task hops: the tap writes a peak into a `ManagedAtomic<UInt32>` (Float bit pattern, relaxed ordering, single writer), and a main-actor Task polls it on a UI interval. Peak detection uses `vDSP_maxmgv`. BPM detection uses the new MusicUnderstanding framework (exists in the macOS 27 SDK) — /documentation/AVFAudio/building-an-audio-sequencer-to-arrange-and-play-clips [symbols: ManagedAtomic (swift-atomics), vDSP_maxmgv, MusicUnderstanding]
- Mac-first split: `AVAudioSession` does not exist on macOS (header: `API_UNAVAILABLE(macos)`); it is the iOS/iPadOS/tvOS/watchOS/visionOS layer. A Mac game uses AVAudioEngine directly with no session setup; an iOS/iPadOS build must configure a session category before audio starts — /documentation/AVFAudio/capturing-stereo-audio-from-built-in-microphones (SDK AVAudioSession.h) [symbols: AVAudioSession] [gate: iOS, iPadOS, tvOS, watchOS, visionOS; not macOS]
- iOS voice-chat or mic-using game: category `.playAndRecord` routes output to the earpiece receiver by default; add `.defaultToSpeaker` for the loudspeaker. Apple's sample still passes `.allowBluetooth`, which the current SDK deprecates in favor of `.allowBluetoothHFP` (same bit, 0x4); `.allowBluetoothA2DP` gives high-quality Bluetooth output while recording. None of these options exist on macOS — /documentation/AVFAudio/capturing-stereo-audio-from-built-in-microphones (SDK AVAudioSessionTypes.h) [symbols: AVAudioSession.Category.playAndRecord, AVAudioSession.CategoryOptions.defaultToSpeaker, AVAudioSession.CategoryOptions.allowBluetoothHFP, AVAudioSession.CategoryOptions.allowBluetoothA2DP] [gate: iOS, iPadOS]
- Stereo capture from built-in mics (iOS 14+ on supported devices): pick the built-in mic port (`.builtInMic`) via `setPreferredInput`, choose a data source whose `supportedPolarPatterns` contains `.stereo`, call `setPreferredPolarPattern(.stereo)` then `setPreferredDataSource`, and set `setPreferredInputOrientation` to the UI orientation; do not change orientation mid-recording — /documentation/AVFAudio/capturing-stereo-audio-from-built-in-microphones [symbols: AVAudioSession.setPreferredInput(_:), AVAudioSessionDataSourceDescription.supportedPolarPatterns, AVAudioSessionDataSourceDescription.setPreferredPolarPattern(_:), AVAudioSessionPortDescription.setPreferredDataSource(_:), AVAudioSession.setPreferredInputOrientation(_:), AVAudioSession.PolarPattern.stereo] [gate: iOS 14, iPadOS 14]
- Apple's Audio Unit Extension App template fixes the language split for audio code: Swift/SwiftUI for parameters and UI, C++ (`*DSPKernel.hpp`) for the realtime `process` path, Objective-C as the bridge. Use it as the model for any custom game DSP, even in-process. Kinds offered: Instrument, Generator, Effect, Music Effect, MIDI Processor, Speech Synthesis — /documentation/AVFAudio/creating-an-audio-unit-extension [symbols: AUParameterAddress, AUValue, AUAudioUnit.parameterTree]
- A game does not need an AUv3 extension for its own DSP; AUv3 is the format for plug-ins other hosts load. If a game hosts AUv3s: they run out-of-process over IPC by default (crash isolation, but per-render-cycle overhead). In-process loading is macOS-only, needs the host to pass `.loadInProcess` and the AU's code to live in a separate framework named by the `AudioComponentBundle` key in the extension's Info.plist — /documentation/AVFAudio/creating-custom-audio-effects [symbols: AUAudioUnit, AUAudioUnitFactory, AudioComponentInstantiationOptions.loadInProcess] [gate: in-process macOS only]
- Parameter changes from UI or game logic reach DSP through `AUParameterTree` with `.flag_CanRamp` for smooth ramping; observer callbacks arrive on an arbitrary queue, so hop to main for UI — /documentation/AVFAudio/creating-custom-audio-effects [symbols: AUParameterTree.createParameter(withIdentifier:name:address:min:max:unit:unitName:flags:valueStrings:dependentParameters:), AUParameterNode.implementorValueObserver, AUParameterNode.token(byAddingParameterObserver:)]
- In-game voice chat echo cancellation is AVAudioEngine voice processing: `inputNode.setVoiceProcessingEnabled(true)` (turns it on for both I/O nodes; engine must be stopped; device rendering only, not manual mode; the input node's output format must equal the output node's input format). Then `isVoiceProcessingInputMuted` for push-to-talk mute, `setMutedSpeechActivityEventListener(_:)` to warn "you are muted", and `voiceProcessingOtherAudioDuckingConfiguration` to set how hard game audio ducks under voice. Available macOS 10.15+/iOS 13+ (ducking config macOS 14/iOS 17), so the Mac build gets it too. The page itself is a stub pointing at WWDC19 session 510; details come from the SDK header — /documentation/AVFAudio/using-voice-processing (SDK AVAudioIONode.h) [symbols: AVAudioIONode.setVoiceProcessingEnabled(_:), AVAudioInputNode.isVoiceProcessingInputMuted, AVAudioInputNode.isVoiceProcessingAGCEnabled, AVAudioInputNode.isVoiceProcessingBypassed, AVAudioInputNode.setMutedSpeechActivityEventListener(_:), AVAudioInputNode.voiceProcessingOtherAudioDuckingConfiguration] [gate: macOS 10.15, iOS 13; ducking config macOS 14, iOS 17; not tvOS/watchOS for ducking]
- Interruption handling changes in OS 27 (iOS/tvOS/visionOS/watchOS 27): the begin/end `AVAudioSession.interruptionNotification`, `InterruptionType`, `InterruptionOptions`, and the type/option/reason keys are deprecated. New code observes three lifecycle notifications posted on the main queue: `didBecomeActiveNotification`, `didBecomeInactiveNotification` (userInfo `deactivationContextKey` → `AVAudioSession.DeactivationContext` with `source` `.app`/`.system` and, for system, `interruptionContext.reason`), and `resumptionRecommendationNotification` (userInfo `resumptionContextKey` → `ResumptionContext.recommendation` `.shouldResume`/`.shouldNotResume`). Why it matters for games: the old model could leave the game stuck "interrupted" when the end event never arrived; the new resumption signal does not depend on the interrupting app. Typed alternative: `NotificationCenter.addObserver(of:for: .didBecomeInactive)` giving `DidBecomeInactiveMessage.deactivationResult` (`.appDeactivated` / `.systemInterruption(context)`). Keep the legacy observer when deploying to 26 or earlier. macOS has none of this (no AVAudioSession) — /documentation/AVFAudio/handling-audio-interruptions (checked iPhoneOS.sdk AVAudioSession.h, AVAudioSessionTypes.h) [symbols: AVAudioSession.didBecomeActiveNotification, AVAudioSession.didBecomeInactiveNotification, AVAudioSession.resumptionRecommendationNotification, AVAudioSession.deactivationContextKey, AVAudioSession.resumptionContextKey, AVAudioSession.DeactivationContext, AVAudioSession.ResumptionContext, AVAudioSession.ResumptionRecommendation, AVAudioSession.DidBecomeInactiveMessage, AVAudioSession.DeactivationResult, AVAudioSession.interruptionNotification] [gate: iOS 27, tvOS 27, visionOS 27, watchOS 27; unavailable macOS]
- Game response to a system deactivation: pause the game and the sim (not just audio), show a pause menu, and only reactivate (`activate(options:)`, now iOS 27 on iOS) and resume when the recommendation says so — a phone call mid-match must not leave audio silently dead. `setPrefersNoInterruptionsFromSystemAlerts(_:)` asks the system not to interrupt for alerts such as incoming-call ringtones; `.overrideMutedMicrophoneInterruption` keeps a play-and-record session alive when an iPad Smart Folio hardware-mutes the mic (input then reads zeros) — /documentation/AVFAudio/handling-audio-interruptions [symbols: AVAudioSession.setPrefersNoInterruptionsFromSystemAlerts(_:), AVAudioSession.CategoryOptions.overrideMutedMicrophoneInterruption, AVAudioSession.activate(options:)] [gate: iOS, iPadOS]
- Header inconsistency to watch: the deprecation message on `AVAudioSessionInterruptionReasonKey` points at `interruptionDetails.reason`, but the declared property is `DeactivationContext.interruptionContext` — use the declared name — /documentation/AVFAudio/handling-audio-interruptions (iPhoneOS.sdk AVAudioSessionTypes.h line ~337 vs AVAudioSession.h)
- Faster-than-realtime bakes (pre-rendering reverb tails, analysis for audio-reactive visuals, deterministic audio tests in CI) use `enableManualRenderingMode(.offline, format:maximumFrameCount:)` before `start()`, then loop `renderOffline(_:to:)` into an `AVAudioPCMBuffer` sized by `manualRenderingFormat`/`manualRenderingMaximumFrameCount` (sample uses 4096) until `manualRenderingSampleTime` reaches the source length. Status `.cannotDoInCurrentContext` means retry; `.insufficientDataFromInputNode` applies only when the input node is a source. The `.realtime` manual mode is the one where the realtime-safe callback variants matter — /documentation/AVFAudio/performing-offline-audio-processing [symbols: AVAudioEngine.enableManualRenderingMode(_:format:maximumFrameCount:), AVAudioEngine.renderOffline(_:to:), AVAudioEngine.manualRenderingFormat, AVAudioEngine.manualRenderingMaximumFrameCount, AVAudioEngine.manualRenderingSampleTime, AVAudioEngineManualRenderingStatus, AVAudioEngineManualRenderingMode.offline]
- Do not set the `.longFormAudio` route-sharing policy for a game: it tells the system the app is a music/podcast-style long-listening source (gains AirPlay 2 buffering, displaces Apple Music-style playback). Games are not long-form. `AVSampleBufferAudioRenderer` + `AVSampleBufferRenderSynchronizer` is the path for streaming your own decoded `CMSampleBuffer`s (e.g. a custom codec for cutscene or radio audio) with `requestMediaDataWhenReady(on:using:)` pull and boundary time observers for item transitions — /documentation/AVFAudio/playing-custom-audio-with-your-own-player [symbols: AVAudioSession.RouteSharingPolicy.longFormAudio, AVSampleBufferAudioRenderer, AVSampleBufferRenderSynchronizer, AVSampleBufferAudioRenderer.requestMediaDataWhenReady(on:using:)] [gate: iOS 17 sample]
- Route changes on iOS/iPadOS: observe `AVAudioSession.routeChangeNotification`; reason `.newDeviceAvailable` → inspect `currentRoute.outputs`, `.oldDeviceUnavailable` → inspect the previous route under `AVAudioSessionRouteChangePreviousRouteKey`; headphones are `portType == .headphones`. Apple's privacy rule: when headphones disconnect, playback should not jump to the speaker unannounced — media pauses; for a game, pausing the game (or at least its audio) on headphone removal follows the same expectation — /documentation/AVFAudio/responding-to-audio-route-changes [symbols: AVAudioSession.routeChangeNotification, AVAudioSession.RouteChangeReason.newDeviceAvailable, AVAudioSession.RouteChangeReason.oldDeviceUnavailable, AVAudioSessionRouteChangeReasonKey, AVAudioSessionRouteChangePreviousRouteKey, AVAudioSession.currentRoute, AVAudioSessionPortDescription.portType, AVAudioSession.Port.headphones] [gate: iOS, iPadOS, tvOS, visionOS; no AVAudioSession on macOS]
- Cross-platform, including the Mac: when the output or input hardware's sample rate or channel count changes (plugging headphones, switching output device), the engine stops itself and posts `AVAudioEngineConfigurationChange`; nodes stay attached, but the game must restart the engine and rebuild input-chain connections whose format must follow the hardware rate. Do not deallocate the engine inside the handler — it runs on an internal queue and can deadlock — /documentation/AVFAudio/responding-to-audio-route-changes (SDK AVAudioEngine.h, not the page) [symbols: AVAudioEngineConfigurationChangeNotification, AVAudioEngine.start()] [gate: macOS 10.10, iOS 8]
- Multi-device routing (e.g. couch co-op with per-player headsets, or a streamer mix): in a multiroute session Core Audio flattens every active device's channels into one global index space in port order. On the engine's output node, set `kAudioOutputUnitProperty_ChannelMap` (output scope, element 0) to an `[Int32]` sized to the total output channel count, each slot naming a source channel or `-1` for silence; compute offsets from `currentRoute.outputs[].channels` rather than hard-coding. Input maps are sized to the recording channel count (input scope, element 1) and pick hardware channels; pass the matching client format to the tap. Alternatives: `kAudioQueueProperty_ChannelAssignments` with `AudioQueueChannelAssignment` (device UID, 1-based channel), or `AVAudioPlayer.channelAssignments` / `AVAudioRecorder.channelAssignments` with `AVAudioSessionChannelDescription` — /documentation/AVFAudio/routing-audio-to-specific-devices-in-multidevice-sessions [symbols: kAudioOutputUnitProperty_ChannelMap, AudioUnitSetProperty, AVAudioSession.maximumOutputNumberOfChannels, AVAudioSessionPortDescription.channels, kAudioQueueProperty_ChannelAssignments, AudioQueueChannelAssignment, AVAudioPlayer.channelAssignments, AVAudioRecorder.channelAssignments, AVAudioSessionChannelDescription] [gate: AVAudioSession multiroute is iOS-family]
- The page's sample reads `engine.outputNode.audioUnit` directly; in the OS 27 SDK that Swift property is deprecated in favor of `withAudioUnit(_:)` — /documentation/AVFAudio/routing-audio-to-specific-devices-in-multidevice-sessions (swiftinterface) [symbols: AVAudioIONode.audioUnit, AVAudioIONode.withAudioUnit(_:)] [gate: OS 27 deprecation]
- On-device text-to-speech for accessibility narration of menus or placeholder dialog: `AVSpeechUtterance` (rate, `pitchMultiplier`, `postUtteranceDelay`, volume, `voice` from `AVSpeechSynthesisVoice(language:)`) spoken by an `AVSpeechSynthesizer`, with its delegate for progress events. — /documentation/AVFAudio/speech-synthesis [symbols: AVSpeechUtterance, AVSpeechSynthesisVoice, AVSpeechSynthesizer, AVSpeechSynthesizer.delegate]
- Hand-rolled filtering inside your own render callback (e.g. occlusion low-pass per voice): vDSP cascaded biquads. Build `vDSP_biquad_CreateSetup` once off the audio thread (it allocates; coefficients are Double, five per section `[b0, b1, b2, a1, a2]` with a0 normalized to 1 per vDSP's transfer function); retune live with `vDSP_biquad_SetCoefficientsSingle`; process with `vDSP_biquad`, keeping a per-voice `delay` state array passed back each call. If an engine-graph EQ suffices, `AVAudioUnitEQ` avoids all of this — /documentation/Accelerate/applying-biquadratic-filters-to-a-music-loop [symbols: vDSP_biquad_CreateSetup, vDSP_biquad_SetCoefficientsSingle, vDSP_biquad, vDSP_biquad_DestroySetup] [gate: SetCoefficientsSingle sample is macOS 13]
- vDSP's Swift overlay comes in two shapes for every op: forms that return a new `[Float]`/`[Double]` (each call allocates an array) and `result: inout` forms that write into caller storage. Only the `result:` forms (or the C `vDSP_*` functions) belong anywhere near a render callback or per-frame mixing code; fused forms such as `vDSP.add(multiplication:_:result:)` cut passes for gain-and-sum mixing — /documentation/Accelerate/arithmetic-operations [symbols: vDSP.add(_:_:result:), vDSP.multiply(_:_:result:), vDSP.add(multiplication:_:result:), vDSP.addSubtract(_:_:addResult:subtractResult:)]
- Swift-side alternative to the C biquad setup: the `vDSP.Biquad` struct wraps single- and multichannel cascaded biquads in single or double precision — convenient for offline or control-rate work; for the realtime path the C `vDSP_biquad*` calls from C/C++ match Apple's no-Swift-on-the-audio-thread guidance — /documentation/Accelerate/biquadratic-iir-filters [symbols: vDSP.Biquad]

## assets.md

- Offline texture bake on the CPU (Accelerate vImage): when quantizing float or 16-bit art down to 8-bit, vImage conversions take a dither flag. For build pipelines prefer `kvImageConvert_DitherOrderedReproducible` (precomputed blue noise, same output every run, so content hashes stay stable) over `kvImageConvert_DitherOrdered` (randomized); `kvImageConvert_OrderedGaussianBlue` / `kvImageConvert_OrderedUniformBlue` pick the noise distribution; Floyd-Steinberg and Atkinson are error-diffusion options — /documentation/Accelerate/1533233-dithering-methods [symbols: kvImageConvert_DitherNone, kvImageConvert_DitherOrdered, kvImageConvert_DitherOrderedReproducible, kvImageConvert_DitherFloydSteinberg, kvImageConvert_DitherAtkinson, kvImageConvert_OrderedGaussianBlue, kvImageConvert_OrderedUniformBlue]
- vImage flag rules for CPU-side texture tools: flags are summed; exactly one edge mode is required by convolutions (`kvImageCopyInPlace`, `kvImageBackgroundColorFill`, `kvImageEdgeExtend` are mutually exclusive; `kvImageTruncateKernel` is the fourth edge option); pass `kvImageNoFlags` otherwise. Useful ones: `kvImageHighQualityResampling` for mip/downscale, `kvImageHDRContent` for HDR-aware handling, `kvImageDoNotClamp` to keep out-of-range floats, `kvImageUseFP16Accumulator` to trade precision for speed on half-float work, `kvImageGetTempBufferSize` + `kvImageNoAllocate` to pre-size scratch and keep vImage from allocating. Swift spelling is `vImage.Options` — /documentation/Accelerate/1578976-processing-flags [symbols: vImage.Options, kvImageNoFlags, kvImageHighQualityResampling, kvImageHDRContent, kvImageDoNotClamp, kvImageUseFP16Accumulator, kvImageGetTempBufferSize, kvImageNoAllocate, kvImageEdgeExtend, kvImageTruncateKernel]
- CPU image-tool pattern Apple recommends in vImage samples: split interleaved RGB(A) into planar buffers and run the per-channel operation concurrently in a `withTaskGroup`, one task per plane (here morphology dilation via `vImage.PixelBuffer.applyMorphology(operation:destination:)` with a `vImage.StructuringElement`). Fine for offline bakes or editor tools; a runtime bokeh/depth-of-field effect belongs on the GPU — /documentation/Accelerate/adding-a-bokeh-effect-to-images [symbols: vImage.PixelBuffer, vImage.PixelBuffer.applyMorphology(operation:destination:), vImage.StructuringElement] [gate: macOS 13.3 sample]
- CPU mip generation and resizing of color textures: Apple's guidance is that vImage convolution and scaling give correct results only on linear data, so convert sRGB to linear first, run the operation, then re-encode. vImage ships `vImage.Gamma.sRGBReverseHalfPrecision` (sRGB→linear) and `.sRGBForwardHalfPrecision` (linear→sRGB) for `vImage.PixelBuffer.applyGamma(_:intermediateBuffer:destination:)`.
