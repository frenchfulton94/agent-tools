- Render-thread rule stated by Apple even in AUGraph docs: graph calls made from the render callback return `kAUGraphErr_CannotDoInCurrentContext` instead of blocking when another thread holds the graph lock; the fix is to retry on a later render cycle or hand the call to another thread, never to spin or sleep the render thread. A graph can hold only one output unit (`kAUGraphErr_OutputNodeErr`). — /documentation/AudioToolbox/1537630-audio-graph-errors [symbols: kAUGraphErr_CannotDoInCurrentContext, kAUGraphErr_OutputNodeErr]
- Gapless looping of compressed music (AAC and similar) depends on the file's packet table: it records priming frames, remainder frames and valid frames, and the three must sum to the total frames in all packets or a set fails with `paramErr`. A loop that clicks or gaps is usually a decoder priming offset that was not trimmed. — /documentation/AudioToolbox/1576499-audio-file-properties [symbols: kAudioFilePropertyPacketTableInfo, AudioFilePacketTableInfo]
- AIFF and WAVE carry 32-bit size limits (`kAudioFileDoesNotAllow64BitDataSizeError`); CAF, RF64, BW64 and Wave64 exist for larger files. CAF is Apple's own container and is the safe default for shipped game audio that is not streamed from a web source. — /documentation/AudioToolbox/1576500-audio-file-errors; /documentation/AudioToolbox/1576497-audio-file-types [symbols: kAudioFileDoesNotAllow64BitDataSizeError, kAudioFileCAFType, kAudioFileRF64Type, kAudioFileBW64Type, kAudioFileWave64Type, kAudioFileFLACType]
- Apple mixer AUs, by subtype: the multichannel mixer takes any bus count and channel count per input, but on iOS its output bus is fixed at two channels (macOS: any); the stereo mixer outputs stereo only; the legacy 3D mixer pans mono buses in 3D, passes stereo through, renders 4-channel ambisonic input, and outputs 2/4/5/6/7/8 channels; the spatial mixer is the modern subtype. The type list also now carries a head-tracking binaural renderer type. AVAudioEngine's mixer and environment nodes wrap these, so a game reaches for the raw subtypes only in a hand-built AU graph. — /documentation/AudioToolbox/1584146-audio-unit-mixer-subtypes; /documentation/AudioToolbox/1584150-mixer_audio_unit_subtypes; /documentation/AudioToolbox/1584142-audio_unit_types [symbols: kAudioUnitSubType_MultiChannelMixer, kAudioUnitSubType_StereoMixer, kAudioUnitSubType_3DMixer, kAudioUnitSubType_SpatialMixer, kAudioUnitSubType_MatrixMixer, kAudioUnitType_HeadTrackingBinauralRenderer]

- Category choice for a game, mapped from the C API's category docs onto AVAudioSession: ambient mixes with the player's own music and is right when the game is playable muted; solo-ambient is the default and silences other audio; playback is for audio central to the app; play-and-record for voice chat (output defaults to the receiver unless overridden to the speaker). - Audio workgroups, three cases (all C/ObjC/C++; the header marks them unavailable from Swift because Swift's runtime is not safe on real-time threads — `AUAudioUnit.osWorkgroup` carries `__SWIFT_UNAVAILABLE_MSG("Swift is not supported for use with audio realtime threads")`): (1) helper threads that render to the same I/O-cycle deadline join the device's workgroup, read from the I/O unit; (2) an AU plug-in's own render helpers join whatever workgroup its render-context observer receives before each render, and drop all when it is null (non-real-time render); (3) real-time threads on their own cadence get a new interval from `AudioWorkIntervalCreate`, whose primary thread brackets each cycle with interval start/finish and a deadline later than the start. Join errors: `EALREADY` means already in a workgroup that cannot nest, `EINVAL` means cancelled. Leave before the thread exits. A device change on the I/O unit changes its workgroup, so re-fetch. — /documentation/AudioToolbox/adding-parallel-real-time-threads-to-audio-workgroups; /documentation/AudioToolbox/adding-audio-unit-auxiliary-real-time-threads-to-audio-workgroups; /documentation/AudioToolbox/adding-asynchronous-real-time-threads-to-audio-workgroups; SDK AudioToolbox/AudioWorkInterval.h, AUAudioUnit.h [symbols: kAudioOutputUnitProperty_OSWorkgroup, AUAudioUnit.osWorkgroup, AURenderContextObserver, AudioUnitRenderContext, kAudioUnitProperty_RenderContextObserver, AudioWorkIntervalCreate, os_workgroup_join, os_workgroup_leave, os_workgroup_join_token_s, os_workgroup_interval_start, os_workgroup_interval_finish, OS_CLOCK_MACH_ABSOLUTE_TIME, kAudioDevicePropertyIOThreadOSWorkgroup] [gate: macOS 11 / iOS 14 / tvOS 14]

- Overloads come from non-real-time work in the render path: taking a lock, allocating, or work longer than the cycle. To confirm a fix, look for an Audio Client track and an Audio Server track with no warnings left. When several real-time threads share one deadline they belong in an audio workgroup. — /documentation/AudioToolbox/analyzing-audio-performance-with-instruments

- Cost of an AU in a game's AVAudioEngine graph depends on where it runs. Apple's built-in AUv2 effects (and, on macOS, third-party AUv2) always run inside the host process. - Who needs audio workgroups: nobody whose only real-time thread is the one the audio framework supplies. The system already joins the app's render thread to the device workgroup, and the audio server's I/O thread is that group's primary. Only real-time threads can join; a normal-priority thread cannot. Adopt the API only when the game spawns its own real-time DSP or synth threads. The render-context observer type is declared `__attribute__((nonblocking))`. — /documentation/AudioToolbox/understanding-audio-workgroups; /documentation/AudioToolbox/workgroup-management [symbols: AURenderContextObserver, kAudioUnitProperty_RenderContextObserver, kAudioDevicePropertyIOThreadOSWorkgroup, AudioWorkIntervalCreate] [gate: macOS 11 / iOS 14 / watchOS 7 / tvOS 14]
- AHAP files are JSON haptic-and-audio patterns that live in the bundle like any other asset. `CHHapticEngine.playPattern(from:)` is fire and forget: the pattern plays to its end, cannot be stopped, and layers over anything already playing. To avoid layering, wait out the first pattern's duration. Haptics do not mix like audio waveforms: two events of the same type at the same moment are hard to tell apart, so layer different kinds, such as a continuous rumble under transient taps. For pause, resume, seek or looping, use `makeAdvancedPlayer(with:)` with `loopEnabled`. Create the engine with `CHHapticEngine(audioSession:)` so audio-based haptics follow the session's behaviour. The Simulator has no haptics; these samples need iPhone 8 or later on iOS 13+. — /documentation/CoreHaptics/playing-a-custom-haptic-pattern-from-a-file [symbols: CHHapticEngine(audioSession:), CHHapticEngine.playPattern(from:), CHHapticEngine.makeAdvancedPlayer(with:), CHHapticAdvancedPatternPlayer.loopEnabled, CHHapticEngine.start()] [gate: iOS 13]
- Pattern players are cheap. Create one right before playing unless you need latency-free feedback (dial ticks, for example); in that case prepare it ahead of time. Calling `start(atTime:)` on a player that is already playing restarts it from the beginning. After `start`, nothing but the engine needs to stay alive; retain the engine. Outside rapid sequences, bracket playback: start the engine, play, and stop it from `notifyWhenPlayersFinished` by returning `.stopEngine`, which saves power. The engine can also stop itself in auto-shutdown mode, so be ready for that. Haptic dictionaries use `CHHapticPattern.Key`, and `CHHapticTimeImmediate` means now. — /documentation/CoreHaptics/playing-a-single-tap-haptic-pattern [symbols: CHHapticPattern(dictionary:), CHHapticPattern.Key, CHHapticEvent.EventType.hapticTransient, CHHapticTimeImmediate, CHHapticEngine.makePlayer(with:), CHHapticPatternPlayer.start(atTime:), CHHapticEngine.notifyWhenPlayersFinished(finishedHandler:), CHHapticEngine.FinishedAction.stopEngine]
- Collision haptics for a game: on each contact, normalize impact speed to 0–1 against a tuned maximum, map it to transient intensity and sharpness, and build a fresh player per hit. The same pattern can also carry an `.audioContinuous` event whose volume, pitch, decay time and sustained flag follow the impact, so the engine synthesizes a matching sound along with the haptic. The sample uses UIKit Dynamics with Core Motion gravity and notes that SpriteKit or any 2D physics engine works the same way. — /documentation/CoreHaptics/playing-collision-based-haptic-patterns [symbols: CHHapticPattern(events:parameters:), CHHapticEvent(eventType:parameters:relativeTime:), CHHapticEvent.EventType.audioContinuous, CHHapticEvent.ParameterID.audioPitch, CHHapticEvent.ParameterID.audioVolume, CHHapticEvent.ParameterID.decayTime, CHHapticEvent.ParameterID.sustained, CMMotionManager.startDeviceMotionUpdates(to:withHandler:)] [gate: iOS 13]

- For an asset-pipeline tool that encodes or decodes game audio with AudioConverter (Apple's C++ sample, macOS 12+ / Xcode 13.3+): one converter cannot transcode from one compressed format to another, so the path is compressed to PCM to compressed in two converters. - Background Assets has three modes, in order of how much the system does for you: (a) Apple-hosted managed asset packs (uploaded to App Store Connect and versioned like builds); (b) self-hosted managed asset packs, where the system still schedules downloads, applies updates and handles compression; (c) unmanaged downloads through `BADownloadManager` and your own downloader extension. Each managed pack's manifest sets a download policy: essential (fetched before first launch), prefetch (fetched without blocking launch), or on-demand. Apple's own example is a game: tutorial assets before launch, level packs and models later. A local mock server ships with Xcode for testing. Apple restricts the framework to downloading the app's own extra assets, with no identifying the user or device and no advertising or ad measurement. — /documentation/BackgroundAssets [symbols: AssetPack, AssetPackManager, AssetPackManifest, ManagedDownloaderExtension, BAAssetPackManager, BAManagedDownloaderExtension, BADownloadManager, BADownloaderExtension, BAURLDownload, BAAppGroupID, BAHasManagedAssetPacks, BAUsesAppleHosting, BAManifestURL, BAInitialDownloadRestrictions, BAEssentialMaxInstallSize, BAMaxInstallSize] [gate: framework iOS/iPadOS/Mac Catalyst 16, macOS 13, tvOS 18.4, visionOS 2.4 native (1.0 for compatible iPad/iPhone apps)]
- Unmanaged (self-hosted) Background Assets lifecycle. The app is installed or updated. The system blocks launch and downloads your manifest from `BAManifestURL`, reporting that progress to the App Store. It then wakes your extension with the manifest's path on disk. The extension parses your own manifest format and returns download requests. The system pauses or kills the extension, runs the downloads, notifies the extension, and only then lets the app launch. Periodic background requests follow the same flow on a schedule the system picks, influenced by usage, Low Power Mode and Background App Refresh. — /documentation/BackgroundAssets/configuring-an-unmanaged-background-assets-project [symbols: BAManifestURL, BADownloaderExtension, BADownloadManager]

- Managed asset packs, from Apple's page. Apple-hosted packs can hold up to 200 GB of compressed assets and are App Store-only, on every platform except watchOS; per-pack limits are in App Store Connect Help. A pack may carry textures, sounds and GPU shaders, and also CPU and GPU executables, though not macOS executables. Policies: `essential` downloads as part of install and counts toward the install progress shown in the App Store, TestFlight and the Home Screen or Home View; `prefetch` starts during install and keeps going in the background afterwards; `onDemand` downloads only when your code asks for it. Essential and prefetch packs choose `installationEventTypes` from `firstInstallation` and `subsequentUpdate`. A tutorial pack set to essential with firstInstallation only is not downloaded again on later updates. — /documentation/BackgroundAssets/creating-managed-asset-packs [symbols: AssetPack, AssetPackManifest]
- Packaging: `xcrun ba-package template -o Manifest.json` generates a manifest template. The manifest takes `assetPackID`, `downloadPolicy`, `fileSelectors` (`file` or `directory` entries, recursive) and `platforms`. `xcrun ba-package Manifest.json -o Tutorial.aar` builds the archive. Manifest paths are relative to the directory the tool runs in. Upload Apple-hosted packs on their own, separate from app builds, with Transporter, `altool`, iTMSTransporter or the App Store Connect API. They go to review before external TestFlight testing or App Store release. — /documentation/BackgroundAssets/creating-managed-asset-packs [symbols: ba-package]
- Apple-hosted setup: create a Background Download target of type "Apple-Hosted, Managed", give the app and extension a shared app group, and put three Info.plist keys on the app: `BAAppGroupID`, `BAHasManagedAssetPacks` = YES and `BAUsesAppleHosting` = YES. Leave out every other BA key; the unmanaged-mode keys must not be present. Apple names Metal shader libraries, ML models, textures and videos as hostable content, and packs update independently of app builds. The template's `shouldDownload(_:)` is optional: delete it unless the game needs runtime filtering, for example device-compatibility checks. — /documentation/BackgroundAssets/downloading-apple-hosted-asset-packs [symbols: BAAppGroupID, BAHasManagedAssetPacks, BAUsesAppleHosting, ManagedDownloaderExtension.shouldDownload(_:)]
- Runtime: `AssetPackManager.shared.assetPack(withID:)` and then `ensureLocalAvailability(of:)` (returns fast if the pack is present; for on-demand packs it starts the download and waits). Call it even for essential packs, because a network failure can leave an essential pack missing.
