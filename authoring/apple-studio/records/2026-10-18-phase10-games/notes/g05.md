# Notes g05

## game-loop-and-threading.md

- simd math functions come in default, `precise`, and `fast` spellings; the default resolves to precise unless the target builds with `-ffast-math`, which silently switches it to the fast form (as low as 11 bits of accuracy in single precision). Check this flag before trusting sim determinism or replay across builds; call the `precise` spelling explicitly where it matters. — /documentation/Accelerate/single-precision-floating-point-vectors [symbols: simd_rsqrt, simd_precise_rsqrt, simd_fast_rsqrt, simd_float3, simd_packed_float4]
- If a per-frame CPU solve (cloth, soft-body, constraint solve) uses Accelerate's sparse solver, call the `SparseSolve` overloads that take a trailing `UnsafeMutableRawPointer` workspace: Apple documents those as doing no internal memory allocation, which keeps the sim thread allocation-free; by contrast the page implies the plain overloads allocate internally. — /documentation/Accelerate/sparse-direct-solving-functions-matrix-rhs, /documentation/Accelerate/sparse-direct-solving-functions-vector-rhs [symbols: SparseSolve, SparseOpaqueFactorization_Float, DenseMatrix_Float, DenseVector_Float]
- For a matrix whose sparsity pattern stays fixed frame to frame but whose values change, `SparseRefactor` reuses the existing factorization's storage; its overloads with a trailing `UnsafeMutableRawPointer` also skip internal allocation. Factor once at load, refactor per step. — /documentation/Accelerate/sparse-refactor-functions [symbols: SparseRefactor, SparseFactor, SparseNumericFactorOptions]
- Accelerate's Sparse Solvers run multithreaded by default, and the summation order then varies between runs, so results are valid but not bit-identical. A lockstep or replay sim that needs determinism must set the environment variable `VECLIB_MAXIMUM_THREADS=1`. The same default means the library spawns its own worker threads, which compete with the game's job system for cores. — /documentation/Accelerate/sparse-solvers-library [symbols: SparseSolve, SparseFactor]
- Apple's own guidance: try a direct sparse method before an iterative one; direct gives machine precision, iterative only about the square root of it and needs a problem-specific preconditioner to be fast. — /documentation/Accelerate/sparse-solvers-library [symbols: SparseFactor, SparseSolve, SparseLSMR, SparseConjugateGradient]
- The split behind that pattern: `SparseFactor(_:_:)` on a `SparseMatrixStructure` returns a `SparseOpaqueSymbolicFactorization` (structure only), and a second `SparseFactor` call takes it plus values; the overload with two trailing `UnsafeMutableRawPointer?` arguments takes caller-owned workspace and factor storage, so the numeric step can run with preallocated memory. — /documentation/Accelerate/sparse-symbolic-factorization-functions [symbols: SparseFactor, SparseOpaqueSymbolicFactorization, SparseMatrixStructure, SparseNumericFactorOptions]
- vDSP's threading contract: nearly every vDSP call runs single-threaded on the calling core, so it is safe to call from a job-system worker without oversubscribing. The exceptions are the matrix multiplies (`vDSP_mmul`, `vDSP_mmulD`, and the complex `vDSP_zmma`, `vDSP_zmms`, `vDSP_zmmul`, `vDSP_zmsm` families with their `D` variants), which may fan out to other threads depending on data size. — /documentation/Accelerate/vdsp-library [symbols: vDSP_mmul, vDSP_mmulD, vDSP_zmma, vDSP_zmms, vDSP_zmmul, vDSP_zmsm]
- Batch transcendental math over many entities (particle phases, wave offsets, LOD distance falloff) goes through vForce: `vvsinf`, `vvsincosf`, `vvexpf`, `vvpowf` and friends. The C form puts the result pointer first and passes the element count by pointer (`UnsafePointer<Int32>`), not by value; inputs may equal outputs, so in-place is fine. Swift: `vForce.sin(_:result:)`, `vForce.sincos(_:sinResult:cosResult:)`. — /documentation/Accelerate/vforce-library [symbols: vvsinf, vvsincosf, vvexpf, vvpowf, vvrsqrtf, vForce.sin(_:result:), vForce.sincos(_:sinResult:cosResult:)]
- simd matrix naming is column-major: `simd_double4x2` is four columns by two rows, and subscripting is `[column, row]`, so a 2D translation goes in `m[2, 0]` and `m[2, 1]`. The unlabeled array initializer takes columns; pass `rows:` to supply rows. Mixing these up silently transposes a transform. A `simd_float3x3` occupies 48 bytes, because each `simd_float3` column pads to 16. — /documentation/Accelerate/working-with-matrices [symbols: simd_double4x2, simd_double2x4, simd_float3x3, matrix_identity_float3x3, simd_mul, simd_float3]
- Quaternion facts from Apple: `simd_quatf` is 16 bytes against 48 for a `simd_float3x3`, and Apple claims chains of combined rotations run up to 30% faster as quaternions, while a single rotation is slightly slower than a matrix. `simd_quatf(angle:axis:)` yields a unit quaternion only when the axis is normalized; an unnormalized axis gives a length above 1 and a wrong rotation. The component initializer is `simd_quatd(ix:iy:iz:r:)`, real part last. `act(_:)` / `simd_act` rotate a vector; `simd_slerp` takes the short arc and `simd_slerp_longest` the long one; `simd_spline` gives a smooth path through a keyframe sequence but needs the neighbouring quaternion on each side (four arguments plus t). — /documentation/Accelerate/working-with-quaternions [symbols: simd_quatf, simd_quatd, simd_quatf.act(_:), simd_act, simd_slerp, simd_slerp_longest, simd_spline, simd_normalize]

## audio-and-haptics.md

- What exists: Apple positions the BNNS Graph API (Accelerate) for ML inference inside real-time audio DSP on the CPU, the Audio Unit case of Logic Pro and GarageBand. The sample page is a stub that points to WWDC25 session 276 ("What's new in BNNSGraph"). If a game runs a learned audio effect on the render thread, this is the Apple-sanctioned path, not Core ML. — /documentation/Accelerate/supporting-real-time-ml-inference-on-the-cpu [symbols: BNNSGraph] [gate: sample lists macOS 26 / Xcode 26]
- vDSP real FFT/DFT gotchas for audio-reactive visuals or spectrum analysis: input must be split-complex (`vDSP_ctoz` packs even samples into real, odd into imaginary); output of n reals is n/2 complex values with the real Nyquist term stored in the imaginary slot of element 0; and vDSP never scales results. A real forward transform comes back 2x too large, a real inverse n x too large, a complex inverse n x; a complex forward is unscaled. Forgetting the factor-of-2 makes every band read 6 dB hot. — /documentation/Accelerate/understanding-data-packing-for-fourier-transforms [symbols: vDSP_ctoz, DSPSplitComplex, vDSP_fft_zrip, vDSP_create_fftsetup, vDSP_destroy_fftsetup, vDSP_DFT_zrop_CreateSetup, vDSP_DFT_zop_CreateSetup, vDSP_DFT_Execute, vDSP_DFT_DestroySetup, vDSP_fft2d_zrip, vDSP_fft2d_zip]
- Apple's sample creates and destroys the FFT/DFT setup inside each call for brevity. In a game, create the setup once at init and reuse it per audio block or frame; setup creation is the costly, allocating step (general knowledge, not stated on the page), so it does not belong on the audio thread. — /documentation/Accelerate/understanding-data-packing-for-fourier-transforms [symbols: vDSP_create_fftsetup, vDSP_DFT_zrop_CreateSetup]
- The Swift `vDSP` overlay ships each arithmetic op in two shapes: one that returns a new `[Float]` and one that writes into an `inout` `result:` buffer. On an audio render callback or a per-frame hot path, use only the `result:` form against preallocated storage; the returning form allocates an Array on every call. Fused forms such as `vDSP.multiply(addition:_:result:)` compute `(a+b)*c` in one pass. — /documentation/Accelerate/using-vdsp-for-vector-based-arithmetic [symbols: vDSP.multiply(addition:_:result:), vDSP.add(multiplication:_:), vDSP.add(_:_:)]
- vDSP functions whose input and output have equal byte sizes may run in place unless their page says otherwise, so an audio effect can process its buffer without a second scratch buffer. — /documentation/Accelerate/vdsp-library [symbols: vDSP_vtmerg, DSPSplitComplex]
- Level metering for a mixer bus, ducking, or audio-reactive gameplay: `vDSP_rmsqv` gives RMS and `vDSP_maxmgv` gives peak magnitude of a sample block, each as one strided C call that writes a scalar and allocates nothing, so both are callable from a render callback or tap. Swift equivalents are `vDSP.rootMeanSquare(_:)` and `vDSP.maximumMagnitude(_:)`. Watch the page's mislabel: it describes `vDSP.indexOfMinimum(_:)` as returning the maximum; the C counterpart `vDSP_minvi` is the minimum. — /documentation/Accelerate/vector-average-calculation, /documentation/Accelerate/vector-extrema-calculation [symbols: vDSP_rmsqv, vDSP_maxmgv, vDSP_meanv, vDSP.rootMeanSquare(_:), vDSP.maximumMagnitude(_:), vDSP.indexOfMinimum(_:), vDSP_minvi]
- Click-free gain changes in a custom mixer: `vDSP_vrampmul` multiplies a block by a gain that steps each sample, and its `__Start` argument is an in/out pointer, so the ramp resumes at the right value on the next render call. `vDSP_vrampmuladd2` does the same for a stereo pair and accumulates into the output, which is one voice's contribution to a stereo bus in a single call. Fixed-point `_s1_15` and `_s8_24` variants exist. Swift: `vDSP.formRamp(withInitialValue:multiplyingBy:increment:result:)` and `vDSP.formStereoRamp(...)`, both taking `inout` initial values. — /documentation/Accelerate/vector-generation [symbols: vDSP_vrampmul, vDSP_vrampmuladd, vDSP_vrampmul2, vDSP_vrampmuladd2, vDSP_vrampmul_s8_24, vDSP.formRamp(withInitialValue:multiplyingBy:increment:result:), vDSP.formStereoRamp(withInitialValue:multiplyingBy:_:increment:results:_:)]
- Before an FFT for a spectrum display, apply a window built once with `vDSP.formWindow(usingSequence:result:isHalfWindow:)` or `vDSP_hann_window` (flag `vDSP_HANN_NORM` or `vDSP_HANN_DENORM`). Apple's linked article on this is "reducing spectral leakage with windowing". — /documentation/Accelerate/vector-generation [symbols: vDSP.WindowSequence, vDSP.formWindow(usingSequence:result:isHalfWindow:), vDSP_hann_window, vDSP_HANN_NORM, vDSP_blkman_window, vDSP_hamm_window]
- Fixed-gain counterparts for a mixer: `vDSP_vsma` computes `D = A*b + C` (mix one voice at scalar gain into an accumulating bus), and `vDSP_vsmsma` computes `E = A*b + C*d` (a two-source crossfade at fixed weights). Every C entry takes strides, so interleaved stereo can be processed one channel at a time with stride 2, without deinterleaving. — /documentation/Accelerate/vector-scalar-real-arithmetic-functions [symbols: vDSP_vsma, vDSP_vsmsma, vDSP_vsmul, vDSP.add(multiplication:_:result:), vDSP.add(multiplication:multiplication:result:)]
- After the FFT, `vDSP_zvmags` turns the split-complex result into per-bin squared magnitudes (power) in one call; `vDSP_zvmgsa` does the same and adds into an existing buffer, useful for averaging spectra across blocks. Swift: `vDSP.squareMagnitudes(_:result:)`. — /documentation/Accelerate/vector-squaring-functions [symbols: vDSP_zvmags, vDSP_zvmgsa, vDSP.squareMagnitudes(_:result:), DSPSplitComplex]
- Argument-order trap in the C vDSP API: `vDSP_vsub` and `vDSP_vdiv` take the subtrahend/divisor `__B` as their first pointer and `__A` second, computing `C = A - B` and `C = A / B`. Code that reads them left-to-right as `first - second` gets the sign or reciprocal wrong; the Swift `vDSP.subtract(_:_:)` overlay takes operands in natural order. `vDSP_vma` (`D = A*B + C`) is the vector-gain mix-in when the gain is itself a per-sample envelope. — /documentation/Accelerate/vector-vector-real-arithmetic-functions [symbols: vDSP_vsub, vDSP_vdiv, vDSP_vma, vDSP_vmma, vDSP.subtract(_:_:result:)]
- vForce covers per-sample nonlinearities on an audio block: `vvtanhf` for a soft-clip or saturation stage, `vvsinpif` / `vvcospif` for an oscillator bank fed by a phase ramp from `vDSP.formRamp`, `vvpowf` for gain curves. Use the `result:` Swift forms or the C forms; both work in place. — /documentation/Accelerate/vforce-library [symbols: vvtanhf, vvsinpif, vvcospif, vvpowf, vForce.tanh(_:result:), vForce.sinPi(_:result:)]
- Apple's spectrogram sample (macOS, microphone through AVFoundation sample buffers) uses a forward DCT (`vDSP.DCT` with `transform(_:result:)`) rather than an FFT: the output is real-valued, so there is no split-complex packing to undo. The recipe is to convert Int16 samples with `vDSP.convertElements(of:to:)`, multiply by a Hann window made once with `vDSP.window(ofType:usingSequence:count:isHalfWindow:)` and `.hanningDenormalized`, transform, then colour-map with `vImage.MultidimensionalLookupTable`. Its numbers are 1024 samples per frame and a hop of 512, which is 50% overlap. A mel view is one `cblas_sgemm` against a triangular filter bank (40 filters in the sample). — /documentation/Accelerate/visualizing-sound-as-an-audio-spectrogram [symbols: vDSP.DCT, vDSP.convertElements(of:to:), vDSP.window(ofType:usingSequence:count:isHalfWindow:), vDSP.WindowSequence.hanningDenormalized, vImage.MultidimensionalLookupTable, cblas_sgemm, vDSP_vgen]
- Porting that sample into a game: it grows and trims Swift arrays per buffer and builds a `CGImage` per frame. That is tolerable on an AVFoundation capture queue but not on an audio render thread or the frame loop. Preallocate a ring buffer, run the DCT off the render thread, and upload the magnitudes to a Metal texture rather than going through Core Graphics. — /documentation/Accelerate/visualizing-sound-as-an-audio-spectrogram [symbols: vDSP.DCT, vImage.PixelBuffer]

## game-design.md

- Menus a Mac game draws in Metal are invisible to VoiceOver, because AppKit's built-in accessibility covers only real `NSView` controls. To expose them, model each button, slider, or list row as an `NSAccessibilityElement` subclass (Apple's prescribed route for elements that are not `NSView`s), parent them under the hosting view, and give each a role, label, and frame. Convert frames with `NSAccessibility.screenRect(fromView:rect:)`, because assistive apps expect screen coordinates. SwiftUI-hosted HUDs use SwiftUI's own accessibility modifiers instead. [gate: macOS / AppKit] — /documentation/AppKit/accessibility-for-appkit, /documentation/AppKit/accessibility-functions [symbols: NSAccessibilityElement, NSAccessibilityProtocol, NSAccessibility.Role, NSAccessibility.screenRect(fromView:rect:)]
- When a custom in-game control changes state (a slider moves, focus shifts between drawn menu items), post the change yourself with `NSAccessibility.post(element:notification:)`, for example `.valueChanged`; nothing else tells VoiceOver. Back the element's actions with the standard verbs `NSAccessibility.Action.press`, `.increment`, `.decrement`, `.cancel`, `.confirm`, so the options screen can be driven without a pointer. — /documentation/AppKit/accessibility-functions, /documentation/AppKit/actions [symbols: NSAccessibility.post(element:notification:), NSAccessibility.Notification.valueChanged, NSAccessibility.Action.press, NSAccessibility.Action.increment, NSAccessibility.Action.decrement, NSAccessibility.Action.cancel, NSAccessibility.Action.confirm]
