## game-center-and-online.md

- Apple's peer-to-peer game sample (TicTacToe) uses two paths: on Apple TV, DeviceDiscoveryUI finds nearby iPhone/iPad/Watch devices to act as controllers; on iOS/iPadOS, Bonjour discovery plus TLS gives a secure two-player local game over a custom framed protocol. - Debugging-tool triage for online code: HTTP status errors from a game backend go to "Debugging HTTP Server-Side Errors" or the Instruments HTTP Traffic template; URLSession internals go to CFNetwork diagnostic logging; anything below HTTP (UDP game traffic, custom framing) needs a packet trace; HTTP proxies are third-party. The aim is to decide whether client or server is wrong by inspecting the wire independently. — /documentation/Network/choosing-a-network-debugging-tool [symbols: URLSession]
- Local-network TLS for a LAN host: Apple's endorsed shape is a local CA (made in Keychain Access on macOS) that issues a leaf certificate to the host, a PKCS#12 identity imported on the host (`SecPKCS12Import` then `SecItemAdd` on iOS; on the Mac that made the CA, `SecIdentityCreateWithCertificate` from the keychain cert), and the root certificate installed on every client so trust evaluation passes unmodified. A consumer game cannot ask players to install a root cert, so this pattern fits venue/kiosk setups, not ad-hoc LAN play. — /documentation/Network/creating-an-identity-for-local-network-tls [symbols: SecPKCS12Import, SecItemAdd, SecItemCopyMatching, SecIdentityCreateWithCertificate, kSecClassIdentity, kSecImportItemIdentity]
- Server side: wrap the `SecIdentity` with `sec_identity_create`, set it with `sec_protocol_options_set_local_identity` on `NWProtocolTLS.Options().securityProtocolOptions`, floor the version with `sec_protocol_options_set_min_tls_protocol_version(..., .TLSv12)`, build `NWParameters(tls:tcp:)`, and hand it to `NWListener(using:on:)`. Client: same TLS options, `NWEndpoint.hostPort(host: "name.local", port:)`, `NWConnection(to:using:)`. The identical listener code runs on macOS and iOS once the identity is loaded. — /documentation/Network/creating-an-identity-for-local-network-tls [symbols: sec_identity_create, sec_protocol_options_set_local_identity, sec_protocol_options_set_min_tls_protocol_version, NWProtocolTLS.Options, NWParameters, NWListener, NWConnection, NWEndpoint.hostPort]
- Gotchas: connecting by raw IP needs the IP in the leaf certificate's Subject Alternative Name (and by name needs the DNS name there), otherwise the handshake fails with BoringSSL `CERTIFICATE_VERIFY_FAILED`. The escape hatch is `sec_protocol_options_set_verify_block` running your own `SecTrustEvaluateWithError` with `SecPolicyCreateBasicX509` (no hostname check); Apple labels this not recommended, for extreme cases only — but it is the realistic route for player-hosted LAN games that pin a known cert. — /documentation/Network/creating-an-identity-for-local-network-tls [symbols: sec_protocol_options_set_verify_block, sec_trust_copy_ref, SecPolicyCreateBasicX509, SecTrustSetPolicies, SecTrustEvaluateWithError]
- Backend HTTP errors split two ways: a transport error arrives as an `NSError` (e.g. `urlSession(_:task:didCompleteWithError:)`), a server-side error only as `HTTPURLResponse.statusCode` outside 200...299 with a nil error. Print the response body first (UTF-8 or hex), then diff against a working client (curl, Safari) recorded with the same tool; the HTTP Tracing instrument (Xcode 13+) shows the requests. — /documentation/Network/debugging-http-server-side-errors [symbols: HTTPURLResponse.statusCode, URLSessionTaskDelegate.urlSession(_:task:didCompleteWithError:)]
- CFNetwork diagnostic logging: set env var `CFNETWORK_DIAGNOSTICS` to 0–3 in the scheme, or `setenv("CFNETWORK_DIAGNOSTICS", "3", 1)` first thing in `main` — in a C++ engine, before any static initializer touches CFNetwork/URLSession. It sees decrypted TLS payloads, so logs are highly sensitive. View in Console.app (select the iOS device as source) or pull from a sysdiagnose for field issues. URLSession only; does not cover raw Network framework UDP. — /documentation/Network/debugging-https-problems-with-cfnetwork-diagnostic-logging [symbols: CFNETWORK_DIAGNOSTICS, URLSession]
- Custom message framing over TCP (length-prefixed game packets) is the framer API, not hand-rolled buffering: `nw_framer_create_definition(identifier, NW_FRAMER_CREATE_FLAGS_DEFAULT, start_handler)` then `nw_framer_create_options` into the protocol stack. Inside the start handler set `nw_framer_set_input_handler` / `nw_framer_set_output_handler`; parse with `nw_framer_parse_input` / `nw_framer_parse_output`, emit with `nw_framer_deliver_input(_no_copy)` / `nw_framer_write_output(_data/_no_copy)`, and finish a handshake with `nw_framer_mark_ready`. Per-message key-value metadata (e.g. a message type) rides on `nw_framer_message_t` via `nw_framer_message_set_value` / `nw_framer_message_access_value`. Swift's equivalent is `NWProtocolFramer`. — /documentation/Network/framer-protocol-options [symbols: nw_framer_create_definition, NW_FRAMER_CREATE_FLAGS_DEFAULT, nw_framer_create_options, nw_framer_set_input_handler, nw_framer_set_output_handler, nw_framer_parse_input, nw_framer_deliver_input_no_copy, nw_framer_write_output_no_copy, nw_framer_mark_ready, nw_framer_message_create, nw_framer_message_set_value, nw_framer_pass_through_input]

- C API connection shape (nwcat sample, macOS 10.14+): parameters from `nw_parameters_create_secure_udp` / `nw_parameters_create_secure_tcp(configure_tls, configure_transport)` — `NW_PARAMETERS_DISABLE_PROTOCOL` for no TLS, `NW_PARAMETERS_DEFAULT_CONFIGURATION` for defaults; the TLS flag gives DTLS on UDP; TLS pre-shared key is supported. - UDP semantics in Network framework: an `nw_connection_t` over UDP is a bidirectional datagram flow between one local port and one remote peer (a "connection" with no handshake); a server takes a listener (`nw_listener_create` or `nw_listener_create_with_port`, port "0" lets the system choose) whose `nw_listener_set_new_connection_handler` yields one connection per peer, which you start or `nw_connection_cancel` to reject. The connection closes when its last reference drops — retain it and release on `nw_connection_state_cancelled`. States to handle: `waiting` (will retry when conditions improve), `ready`, `failed`, `cancelled`. — /documentation/Network/implementing-netcat-with-network-framework [symbols: nw_listener_create, nw_listener_create_with_port, nw_parameters_set_local_endpoint, nw_listener_set_new_connection_handler, nw_listener_set_state_changed_handler, nw_connection_cancel, nw_connection_set_state_changed_handler, nw_connection_state_waiting, nw_connection_state_cancelled, nw_retain, nw_release]
- Send/receive: `nw_connection_receive(conn, min, max, handler)` — min/max let a record protocol read the length header then the body; always consume delivered content before checking `is_complete`/error, because one callback can carry both. End-of-stream that works for UDP and TCP: `is_complete && (context == NULL || nw_content_context_get_is_final(context))`. For UDP each `nw_connection_send(..., NW_CONNECTION_DEFAULT_MESSAGE_CONTEXT, true, ...)` is one datagram — message boundaries matter; keep a send under 64 KiB (sample uses 8 KiB); a real game stays under path MTU. Close the send side with `NW_CONNECTION_FINAL_MESSAGE_CONTEXT`. Chain async read→write to get flow control instead of unbounded buffering. — /documentation/Network/implementing-netcat-with-network-framework [symbols: nw_connection_receive, nw_connection_send, nw_content_context_get_is_final, NW_CONNECTION_DEFAULT_MESSAGE_CONTEXT, NW_CONNECTION_FINAL_MESSAGE_CONTEXT, dispatch_read, dispatch_write]

- L4S (ECN-based low-latency congestion control) names cloud and online gaming as a beneficiary. Apple support since iOS/iPadOS 17 is for some users only: QUIC has full sender+receiver L4S, TCP has receiver-side only. So a game that wants L4S benefit on its upstream needs QUIC (Network framework QUIC, not raw UDP — custom UDP gets no Apple congestion control at all) and a server stack that implements L4S both ways. - Verifying L4S: in a Wireshark capture, sent QUIC packets should carry ECT(1) in the IP header (check 10–20 packets; Apple's stack tests for networks that bleach ECN at connection start and drops ECN if so); TCP shows Accurate ECN negotiated in SYN/SYN-ACK flags (AE/CWR/ECE, a 3-bit CE counter that wraps every 8). ## game-design.md

- The games overview links the HIG page "Designing for games" (`/design/Human-Interface-Guidelines/designing-for-games`) as the design entry point and stresses designing for each device's usage context (iPhone on the couch or travelling vs Mac at a desk) and for all attached hardware. visionOS: iPad/iPhone games run in a window on Vision Pro with direct and indirect gestures; full immersion uses Metal + Compositor Services. — /documentation/TechnologyOverviews/games-technologies [symbols: CompositorServices]

Apple's visionOS game samples: Petite Asteroids (volumetric), Chaparral Village (immersive adventure, Reality Composer Pro 3), Happy Beam (Full Space + ARKit), no-code Script Graph games in Reality Composer Pro 3. — /documentation/visionOS [gate: visionOS]

## apple-metal/cpp-and-rust.md

- Sanitizers outside Xcode schemes: clang `-fsanitize=address|thread|undefined` (and granular `-fsanitize=alignment`, `bounds`, `null`, `signed-integer-overflow`, `float-cast-overflow`, `vptr`, etc.), swiftc `-sanitize=address|thread`, xcodebuild `-enableAddressSanitizer YES`, `-enableThreadSanitizer YES`, `enableUndefinedBehaviorSanitizer YES`. Main Thread Checker works on any existing macOS binary (CMake/cargo builds included) by injecting `/Applications/Xcode.app/Contents/Developer/usr/lib/libMainThreadChecker.dylib`. For the Test action, set the sanitizers in the test plan configuration, not the scheme's Run diagnostics. — /documentation/Xcode/diagnosing-memory-thread-and-crash-issues-early [symbols: -fsanitize=address, -fsanitize=thread, -fsanitize=undefined, -enableAddressSanitizer, -enableThreadSanitizer, libMainThreadChecker.dylib]
- Dispatch from C++ under ARC vs MRC: compiled as Objective-C(++), dispatch objects are ObjC objects and ARC retains them; without ARC use `dispatch_retain` / `dispatch_release` (never CFRetain/CFRelease). To keep manual retain/release semantics in an ARC target, compile with `-DOS_OBJECT_USE_OBJC=0`. Relevant to metal-cpp engines that mix .mm files and plain C++. — /documentation/dispatch [symbols: dispatch_retain, dispatch_release, OS_OBJECT_USE_OBJC]

## apple-metal/command-model.md

- Metal 3/Metal 4 seam: Touch Controller's only draw entry point is `renderUsingRenderCommandEncoder:(id<MTLRenderCommandEncoder>)` — a Metal 3 encoder; the iOS 27.1 SDK header has no `MTL4RenderCommandEncoder` variant. A Metal 4 renderer on iOS must encode the touch-control overlay in a Metal 3 command buffer/render pass (e.g. a final overlay pass on the drawable) and order it after the Metal 4 work. — iPhoneOS SDK TCTouchController.h [symbols: TCTouchController.renderUsingRenderCommandEncoder:, MTLRenderCommandEncoder, MTL4RenderCommandEncoder] [gate: iOS 26+]
