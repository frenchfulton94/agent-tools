== 1. mach timebase ratio, native and translated (timebase.c) ==
$ clang -O1 -arch arm64  -o $O/timebase-arm64  timebase.c
$ clang -O1 -arch x86_64 -o $O/timebase-x86_64 timebase.c
$ $O/timebase-arm64
arch=arm64 numer=125 denom=3
ticks=2457040 scaled_ns=102376666 clock_uptime_raw_ns=102376625
raw_ticks_as_ns_error=-97.6%
$ arch -x86_64 $O/timebase-x86_64          # Rosetta 2
arch=x86_64 numer=1 denom=1
ticks=105024459 scaled_ns=105024459 clock_uptime_raw_ns=105025291
raw_ticks_as_ns_error=-0.0%
Reading: a native arm64 tick is 125/3 ns (24 MHz); a tick count read as
nanoseconds runs 41.7x slow. Under Rosetta the ratio is 1/1. Ticks scaled by
the ratio agree with clock_gettime_nsec_np(CLOCK_UPTIME_RAW) to within 41 ns
over 100 ms.

Reading: 10 of 10 handlers ran off the main thread, on the dispatch queue
labelled com.Metal.CompletionQueueDispatch, at userInteractive QoS, whatever
the committing thread's QoS (userInteractive or utility). Neither the
addCompletedHandler(_:) page nor MTLCommandBuffer.h states this; it is
observed behavior, not contract.

== 3. Raw priority 45 against QoS (thread_priority.c) ==
$ clang -O1 -o $O/thread_priority thread_priority.c && $O/thread_priority
attr qos userInteractive           qos_class_self=userInteractive  sched_priority=31 policy=1
attr qos userInitiated             qos_class_self=userInitiated    sched_priority=31 policy=1
attr qos default                   qos_class_self=default          sched_priority=31 policy=1
attr qos utility                   qos_class_self=utility          sched_priority=31 policy=1
attr qos background                qos_class_self=background       sched_priority=31 policy=1
pthread_attr_setschedparam(45) rc=0
attr setschedparam 45 (rc above)   qos_class_self=unspecified      sched_priority=45 policy=1
plain pthread_create               qos_class_self=default          sched_priority=31 policy=1
main thread (CLI process)          qos_class_self=userInteractive  sched_priority=31 policy=1
Reading: the priority-45 recipe leaves the thread with QOS_CLASS_UNSPECIFIED,
so it opts out of QoS rather than ranking within it. pthread_getschedparam
reports 31 for every QoS class, so it cannot be used to confirm a thread's QoS;
use qos_class_self().

== 4. Foundation Thread QoS (thread_qos.swift) ==

Thread, no QoS set: qos_class_self=default Thread.qualityOfService.rawValue=-1
Thread, qualityOfService = .userInteractive before start: qos_class_self=userInteractive Thread.qualityOfService.rawValue=33
Thread, qualityOfService = .utility before start: qos_class_self=utility Thread.qualityOfService.rawValue=17
Reading: a Thread started with no QoS runs at default, not at the main
thread's userInteractive. Setting qualityOfService before start() takes effect.
